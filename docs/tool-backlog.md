# ツール候補バックログ

**今後作るかもしれないツールの候補を固定するファイル。ここにあるものは未着手。**
思いついた時点で消えないように書き留めておく場所であって、作ることを約束する場所ではない。

既存ツールの改善要望は `docs/ux-backlog.md`、各ツールの仕様は `docs/specs/<tool>.md`。

## 着手ルール

- **着手条件: 実務で2回以上「これが欲しい」と思ったら着手する。**
  1回目はこのファイルに日付を記録するだけ（回数と日付の列に足す）
  - **「2回」は AI が想像で挙げた候補に対する歯止め**（xref・mermaid・gantt など、
    欲しいと言われた記録がゼロのもの）。**利用者が自分から要望したものは1回目でも着手してよい。**
    ただし要望が抽象的なら、調査で範囲を絞ってから着手する
    （doc2xl の例: 「Excel と md を相互変換したい」→ 調査で「Excel→MD は表現モデルが違い
    機械変換では意味が出ない（LLM の仕事）」と判明 → 「MD→Excel の一方向のみ」に絞って着手。
    2026-08-12 のユーザー判断）
- 着手前に必ず次の2つの原則で判定する:
  1. **この情報はチームで共有すべきものか** → Yes なら**作らない**
     （`~/Personal/vault/_rules/vault-rules.md` の「管理範囲の原則」。
     共有すべき情報を個人ツールに囲い込むと、正本が分裂して後で必ず破綻する）
  2. **使う瞬間に得をするか**（＝運用・維持に時間を要求しないか）。
     入力・更新の手間が継続的に発生するものは、その時点で「管理ツール」になっていて
     このリポジトリの目的（業務効率化）から外れる
- **既存ツールで代替できないかを先に確認する。** devpad にタブを1つ足すだけで済むことが多い
  （タブ追加は `TABS` 配列に1要素で、独立性は既存の `guard()` が担保する）
