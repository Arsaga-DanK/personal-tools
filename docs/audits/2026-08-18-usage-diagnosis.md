> `docs/ux-backlog.md` から 2026-09-25 に移した監査ログ（内容は書き換えていない）。判断の現行版は `docs/ux-backlog.md` の「やらないと判断したもの」「検討して現状維持と判断した事項」を見る。

## 2026-08-18 使用実態の診断と「Draw Gantt の凍結」

利用者「**そもそも今のままだとそんなに使わないかも**」を受けた診断（16本の空状態を実測）。

**診断の核心（実測）**: **16本のうち11本が「貼る」から始まるのに、ツール間リンクが1本も無かった**
（全 `web/*.html` の `href` は favicon・`ui.css`・`../index.html` の3種類だけ。
URL パラメータによる入力口も0本）。データ形式としては繋がっているのに**経路が存在しない**。
Gantt は貼り付け取り込みが完成しているのに、既定ビューにそれが書かれておらず、
手入力（3欄×行数＋1）の道だけが見えていた。

### Draw Gantt は凍結（2026-08-18・利用者判断）

利用者「**ガントチャートはそんなに触ってないかも**」。
→ **これ以上の機能追加・改善に時間を使わない**。既にあるもの（行エディタ既定・貼るだけ取り込み・
受け渡しの受け側・md 記法）はそのまま維持する。消さないのは、場面が来たときに代替が無いため。
- **やらないと決めたもの**: 進捗・依存・祝日・担当者（spec「管理はしない」を壊す）／
  行エディタのドラッグ並べ替え／FSA での tasks.md 直読／md 記法のさらなる拡張
- **再開のトリガー**: 実際にガント画像を資料に貼る場面が3回以上出たとき

### 効くと判断した施策（コストの小さい順）と実施状況

1. **ハブへの到達を1操作にする**（コード変更ゼロ — ブックマークバー先頭に絵文字1字で置く）。
   ハブ自体は「打つ→Enter」で到達完了まで作ってあるので、残るコストは「ハブに着くこと」だけ。
   → **利用者の設定作業（こちらでは代われない）**
2. **Obsidian 側に導線を作る** — ツールを思い出す瞬間は Obsidian の中で来る。
   → **実装済み（2026-08-18）**: ハブの［Obsidian 用のリンク集］が
   「ハブ＋全16本＋カテゴリ見出し」の md をクリップボードへ出す（HUB-25）。
   **vault には書き込まない**（正本は利用者が置く）。**パスはコードに書かず `location` から組む**
   （環境依存を持たない — PC が変わってもハブを開き直せば正しいパスが出る）
3. **貼ったデータから行き先を決める** → **実装済み（2026-08-18）**: ハブの［データから探す］。
   `routeText` で判定し**候補を複数出して理由を添える**（決め打ちしない）。
   **候補は受け取り側を実装済みのツールだけ**（HUB-22/23）＋
   **貼る→押す→受け側に入るまでの実機通し**（HUB-24。この通しで devpad の受け取り忘れを検出した）
4. **ツール間の受け渡し**（Plan Tasks →［Draw Gantt で開く］）→ **実装済み**（`lib/handoff.js`・TB-H1/GN-U20）

### やらないと決めたもの（診断の結論）

- md 記法をさらに磨く（**md 化して「なお使いづらい」と言われた。記法の層に答えはない**）
- Sort Ideas / Draw Mindmap を磨く（使われていないものを磨く行為。**凍結**。
  ただし両方とも利用者が自分から要望したツールなので**消さない** —
  「作ってみたら違った」のか「まだ場面が来ていない」のか判定できない）
- 低頻度ツール（Document Schema・Export Outline・Normalize Text・Unify Terms・Check Vault）を消す
  → **「使われない」ではなく「その場面が来たら必ず使う」**。消すと代替が無い
- 使用回数での並べ替え（たまに使う道具が沈む）／17本目を作る（導線が問題なのに本数を増やす方向）
