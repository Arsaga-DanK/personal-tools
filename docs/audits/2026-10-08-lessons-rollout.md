# Plan Tasks の教訓を他のツールに当てはめる点検（2026-10-08）

利用者「一番使ってるのがタスク管理ツールだから、そこだけクオリティがマジで高い」→ 「Plan Tasks で直したことを、ほかのツールにも当てはまるか点検して、直す候補を一覧にする」を選択。
**この文書は点検の記録。何も直していない**（候補から利用者が選ぶ）。

点検した教訓（出どころは `docs/specs/taskboard/decisions.md`）:
①読めなかったら空とみなして上書きしない（TB-Q74）②書く直前に読み直して NFC 比較（外部変更を消さない）③複数手順の操作は失敗しても「消える」より「重複」に倒す・書いたら読み直す・途中で元が変わったら止める（TB-Q75・AF6〜AF9）
④覚えたフォルダを毎回確かめる（TB-AF9・AR-1）⑤元と書き先が同じファイルにならない（TB-AF8）⑥戻せない操作には確認か［元に戻す］（AR-3・TB-Q65・Q71）
⑦未保存のまま離れない（TB-Q61）⑧IME の Enter／Esc（TB-Q6・Q9）⑨裏の読み込みが押した操作に勝たない（TB-AV5）
⑩保存した UI 状態は既知の値だけ戻す（TB-Q17）⑪日付は今日が既定・年＋月/日＋曜日・今日チップ（TB-Q73・Q68・Q59）⑫コピーは画面と一致（TB-Q14）
⑬ドラッグは本物のマウスで検証（TB-K23）⑭不正入力は無言で通さない。

点検の方法: コードを読み、Playwright の実機プローブで再現したものを「確認済み」とした（2本の点検エージェント。片方は Check Issue・Check Vault、片方は残り14本）。
「未確認」はコードから読んだ結論で、実機では試していない。

## すでに大丈夫だったこと

- ①読めなかったら空扱いしない: Check Issue（ui.js:213-219・wizard.js:390-393・list.js:701-704）／Check Vault（fsa.js:72-78・fix.js:162-166）
- ②書く直前の読み直し＋NFC 比較: Check Issue（list.js:684-697・wizard.js:415-420）／Check Vault（fix.js:161-169）
- ③の一部: Check Issue のスピンオフは新しいノートを先に作る（失敗は重複側 — wizard.js:386-410）／Check Vault の移動はコピー→サイズ確認→削除（fsa.js:86-99）
- ④: Check Vault はハンドルを覚えない ⑤: Check Issue に元＝書き先の操作は無い
- ⑥: Check Vault は件数＋先頭20件の確認・コミット済みチェック・変更前つきログ（fsa.js:116-174）。Sort Ideas・Mask Image・Draw Gantt は戻す仕組みあり
- ⑧: Check Issue の［＋分かったこと］の Enter・検索欄・行のキー、Draw Gantt の編集の Enter、Sort Ideas・Mask Image の編集欄は変換中を除けている。ほかは Cmd+Enter だけ
- ⑩: norm・doc2xl・ddl2spec・excel2md・devpad・gantt・board は既知の値だけ戻す
- ⑫: 明らかな不一致は無し（diff の省略行とコピーの対応は未確認）⑭: terms・mindmap・diagram・gantt・ddl2spec・mask・norm・devpad は警告を出して最善の出力

## 未確認（コードから疑っているが実機で見ていない）

- Check Issue の `loadIssues`（list.js:90-122）に「新しいものが勝つ」印が無く、続けて書くと古いノートが残って「Obsidian 側で変更」が誤って出るかもしれない
- Check Vault でアーカイブ先の設定が Inbox と大文字小文字だけ違うと、APFS では元と移動先が同じファイルになり、コピーしてから元を消すのでノートが消える
- Check Issue はどの書き込みでもノート全体を NFC・LF に揃えて書く（触っていない行まで変わる。失うものは無い）。Plan Tasks は「比べるときだけ NFC・書く中身は変えない」（io.js:247）
