## 2026-08-17 Obsidian 連携の監査（FSA は不採用・クリップボード往復を採用）

利用者要望「自動で obsidian に連携して外部記憶として使用しても良いし、組み込めるんじゃない？」
に対する設計監査の結論。**FSA（vault のファイルを直接読み書き）は4本すべてで不採用**:

| ツール | 判定 | 理由 |
|---|---|---|
| board | やらない | 盤面（座標・色・結線）は md に写せず**書き出した md から復元できない**。vault に写しを置くと実体（localStorage）と二重になる。`specs/board.md` F9 で既に「やらないこと」・トリガー未発火 |
| mindmap | やらない | 入力は既に md 互換で Obsidian から貼れる（MM-Q4）。FSA にしても**削れる手数は1**で、権限フロー一式に見合わない |
| gantt | 保留（GN-Q6 のまま） | トリガーは「貼るのが面倒という実測」だが、**同日の paste 取り込み＋行エディタで解消済み**。再発したら発火 |
| diagram | **クリップボード往復を採用**（DG-Q5） | Obsidian は mermaid をネイティブに描画する → **ノートが唯一の正本**にできる。FSA は不要 |

- 実測で分かった FSA の事実（`docs/verification-notes.md` §2 に反映済み）:
  ジェスチャ要求のエラー名は Chrome のバージョンで変わる（名前で判定しない）・`getParent` は無い・
  **file:// は全ローカルページで1オリジンなので IDB のハンドルは他のローカル HTML から列挙できる**
  （vault ルートのディレクトリハンドルを保存すると露出面が vault 全体に広がる）
- 「自動連携」の上限は**初回1クリック → 権限が生きている間は自動**。完全自動は不可（ピッカーはジェスチャ必須）

### 見送り（トリガー付き — 蒸し返さないための記録）

| 項目 | 内容 | トリガー |
|---|---|---|
| mindmap / gantt の［Obsidian 用にコピー］ | mermaid ブロックとしてノートに貼れば描画はされる。**だが往復が閉じない** — ノートに残るのは mermaid（mindmap DSL / gantt DSL）で、ツール側の入力（箇条書き / タスク表）とは別表現になり、**同じ内容が2つの形で存在する**（第二の正本の芽）。diagram だけ採用したのは mermaid が入力そのものだから | **逆変換を先に作ること**（mermaid mindmap → 箇条書き / mermaid gantt → タスク表）。逆変換ができて往復が閉じたら採用してよい。gantt は GN-Q5（日数と終了日の相互変換はしない）と衝突しないか要確認 |
| board の md をノートへ | 現状は「md をコピー → ノートに貼る」で足りる想定 | コピペ運用を実際にやって足りないと分かったとき（board.md F9） |
| `lib/fsa.js`（ハンドル永続化＋権限の2関数だけ） | 現在の利用者は taskboard 1本のみで、vaultlint は IDB を使わない（＝2番目の利用者がいない）。coding-rules の共通化条件を満たさない | gantt 等に読み取り FSA が入り、IDB＋権限が db 名と key 以外同型になった実測が出たとき |
| FSA の実機確認2点 | `obsidian://` の「常に許可」・FSA の「Allow on every visit」が **file:// で出るか**（下の 2026-08-13 項に既出・未実施のまま） | vault を直接読み書きするツールを増やす前に必ず消化する |
