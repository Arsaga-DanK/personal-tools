## 2. なぜ第1案では足りなかったか（実データ 2026-10-01 の3本で確かめた）

- カードが**量**（掘る 63行・論点 1・画像 3）を出していて、**意味**（何が分かり、何を待っているか）を出していなかった。
  中身は全部「掘る」にある — 例: 先方に確認のノートの掘るに「F/W ではなくネットワークで制御する、ということは分かった」「本番と通信できるかが分かっていない」「解答受領待ち」
- ノート名（やること — Plan Tasks の 🎯 がタスク名から作る）と論点（問い）が同じ大きさで並び、どちらが何か分からない
- Check Issue だけでは**閉じどき**が分からない — 先方に確認のタスクは 9/29 に済んでいるのに、論点は開いたまま「6日遅れ」と出ていた
- 本の見方（1つのイシューを一目で分かるのに要るもの）: ①問い ②今の見立て ③まだ白黒がつかないこと ④次の一手・誰待ち ⑤答えの出口。第1案は ① だけ

## 3. 画面（上から）

1. **見出し2行**（Plan Tasks と同じ形）: 1行目 ☰ ツール／Check Issue（説明は題名の title）／タスク・イシュー／件数と「タスクは Plan Tasks で ◯/◯ ◯:◯ に読んだ時点」／⋯（vault 名・再読込・使い方）。
   2行目 ＋新しく立てる・表示（開いている／すべて／閉じた）・検索。「使い方」はノートが0のときだけ開いて出す（今と同じ）
2. **いま**: 遅れ → 今日まで → 立て直す → 論点がまだ無い → 閉じどき を1行ずつ。札は「ノート名（12字）› 論点（6日遅れ）」。
   **1つの論点は1か所だけ**: 閉じどきのノートの論点は遅れに出さない（閉じどきが先）。遅れ・今日までの論点に ⚠ があれば札に ⚠ の印。待ちの行があれば札に「⏳ 待ち」。
   札を押すとそのカード（論点の行）へ飛んで光る。たためる（覚える）
3. **案件の見出し**: ▾ ITK 開いている 3・閉じた 3 遅れ 1・論点なし 1・閉じどき 1（たためる）
4. **ノートのカード**:
   - 見出し: 「やること」の印＋ノート名／右に **タスク N・済み M**（全部済みなら「全部済み ✓」）・Obsidian・＋論点・⋯
   - 論点の行: 左端の色の帯で状態を1つ（遅れ＝赤・今日＝橙・立て直す＝黄）。「問い」の印＋論点。締切は `2026/9/25(金)`＋「6日遅れ」（閉じどきの論点は赤くしない）。⋯
   - ⚠ の理由と、その下に**直し方**1行（判定の `fix` の文 —「〜は A ではなく B ではないか」の形に）
   - **分かった**・**⏳ 待ち** の行と［＋ 分かったこと］
   - 閉じどきなら「✓ つながるタスクは全部済み（9/29）— 論点を閉じますか？［閉じる…］」（**自動では閉じない**）
   - 論点が無いノート: 「掘る 18行から、答えを出すべき問いを1行に［＋ 論点を一行で書く］」
   - ［掘るを読む（11行・画像 3）］で掘るの中身をその場で広げる（押さなければ閉じたまま）
5. **論点の行は右クリックでも**: タスクにする `T`・ちゃんと立てる `R`・閉じる `X`・Obsidian で開く `O`（Plan Tasks の TB-RM と同じ作り。⋯ は残す）

## 4. データ

- **分かったこと・待ち**: 論点の行（`## 論点` の `- [ ]`）の**直後の字下げの箇条書き**。今も `issueLines` が `note`（閉じるときの「分かったこと」）として読んでいる場所なので**記法は増やさない**。
  `待ち:`（全角の `待ち：` も）で始まる行を「待ち」、それ以外を「分かった」とする。［＋ 分かったこと］はその論点の子の最後に1行足す
  （書き込みは今の書き込みと同じく、直前に再読して NFC 比較 — 外で変わっていたら書かずに警告）
- **掘るを読む**: `## 掘る` の節の本文を、箇条書き・番号・表・区切り・画像の名前・太字・コードだけの最小の表示にする（`createElement` のみ。`>` の注記は出さない。画像は名前だけ — 添付は読まない）
- **タスクとのつながり**（表示用の写し）: Plan Tasks が tasks.md を読み込んだとき・保存したときに、
  **関連ノート `[[名前]]` ごとに タスクの数・済みの数・最後に済んだ日**を数え、日時つきで保存領域に書く。Check Issue はそれを読んで出す。
  - `file://` のページ同士は同じ保存領域を見られる（2026-10-01 に実測: taskboard.html で書いた値を issue.html で読めた。`location.origin` は `file://`）
  - CLAUDE.md の「localStorage は UI 状態と設定のみ」との関係: **正本は tasks.md のまま**。これは数え直せる表示用の写しで、必ず「いつ読んだ時点か」を出す。
    古い・無いときは数を出さない（「Plan Tasks で開くと出ます」）。この扱いは taskboard の判断記録に残す
  - **閉じどき** = 開いているノートで、つながるタスクが1つ以上あり全部済み

## 6. セルフ監査（CLAUDE.md の4点）

### ① 一次情報で確かめたこと

### ② 観点ごとの懸念（各2件以上）
- **データ**: 字下げの書き方の揺れ（タブ／空白・`-`／`*`）— 今の `issueLines` は両方受ける／「待ち」の書き方の揺れ（`待ち:`・`待ち：`・「〜待ち」で終わる）— 前2つだけ受け、3つ目は「分かった」に出る（見えはするので害は小さい）
- **表示用の写し**: Plan Tasks をしばらく開いていないと数が古い — 日時を出し、古ければ数を出さない／ノートの名前が変わるとリンクが外れて数が0になる — Check Vault のリネーム追随はリンクも直すので通常は保たれる
- **共通化**: Plan Tasks の差し替えで回帰する — 段1では既存のチェックを1つも変えずに通すことを合否にする／部品が2つのツールの事情を抱えて太る — ツール固有の部分（何を「いま」に入れるか等）は各ツールに残し、部品は見た目と操作だけにする
- **掘るを読む**: 自前の最小の表示なので崩れる書式がある — 崩れても素の文字で読めるようにする／長い掘る（63行・横に長い表）— 高さの上限と表だけの横スクロール
- **閉じどき**: タスクが全部済んでも答えが出たとは限らない — 「閉じますか？」と聞くだけで自動では閉じない／タスクが無いノートは閉じどきにならない（数が無いので判定しない）
- **範囲**: 段5で全ツールの見出しを変えるとハブ・各ツールのテストに広く効く — 段5を独立させ、ツールごとに見た目のチェックを足す／各ツールの「自動保存の注記」の置き場所がツールごとに違う — 段5の前に全ツールを棚卸しする

### ③ 確信を持てていない点
- 見出し2行を全ツールへ広げたとき、変換系の2ペインのツールで「操作が1段に収まる」か（ボタンが多い Convert Data など）
- 立て直す（黄）の色がライトテーマで十分読めるか（画面イメージは暗い配色でしか見ていない）
- 写しを書くのが「読み込み時・保存時」だけでよいか（Plan Tasks を開いたまま Obsidian で tasks.md を直した場合は、次に Plan Tasks が読み直すまで古い）
- 右クリックのキー T／R／X／O が Check Issue の他の操作とぶつからないか（検索欄など。Plan Tasks と同じ除外規則にする予定）
- Check Vault の「一覧の振る舞い」で何が要るか（段6の前に決める）
