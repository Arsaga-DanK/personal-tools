## XL-2 の訂正（2026-08-05・対応済み）

**当初の記述「2つ目以降の表・表の後のテキストが無言で無視される」は片方のケースにしか
当てはまっておらず、実際にはより危険な誤変換だった。** 実装前に実挙動を確認した結果:

| 入力の形 | 実際の挙動（訂正前の実装） |
|---|---|
| 表 → **空行** → 表 | **2つ目が1つ目に吸収され、区切り行が `---` というデータ行として混入していた**（`A\tB / 1\t2 / C\tD / ---\t--- / 3\t4`）。無視ではなく**誤変換** |
| 表 → **テキスト** → 表 | テキスト行で打ち切り。2つ目は無視（当初の記述どおり） |

**原因**: `parseMarkdownTable` が走査前に `filter(l => l !== '')` で空行を捨てていたため、
2つの表を隔てる空行が消え、ボディの打ち切り条件（`|` を含まない行）に到達しなかった。

**対応**: 表の終端を GFM と同じ**空行**にし、`moreTables` 判定で info バナーを出す
（spec「変換仕様（MD→TSV）」8・9、テスト E2M-R09〜R12）。
`---` 混入した表を Excel に貼って気づかず提出する方が、2つ目が出てこないと気づくより
危険という判断で、バナー追加と検出修正を分けずに実施した。

**再発防止のための反省**: この項目は**静的解析だけで記録し、実挙動を検証していなかった**
（根拠列も「静的解析」のまま）。コードを読んで推測した挙動と実際の挙動が食い違う典型例。
**UX 監査で「無言で無視される」類の指摘を書くときは、実際に入力して出力を確認する。**
重要度も「低」と見積もっていたが、誤変換なら「中」以上が妥当だった。

## 検討して現状維持と判断した事項（2026-08-05 / 2026-08-07 追記）

将来「なぜ直していないのか」を再検討せずに済むよう、判断と理由を残す。

- **`el` ヘルパの2形（2026-08-07 のリファクタ監査で判断）**: 関数版
  `const el = id => document.getElementById(id)`（ddl2spec・taskboard）と
  オブジェクト版 `const el = { … }`（diff・excel2md・norm）と devpad 独自の3通りがある。
  **統一しない。** 理由: **これが原因で編集コストが発生した記録が一度もない**
  （共通化の根拠は「同じ変更に N 箇所の編集が必要だった実測」であり、この項目には無い）。
  一方オブジェクト版を関数版に寄せると全参照の書き換えになり、コストは大。
  → **再評価するトリガー: Cursor がツール間でコードを流用し始めたとき**
  （流用のたびに `el` の形の差で書き換えが要るなら、そこで初めて実測値が出る）

- **貼り付け時の揃えリセット（excel2md）**: 揃えを設定したまま別の表を貼ると前の揃えが残る。
  spec の「列数が変わっても列位置で揃えを保持」どおりの設計だが、別の表に前の揃えが
  引き継がれるのは意図とずれる場面がある。**実害小のため現状維持**
  （気になれば paste ハンドラで `colAligns.length = 0` を足すだけ）
- **プレビューのセル幅（excel2md）**: 60列表示で各列が min-content まで潰れて読みにくい。
  `max-width` を設けて横スクロールさせる案があるが、**60列の表を扱う場面がないため対応不要**
- **devpad のエラー規約が非対称**: `b64decode` / `epochToJst` / `jstToEpoch` は `{error}` を返し、
  `urlDecode` / `unescapeJsonStr` は **throw して UI 側が try/catch** する。
  spec が要求しているのは「エラーバナーが出ること」だけなので**適合しており修正不要**。
  ただし**新しいタブを足すときはどちらかに寄せる判断が必要**
  （2026-08-05 のハーネス作成時に把握。`test/devpad.js` は両方の規約を明示的に照合している）
- **変換中 Cmd+Enter でコピー・整形が走る（excel2md / norm / diff / devpad）**: IME の変換中でも
  修飾キー付き Enter は `isComposing: true` で届き、ハンドラが発火する（実測）。
  ただし動作は**非破壊で入力も保持される**ため**現状維持**。
  判定軸は `docs/verification-notes.md` §8。taskboard だけは破壊的操作だったのでガード済み

## 世間の定番ツールとの総評

**優位点（3エージェント共通の結論）**
- **完全ローカル・オフライン**: 貼り付けデータが端末外に出ない。diffchecker / Tables Generator / JSON 整形サイトに対する決定的優位（業務機密の変換・比較に安心して使える）
- **日本語業務特化**: 全角半角同一視 diff、NFKC の除外集合方式と長音保護（norm）、JST 固定・CP932 概算（devpad）、Excel セル内改行の忠実往復（excel2md）は定番に存在しない
- **「落ちない・嘘をつかない・保存が正確」**: 全ツールで不正入力時に警告＋最善出力、劣化パスの明示、注記（自動保存の範囲）と実挙動の一致を実測確認。この基礎品質は定番ツール以上
- taskboard の「プレーン Markdown 正本＋Obsidian 共存＋競合検知」は Todoist/Things にも Obsidian Tasks 単体にもない組合せ

**劣位点**
- キーボードショートカットの欠如（DevToys・Todoist は主要操作にあり）→ CM-3
- 表示系の薄さ: diff の side-by-side・行番号なし、excel2md のプレビュー・列揃えなし、devpad の JSON ツリー/ハイライトなし
- 機能網羅性は DevToys 等に劣る（ただし単機能分担の設計思想とは整合。水増しは「やらないこと」）
- taskboard: 完了自動退避（→確定項目3）・テキスト検索・クイック追加のキーボード完結性で定番タスク管理に劣る

## 確定3項目の実装方針案（Phase P・承認済み分）

1. **favicon**: 各ページ `<head>` に `<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 100 100'><text y='.9em' font-size='90'>絵文字</text></svg>">`（URL エンコード済みで埋め込み。外部ファイル不要・file:// 動作）。絵文字割当案: ハブ 🧰 / excel2md 📊 / devpad 🛠 / norm 🔤 / diff 🔍 / taskboard ✅
2. **サンプル投入ボタン**: 各入力ペイン見出し横に「サンプルを入れる」リンク。内容案 — excel2md: セル内改行入り 3x3 TSV / devpad: JSON タブに崩れた JSON / norm: 全変換が1回ずつ発火する例文（Ｗｅｂ・ｶﾞ・−・～・連続空白）/ diff: 3種の差分を仕込んだ2テキスト同時投入 / taskboard: ファイル不要の「デモデータを表示」（メモリ上・保存ボタン無効＋デモ中バナー）
3. **taskboard 完了アーカイブ**: ツールバーに「完了をアーカイブ」。表示中の完了行を vault/03_Tasks/archive.md へ追記（ハンドルは初回に picker で取得し IndexedDB に tasks.md と同様に永続化）、tasks.md から除去。両ファイルとも保存前に NFC 外部変更検知。spec に「archive.md がなければ作成/ヘッダ付与/ラウンドトリップ」のテストケースを追加
