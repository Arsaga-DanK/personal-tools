## 2026-08-18 ハブを「カード＋一言・1画面」に変更（利用者「16本になって探すのはめんどくさい」）

**実測**: 変更前は 1280x900 で `scrollHeight` 2,093px ＝ **縦2.3画面**。カード1枚が
「名前＋長い説明＋いつ使う」の3要素で、16本並ぶと一覧の用をなしていなかった。

**3回作り直している。経緯を残す（同じ往復をしないため）**:
1. 名前だけのチップ（丸い小さなピル）で1画面に収めた → 利用者「**ちょっと使いにくすぎる。
   カードっぽく大きくして欲しい**」「**説明文もないとわかりにくい**」
2. アイコン＋名前＋一言のカードにし、カテゴリ名を行の左に置いた
   → 利用者「**まだちょっと使いにくいし見にくい。web 調べて参考にしても良い**」
3. → **現行 Web の実装調査**（GitHub Marketplace / Raycast / Stripe / Linear / Vercel / Notion の
   配信 CSS と構造）を経て**カテゴリ分割をやめ、1枚の 4×4 グリッド**に。カテゴリは絞り込みチップへ

**調査で分かった「見にくい」の正体（推測ではなく計算・実測）**:
- **升目の6割が空だった**。カテゴリごとに別グリッドにすると、5列の枠に1〜6本を流すことになり、
  7カテゴリ中4つが1〜2本しかないため**8行×5列=40枠に16枚（充填率40%）**。
  右側に穴が並ぶのが「見にくい」の主因で、カードの造形をいくら磨いても消えない
- **16 = 4×4** なので列数を 4→2→1 に固定すると**どの幅でも余りが出ない**。
  `auto-fit` は使わない（本数が少ない行でカードが全幅に伸びる）
- ダークモードで一言（`--muted` on `--panel`）が **4.06:1 で WCAG AA 不合格**だった
- ホバーで名前を accent 色にしていたため、**コントラストが 12.5:1 → 4.0:1 に落ちていた**
  （GitHub は文字色を変えず面色だけ変える）
- ダークでカードの枠が面との差 **1.36:1** しかなく、影も無いので輪郭が消えていた
- 一言 11.5px は日本語には小さすぎ（実例はいずれも 13〜14px）。かつテキスト列 152px に対し
  最長の一言が 149.5px と限界で、1枚でも折り返すと**同じ行の5枚すべてが高くなる**構造だった

**現行の作法（実例に準拠）**: 影で立てず枠と面で見せる／ホバーは面色だけ（動かさない・文字色を変えない）
／アイコンは角丸タイル（42px に 23px グリフ・内側1pxリング）に載せて**絵文字ごとの視覚的な重さの差を吸収**
／タイル色はカテゴリ色だが、意味はチップと `title` が担う（色だけに意味を持たせない）

- **決定**: カード（アイコン＋名前＋`short` 一言）を**1枚のグリッド**に。全16本が1画面に収まる
  （HUB-18 が 900px 以内をピン）。**列数は3**（利用者の指定 — 4列より1枚が大きい方が良い。
  16本なので最終行は1枚になるが、左端に付けて中央寄せしない）。
  カード 382×84px・アイコンタイル46px・1280x900 で content 893px（余裕7px）。
  **寸法や本数を変えたら必ず測り直す**（余裕が小さいので他の環境で溢れうる）。**長い説明（desc）と用途（when）は画面から消し、
  `title` 属性と検索にだけ残す**（HUB-17）
- **カテゴリは絞り込みチップ**（件数つき＝目次も兼ねる。押すと絞る・もう一度押すと解除・検索と合成 HUB-21）。
  並びは CATEGORY_ORDER 順のままなので、同カテゴリはタイル色の帯として隣り合って見える
- **`short`（カードの一言）と `icon` を TOOLS に追加**。icon は各ツールの favicon が基本だが、
  U+FE0F が要るもの（board/doc2xl/devpad）と重複するもの（excel2md と gantt が同じ）は差し替えた。
  **HUB-17 がアイコンの重複を検出する**（目印にならないため）
- **DOM の契約が変わった**: リンクのテキストは「アイコン＋名前＋一言」なので、
  **表示名で要素を選ぶときは `.tool-name` を使う**（全16ハーネスのハブ導線を追随させた）
- **desc は短くしない** — 表示から外れたので、機能名・別名を盛り込むほど検索で辿り着ける
  （HUB-11 が devpad の4タブ名で引けることをピン）。「画面を簡素にする」ことと
  「検索を賢くする」ことが両立する形にした
- **最近使った**（`tools:hub`・上限5・ハブ経由で開いたときだけ記録）を先頭に追加（HUB-19）
- **検索へ自動フォーカス＋Enter で先頭を開く**（HUB-20）。**IME ガード必須**
  （変換確定の Enter で遷移させない — taskboard TB-I の教訓を横展開）
- 見送り: カテゴリの折り畳み・お気に入りのピン留め・使用回数順。
  トリガー: 最近使った5件で足りないと感じたとき（回数順は「たまに使う道具」が沈むので慎重に）

## 2026-08-17 Obsidian 連携の監査（FSA は不採用・クリップボード往復を採用）

利用者要望「自動で obsidian に連携して外部記憶として使用しても良いし、組み込めるんじゃない？」
に対する設計監査の結論。**FSA（vault のファイルを直接読み書き）は4本すべてで不採用**:

| ツール | 判定 | 理由 |
|---|---|---|
| board | やらない | 盤面（座標・色・結線）は md に写せず**書き出した md から復元できない**。vault に写しを置くと実体（localStorage）と二重になる。`specs/board.md` F9 で既に「やらないこと」・トリガー未発火 |
| mindmap | やらない | 入力は既に md 互換で Obsidian から貼れる（MM-Q4）。FSA にしても**削れる手数は1**で、権限フロー一式に見合わない |
| gantt | 保留（GN-Q6 のまま） | トリガーは「貼るのが面倒という実測」だが、**同日の paste 取り込み＋行エディタで解消済み**。再発したら発火 |
| diagram | **クリップボード往復を採用**（DG-Q5） | Obsidian は mermaid をネイティブに描画する → **ノートが唯一の正本**にできる。FSA は不要 |

- 実測で分かった FSA の事実（`docs/verification-notes.md` §2 に反映済み）:
  ジェスチャ要求のエラー名は Chrome のバージョンで変わる（名前で判定しない）・`getParent` は無い・
  **file:// は全ローカルページで1オリジンなので IDB のハンドルは他のローカル HTML から列挙できる**
  （vault ルートのディレクトリハンドルを保存すると露出面が vault 全体に広がる）
- 「自動連携」の上限は**初回1クリック → 権限が生きている間は自動**。完全自動は不可（ピッカーはジェスチャ必須）

### 見送り（トリガー付き — 蒸し返さないための記録）

| 項目 | 内容 | トリガー |
|---|---|---|
| mindmap / gantt の［Obsidian 用にコピー］ | mermaid ブロックとしてノートに貼れば描画はされる。**だが往復が閉じない** — ノートに残るのは mermaid（mindmap DSL / gantt DSL）で、ツール側の入力（箇条書き / タスク表）とは別表現になり、**同じ内容が2つの形で存在する**（第二の正本の芽）。diagram だけ採用したのは mermaid が入力そのものだから | **逆変換を先に作ること**（mermaid mindmap → 箇条書き / mermaid gantt → タスク表）。逆変換ができて往復が閉じたら採用してよい。gantt は GN-Q5（日数と終了日の相互変換はしない）と衝突しないか要確認 |

## XL-2 の訂正（2026-08-05・対応済み）

**当初の記述「2つ目以降の表・表の後のテキストが無言で無視される」は片方のケースにしか
当てはまっておらず、実際にはより危険な誤変換だった。** 実装前に実挙動を確認した結果:

| 入力の形 | 実際の挙動（訂正前の実装） |
|---|---|
| 表 → **空行** → 表 | **2つ目が1つ目に吸収され、区切り行が `---` というデータ行として混入していた**（`A\tB / 1\t2 / C\tD / ---\t--- / 3\t4`）。無視ではなく**誤変換** |
| 表 → **テキスト** → 表 | テキスト行で打ち切り。2つ目は無視（当初の記述どおり） |

**原因**: `parseMarkdownTable` が走査前に `filter(l => l !== '')` で空行を捨てていたため、
2つの表を隔てる空行が消え、ボディの打ち切り条件（`|` を含まない行）に到達しなかった。

**対応**: 表の終端を GFM と同じ**空行**にし、`moreTables` 判定で info バナーを出す
（spec「変換仕様（MD→TSV）」8・9、テスト E2M-R09〜R12）。
`---` 混入した表を Excel に貼って気づかず提出する方が、2つ目が出てこないと気づくより
危険という判断で、バナー追加と検出修正を分けずに実施した。

**再発防止のための反省**: この項目は**静的解析だけで記録し、実挙動を検証していなかった**
（根拠列も「静的解析」のまま）。コードを読んで推測した挙動と実際の挙動が食い違う典型例。
**UX 監査で「無言で無視される」類の指摘を書くときは、実際に入力して出力を確認する。**
重要度も「低」と見積もっていたが、誤変換なら「中」以上が妥当だった。

- **貼り付け時の揃えリセット（excel2md）**: 揃えを設定したまま別の表を貼ると前の揃えが残る。
  spec の「列数が変わっても列位置で揃えを保持」どおりの設計だが、別の表に前の揃えが
  引き継がれるのは意図とずれる場面がある。**実害小のため現状維持**
  （気になれば paste ハンドラで `colAligns.length = 0` を足すだけ）
- **プレビューのセル幅（excel2md）**: 60列表示で各列が min-content まで潰れて読みにくい。
  `max-width` を設けて横スクロールさせる案があるが、**60列の表を扱う場面がないため対応不要**
- **devpad のエラー規約が非対称**: `b64decode` / `epochToJst` / `jstToEpoch` は `{error}` を返し、
  `urlDecode` / `unescapeJsonStr` は **throw して UI 側が try/catch** する。
  spec が要求しているのは「エラーバナーが出ること」だけなので**適合しており修正不要**。
  ただし**新しいタブを足すときはどちらかに寄せる判断が必要**
  （2026-08-05 のハーネス作成時に把握。`test/devpad.js` は両方の規約を明示的に照合している）
- **変換中 Cmd+Enter でコピー・整形が走る（excel2md / norm / diff / devpad）**: IME の変換中でも
  修飾キー付き Enter は `isComposing: true` で届き、ハンドラが発火する（実測）。
  ただし動作は**非破壊で入力も保持される**ため**現状維持**。
  判定軸は `docs/verification-notes.md` §8。taskboard だけは破壊的操作だったのでガード済み

## 世間の定番ツールとの総評

**優位点（3エージェント共通の結論）**
- **完全ローカル・オフライン**: 貼り付けデータが端末外に出ない。diffchecker / Tables Generator / JSON 整形サイトに対する決定的優位（業務機密の変換・比較に安心して使える）
- **日本語業務特化**: 全角半角同一視 diff、NFKC の除外集合方式と長音保護（norm）、JST 固定・CP932 概算（devpad）、Excel セル内改行の忠実往復（excel2md）は定番に存在しない
- **「落ちない・嘘をつかない・保存が正確」**: 全ツールで不正入力時に警告＋最善出力、劣化パスの明示、注記（自動保存の範囲）と実挙動の一致を実測確認。この基礎品質は定番ツール以上
- taskboard の「プレーン Markdown 正本＋Obsidian 共存＋競合検知」は Todoist/Things にも Obsidian Tasks 単体にもない組合せ

**劣位点**
- キーボードショートカットの欠如（DevToys・Todoist は主要操作にあり）→ CM-3
- 表示系の薄さ: diff の side-by-side・行番号なし、excel2md のプレビュー・列揃えなし、devpad の JSON ツリー/ハイライトなし
- 機能網羅性は DevToys 等に劣る（ただし単機能分担の設計思想とは整合。水増しは「やらないこと」）
- taskboard: 完了自動退避（→確定項目3）・テキスト検索・クイック追加のキーボード完結性で定番タスク管理に劣る

## 確定3項目の実装方針案（Phase P・承認済み分）

1. **favicon**: 各ページ `<head>` に `<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 100 100'><text y='.9em' font-size='90'>絵文字</text></svg>">`（URL エンコード済みで埋め込み。外部ファイル不要・file:// 動作）。絵文字割当案: ハブ 🧰 / excel2md 📊 / devpad 🛠 / norm 🔤 / diff 🔍 / taskboard ✅
2. **サンプル投入ボタン**: 各入力ペイン見出し横に「サンプルを入れる」リンク。内容案 — excel2md: セル内改行入り 3x3 TSV / devpad: JSON タブに崩れた JSON / norm: 全変換が1回ずつ発火する例文（Ｗｅｂ・ｶﾞ・−・～・連続空白）/ diff: 3種の差分を仕込んだ2テキスト同時投入 / taskboard: ファイル不要の「デモデータを表示」（メモリ上・保存ボタン無効＋デモ中バナー）
3. **taskboard 完了アーカイブ**: ツールバーに「完了をアーカイブ」。表示中の完了行を vault/03_Tasks/archive.md へ追記（ハンドルは初回に picker で取得し IndexedDB に tasks.md と同様に永続化）、tasks.md から除去。両ファイルとも保存前に NFC 外部変更検知。spec に「archive.md がなければ作成/ヘッダ付与/ラウンドトリップ」のテストケースを追加
