# issue 仕様書兼テストケース

## 概要

論点（イシュー）を点検して形にするツール。`web/issue.html`、表示名 `Check Issue`、カテゴリ: タスク（`Plan Tasks` の隣）。
**貼った文章から「これはイシューか」を判定し**、vault の `04_Issues` に貼れる md と
`tasks.md` に貼れる1行を出す。

採択理由: vault 側にイシュー運用（`IssueDriven.md` / `99_Templates/issue.md` /
`_prompts/Issue-driven.md` の5ステップ）を整備したが、**テンプレートは「これはイシューではない」を
教えてくれない**。実際 `04_Issues/2026-09-24_現状整理.md` は論点欄に
「現状を整理し、今後の進め方の確認をする」と書かれたまま通っており、3条件のチェックも空だった。
**代替（md テンプレート）が静かに間違う**箇所に道具を置く（coding-rules「提案が当たるかの判定」条件4）。

## 入力は「貼る」1本（IS-Q1）

coding-rules「提案が当たるかの判定」の実測（**当たり外れは入力コストで決まる。
入力を著述させる道具は使われない** — Draw Gantt の凍結）に従い、**入力欄を分けたフォームにしない**。
左ペインに **5ステップの Markdown をそのまま貼る**。貼る元は既に手元にある:

- `_prompts/Issue-driven.md` を AI に渡した出力（5ステップで返る）
- `04_Issues/` の書きかけノート
- 定例メモ・「なぜ？」の掘削ログ（見出しが無ければ全文が `rest` に入る）

## 5ステップの見出し認識

次の語を**セクション見出し**として認識する（`ゴール` `論点`(別名 `イシュー`) `不明点` `リスク` `次の一手`）。

- 見出しの揺れを許容: `## 1. ゴール` / `## ゴール` / `### 1.ゴール` / `**2. 論点**` / `3. 不明点：`
- 行頭の `- ` `* ` `1. ` は内容から落とす。表の行（`|` 始まり）と区切り行はそのまま内容として拾う
- **どの見出しにも当たらない先頭部分は `rest`**（掘削ログ）。見出しが1つも無ければ全文が `rest`
- `# 見出し` が1本目にあれば `title`（ノートの H1 になる）

## 判定（IS-Q5: 警告であって拒否ではない）

**論点の1行目**と、締切・不明点の有無を見る。`warn` が0件なら「まず外していない」と表示する。

| id | level | 検出 | 根拠（本） |
|---|---|---|---|
| `empty` | warn | 論点が空 | — |
| `about` | warn | 末尾が「について」「の件」「まとめ」「整理」 | 「〜について」で止めない |
| `worktheme` | warn | 「整理/確認/検討/調査/把握/対応/共有」＋「する・します・を行う・を実施」 | 犬の道（作業テーマ） |
| `why` | warn | 先頭が「なぜ」「何故」「どうして」「why」 | **WHY ではなく WHERE / WHAT / HOW** |
| `deadline` | warn | 締切が未入力 | よいイシューの条件③ 答えを出せる |
| `evidence` | warn | 不明点が0件 | 同上（何を見れば白黒つくか） |
| `subject` | info | 「は」も「が」も含まない | 言語化のコツ① 主語と動詞 |
| `compare` | info | 「ではなく／じゃなく／より／それとも／vs」を含まない | 言語化のコツ③ 比較の形 |
| `multiline` | info | 論点が2行以上 | 一行で書く |

- **掘るときの「なぜ」は判定対象外** — `why` が見るのは論点の1行目だけ。
  `rest`（掘削ログ）に「なぜ？」が何個あっても警告しない（`IssueDriven.md` の線引き）

## 出力（IS-Q2 改訂: 04_Issues に直接ノートを作る）

**① ノート（`04_Issues` 用）** — `99_Templates/issue.md` と同じ器で組む

```
---
created: <今日>
deadline: <締切 or 空>
status: open
tags: [issue]
---
# <title or 無題>

→ [[IssueDriven]] ｜ [[イシューの書き方と記入例]]

## 1. ゴール
## 2. 論点
## 3. 不明点   ← 表。各行の「聞く/調べる/試す」は本文から検出して2列目へ
## 4. リスク
## 5. 次の一手
```

- 空のセクションも**見出しだけ残す**（後でノート側で埋めるため）
- `rest` があれば末尾に `## 掘ったログ` として付ける（捨てない）

**③ ［04_Issues にノートを作成］** — File System Access でそのまま書く（Chrome 系）

- 初回に `showDirectoryPicker({ mode: 'readwrite' })` で **`04_Issues` フォルダを選ばせる**。
  **フォルダ名をコードに書かない**（coding-rules「vault 連携」）。選んだハンドルは IndexedDB に保存し、
  2回目以降は選び直さない。**保存に失敗しても機能は動く**（毎回選ぶだけ）
- ファイル名は `YYYY-MM-DD_<タイトル>.md`（vault-rules の命名規則）。
  タイトルが空なら `無題`。ファイル名に使えない文字（`\ / : * ? " < > |`）は `-` に置換
- **同名のノートが既にあれば上書きせず warn で止める**（タイトルを変えてもらう）
- 書けたら success バナーに作成したファイル名を出す
- 権限は押した時点で `queryPermission` → 必要なら `requestPermission`（クリックのジェスチャ内）
- **FSA 非対応（Safari / Firefox）ではボタンを無効にし、理由を出す**（`Check Vault` と同型）。
  コピー経路は常に使える

**② tasks.md 用の行** — `次の一手` の各行を Obsidian Tasks 記法に

- `- [ ] <内容>`、締切があれば ` 📅 YYYY-MM-DD` を付ける
- 既に `- [ ]` で始まっていれば二重に付けない

## UI

- `<main class="app-wide">`・`.tool-header`・2ペイン（左=貼る / 右=ノート md）
- ツールバー: **［04_Issues にノートを作成］(`primary`)** ・［md をコピー］(`title="Cmd/Ctrl+Enter"`)・［tasks.md 用の行をコピー］・
  締切（`<input type="date">`）・タイトル（`<input type="text">`）
- 判定結果は入力の下に一覧表示（warn は `banner-warn` 相当の見た目、info は控えめ）
- 入力は 200ms デバウンスでリアルタイム判定。**コピー時に確定**（ハンドラ先頭で `clearTimeout + run()`）
- サンプル投入ボタン（`.sample-btn`）は入力が空のときだけ表示
- 入力欄に `ToolEdit.tabIndent(el, {mdList:true})`（md を書く欄 — coding-rules）、
  `ToolEdit.mountTodayShortcut()`（締切に Ctrl/Cmd+;）

## 保存

- localStorage（`tools:issue`）に**入力・タイトル・締切**を自動保存（300ms デバウンス＋
  pagehide / visibilitychange(hidden) フラッシュ）
- 1フィールド 100KB 超は `{omitted: true}` にして次回起動時に info バナー

## 純関数・フック

```
window.issue = {
  parseSections(text) → { title, goal[], issue[], unknowns[], risks[], next[], rest[] },
  judge(line, { deadline, unknowns }) → [{ id, level, msg, fix }],
  toNote(parsed, { deadline, today, title }) → md 文字列,
  toTasks(nextLines, { deadline }) → md 文字列
}
```

## 検証手順

> **合否の正本は `./test/run issue` が全 pass（コンソールエラー0件を含む）。**

## やらないこと

- **論点文の自動生成**（IS-Q4）— 純関数では不可能。AI の領分（`_prompts/Issue-driven.md` が担当）
- **イシューの一覧・進捗・ステータス管理**（IS-Q3）— 管理ツール化して tool-backlog の原則2で落ちる。
  正本は `04_Issues/` のノートであり、ツールは第二の正本を持たない
- **既存ノートの書き換え・削除・リネーム**（IS-Q2）— 作るのは**新規ノート1本だけ**。
  同名が既にあれば**上書きせず warn で止める**（vault-rules の掟②「削除・一括リネームは提案まで」）
- **`tasks.md` への直接書き込み** — 正本は `Plan Tasks` が持つ。二重の書き手を作らない。
  こちらは Tasks 記法の行をコピーで渡すだけ
- **ツール間の受け渡しの受け口**（IS-Q6）— v1 では作らない。
  `hub.routeText` の判定追加は既存の検索・ルーティングのテスト集合を動かすため、
  実際に「ハブから来たい」と思った回が出たら別件で足す

## 決定事項（2026-09-24）

- **IS-Q1**: 入力は「貼る」1本。欄分けフォームにしない（入力コストが当たり外れを決めるという実測）
- **IS-Q2（2026-09-24 に改訂）**: **`04_Issues` にノートを直接作る。**
  初版は「書き込まない」としていたが、利用者の指摘「普通に task みたいにそのままノートを
  作ってくれた方が助かる」により撤回。**既存の前例（`Plan Tasks` が `tasks.md` を、
  `Check Vault` が vault 全体を書き換えている）と CLAUDE.md「永続データの正本は vault 側」
  に照らすと、書き込まない方が例外だった。** コピーも残す（FSA 非対応ブラウザの経路）
- **IS-Q3**: 一覧・進捗・ステータスを持たない
- **IS-Q4**: 論点文の自動生成はしない（判定と整形だけ）
- **IS-Q5**: 判定は warn / info の2段。**拒否しない**（不正入力でも落ちず最善の出力 — coding-rules）
- **IS-Q6**: handoff の受け口は v1 では作らない
- **IS-Q7**: 書き込み先は **`showDirectoryPicker` で利用者に選ばせる**（`lib/config.js` に
  フォルダ名を足さない）。ハンドルは IndexedDB に保存して2回目以降は選び直さなくてよい。
  **保存に失敗しても機能は動く**（毎回選ぶだけ）ので best-effort。
  カテゴリを「発想」から「タスク」へ移したのも同じ指摘による（`Plan Tasks` の隣が探しやすい）
