# issue 仕様書兼テストケース

## 概要

論点（イシュー）を点検して形にするツール。`web/issue.html`、表示名 `Check Issue`、カテゴリ: タスク（`Plan Tasks` の隣）。
**開くと `04_Issues` のイシューがカードで並ぶ**（主）。［イシューを書く］のウィザードで新しく作り、
カードから**閉じて振り返る**。貼った文章の点検もできる（折りたたみ）。

採択理由: vault 側にイシュー運用（`IssueDriven.md` / `99_Templates/issue.md` /
`_prompts/Issue-driven.md` の5ステップ）を整備したが、**テンプレートは「これはイシューではない」を
教えてくれない**。実際 `04_Issues/2026-09-24_現状整理.md` は論点欄に
「現状を整理し、今後の進め方の確認をする」と書かれたまま通っており、3条件のチェックも空だった。
**代替（md テンプレート）が静かに間違う**箇所に道具を置く（coding-rules「提案が当たるかの判定」条件4）。

## 入力は「貼る」1本（IS-Q1）

coding-rules「提案が当たるかの判定」の実測（**当たり外れは入力コストで決まる。
入力を著述させる道具は使われない** — Draw Gantt の凍結）に従い、**入力欄を分けたフォームにしない**。
左ペインに **5ステップの Markdown をそのまま貼る**。貼る元は既に手元にある:

- `_prompts/Issue-driven.md` を AI に渡した出力（5ステップで返る）
- `04_Issues/` の書きかけノート
- 定例メモ・「なぜ？」の掘削ログ（見出しが無ければ全文が `rest` に入る）

## 5ステップの見出し認識

次の語を**セクション見出し**として認識する。

| 見出し | キー | 備考 |
|---|---|---|
| ゴール | `goal` | マイルストーン |
| 論点 / イシュー | `issue` | 1行目が判定対象 |
| **絵コンテ** | `picture` | 2026-09-24 追加（本の第3章） |
| **サブイシュー** / 不明点 | `subs` | **旧「不明点」も同じ枠へ**（既存ノートを壊さない） |
| リスク | `risks` | **旧枠**。新規では作らないが、既存ノートの内容は保持する |
| 次の一手 | `next` | |
| **分かったこと** / **結論** | `found` / `conclusion` | 2026-09-24 追加（**閉じられないと振り返れない**） |
| 掘ったログ | `rest` | 見出しに当たらない部分もここ |

- 見出しの揺れを許容: `## 1. ゴール` / `## ゴール` / `### 1.ゴール` / `**2. 論点**` / `3. 不明点：`
- 行頭の `- ` `* ` `1. ` は内容から落とす。表の行（`|` 始まり）と区切り行はそのまま内容として拾う
- **どの見出しにも当たらない先頭部分は `rest`**（掘削ログ）。見出しが1つも無ければ全文が `rest`
- `# 見出し` が1本目にあれば `title`（ノートの H1 になる）

## 判定（IS-Q5: 警告であって拒否ではない）

**論点の1行目**と、締切・不明点の有無を見る。`warn` が0件なら「まず外していない」と表示する。

| id | level | 検出 | 根拠（本） |
|---|---|---|---|
| `empty` | warn | 論点が空 | — |
| `about` | warn | 末尾が「について」「の件」「まとめ」「整理」 | 「〜について」で止めない |
| `worktheme` | warn | 「整理/確認/検討/調査/把握/対応/共有」＋「する・します・を行う・を実施」 | 犬の道（作業テーマ） |
| `why` | warn | 先頭が「なぜ」「何故」「どうして」「why」 | **WHY ではなく WHERE / WHAT / HOW** |
| `deadline` | warn | 締切が未入力 | よいイシューの条件③ 答えを出せる |
| `evidence` | warn | サブイシューが0件 | 同上（何を見れば白黒つくか） |
| `picture` | warn | 絵コンテが空 | **欲しい絵が描けないなら、まだイシューが定まっていない**（第3章） |
| `alternatives` | info | 論点の候補が2つ未満（候補を渡したときだけ判定） | 解ける問題の中から選ぶ（イシュー度 — 第1章） |
| `subject` | info | 「は」も「が」も含まない | 言語化のコツ① 主語と動詞 |
| `compare` | info | 「ではなく／じゃなく／より／それとも／vs」を含まない | 言語化のコツ③ 比較の形 |
| `multiline` | info | 論点が2行以上 | 一行で書く |

- **掘るときの「なぜ」は判定対象外** — `why` が見るのは論点の1行目だけ。
  `rest`（掘削ログ）に「なぜ？」が何個あっても警告しない（`IssueDriven.md` の線引き）

## 出力（IS-Q2 改訂: 04_Issues に直接ノートを作る）

**① ノート（`04_Issues` 用）** — `99_Templates/issue.md` と同じ器で組む

```
---
created: <今日>
deadline: <締切 or 空>
status: open
tags: [issue]
---
# <title or 無題>

→ [[IssueDriven]] ｜ [[イシューの書き方と記入例]]

## 1. ゴール
## 2. 論点
## 3. 絵コンテ
## 4. サブイシュー   ← 表。各行の「聞く/調べる/試す」は本文から検出して2列目へ
## 5. 次の一手
（## リスク — 既存ノートに書かれていた場合のみ）
## 分かったこと
## 結論          ← **ここが無いとイシューを閉じられず、振り返りの素材が残らない**
```

- 空のセクションも**見出しだけ残す**（後でノート側で埋めるため）
- `rest` があれば末尾に `## 掘ったログ` として付ける（捨てない）

**③ ［04_Issues にノートを作成］** — File System Access でそのまま書く（Chrome 系）

- 初回に `showDirectoryPicker({ mode: 'readwrite' })` で **`04_Issues` フォルダを選ばせる**。
  **フォルダ名をコードに書かない**（coding-rules「vault 連携」）。選んだハンドルは IndexedDB に保存し、
  2回目以降は選び直さない。**保存に失敗しても機能は動く**（毎回選ぶだけ）
- ファイル名は `YYYY-MM-DD_<タイトル>.md`（vault-rules の命名規則）。
  タイトルが空なら `無題`。ファイル名に使えない文字（`\ / : * ? " < > |`）は `-` に置換
- **同名のノートが既にあれば上書きせず warn で止める**（タイトルを変えてもらう）
- 書けたら success バナーに作成したファイル名を出す
- 権限は押した時点で `queryPermission` → 必要なら `requestPermission`（クリックのジェスチャ内）
- **FSA 非対応（Safari / Firefox）ではボタンを無効にし、理由を出す**（`Check Vault` と同型）。
  コピー経路は常に使える

**［md をコピー］は FSA が使えないときだけ出す**（2026-09-24。利用者「コピー用は必要ない。
そのまま 04_Issues に保存できるんだよね？」）。直接保存できる環境では経路が2つあると迷うだけで、
Safari / Firefox では**唯一の経路**なので消さない。`Cmd/Ctrl+Enter` は
**そのとき有効な方**（作成 or コピー）に向ける。右ペインは「作られるノート（プレビュー）」として残す。

**② tasks.md 用の行** — `次の一手` の各行を Obsidian Tasks 記法に

- `- [ ] <内容>`、締切があれば ` 📅 YYYY-MM-DD` を付ける
- 既に `- [ ]` で始まっていれば二重に付けない

## モード切替（`Plan Tasks` と対）

`.tool-header` の下に**セグメント**を置き、1クリックで相手へ移る。
`Plan Tasks` 側にも同じものを置く（`docs/specs/taskboard.md`）。ハブからは従来どおり両方開ける
＝「どちらのモードでその画面を開くか」。

```
← ツール一覧
[ ✅ タスク ][ 🎯 イシュー ]      ← 今いる方が aria-current="page"
```

- マークアップは `<nav class="modes">` ＋ リンク2本。**スタイルは `lib/ui.css` の `.modes`**（2ツールで共有）
- 状態は引き継がない（別ツール・別 localStorage）。`handoff` も使わない

## 入力ウィザード（IS-Q8 — ここが道具の本体）

**ただの md 入力欄では Obsidian と同じで、思考の順番を持たない。**
［イシューを書く］でモーダルを開き、**1問ずつ・逆算の順に**答えさせる。

| Step | 問い | 入力 | 添える一行（訓練） |
|---|---|---|---|
| 1/5 | **いつまでに、何が達成されていればいい？** | 状態（複数行）＋ 期限 | ここが決まらないと何を問うかも決まらない（最終形からたどる） |
| 2/5 | **答えを出すべき問いの候補を出して、1つ選ぶ** | 候補（既定2行・各行に「答えが出たら誰の何が変わる？」）＋ 選択 ＋ **決着期限** | イシュー度で選ぶ。解ける問題の中から最もインパクトのあるものを選ぶ |
| 3/5 | **答えが出たとき、最後に何を出す？** | 形（表 / グラフ / 一文 / 画面）＋ 中身 | **欲しい絵が描けないなら、まだイシューが定まっていない**（絵コンテ＝イシューの検算） |
| 4/5 | **答えが出る大きさまで割ると？** | 行ごとに 内容・**聞く/調べる/試す**・誰に・いつまでに | 崩れたら全部やり直しになるものを上に（最重要サブイシューから） |
| 5/5 | **最初に潰すのは？** | 内容 ＋ 期限 ＋ **ノートの名前** | 回転数 × スピード。60%で全体を回す |

- **Step 1・2・3 は必須**（空では次へ進めず、理由をその場に出す）。
  マイルストーンを飛ばして論点を書けず、**絵コンテを描けないまま先へ進めない**のがウィザードの目的。
  Step 3 を必須にしたのは、本で最も強い検算がここだから（描けない＝イシューが定まっていない）
- **Step 2 の候補欄は既定で2行**出す。1つしか埋めなくても進めるが `alternatives` の info が出る
  （選別していないことを可視化する。**拒否はしない** — IS-Q5）
- **旧「リスク」のステップは廃止**（本に対応物が無く、本の3章分が欠けている一方で1ステップを専有していた）。
  既存ノートの `## リスク` の内容は `toNote` が保持する
- **Step 2 では判定がその場に出る**（`judge` と同じ純関数。作業テーマ・WHY 始まりなどを即指摘）
- 進捗は `● ○ ○ ○ ○`。［← 戻る］で前へ。**Esc で閉じても下書きは残る**（非破壊なので IME ガード不要）
- 最後の［04_Issues に作成］で **md を組み立てて入力欄へ流し込み**、既存の作成経路をそのまま通る
  （判定・出力・書き込みの実装を二重に持たない）

## 一覧（IS-Q10 — 2026-09-24。ここが画面の主）

利用者「**Issue もタスクみたいに一覧にしたい。今のままだと使わない**」。

**原因の診断**: `Plan Tasks` は開いた瞬間にタスクが並ぶので「見るため」に毎日開き、
ついでに編集される。`Check Issue` は**作るときにしか用が無く**、それ以外の日は開く理由がゼロだった
（開いても空の textarea が2つ出るだけ）。**道具が使われるかは「毎日開く理由があるか」で決まる。**

- 起動時、IndexedDB に覚えたフォルダハンドルがあれば**自動で読み込んで並べる**（選び直し不要）
- 並びは**締切の早い順**（締切なしは最後）。期限切れは強調
- フィルタ: 開いているもの（既定）/ すべて / 閉じたもの
- 上限 **200件**（超えたら読み込まず理由を出す — 性能ガードは処理の前に弾く）

### カード1枚の中身（上から重要な順）

| 位置 | 出すもの | なぜ |
|---|---|---|
| 1 | タイトル ＋ 締切（残日数） | 急ぐかどうかが一目で分かる |
| 2 | **論点の一行（最も大きく）** | 眺めるだけで「いま何に答えようとしているか」が入る＝訓練 |
| 3 | 絵コンテ / 次の一手（＋期限）/ サブイシュー件数（聞く・調べる・試すの内訳） | 次の一手が分かる |
| 4 | **引っかかり N 件**（`judge` の warn。押すと展開） | 直すべき点がその場で見える |
| 5 | ［Obsidian で開く］［閉じる…］ | `vaultName` 未設定なら Obsidian リンクは作らない（押しても開かないリンクを作らない） |

### 論点は「ノートの中の1行」（IS-Q12 — 2026-09-24。**決めずに両対応にする**）

利用者「**書き殴っていかないと論点が見えてこない。そこまで頭の中で整理した状態で論点って出てこない**」。

**1ノート = 1論点は実データで既に破綻している** — 9/24 のノートには少なくとも3つの論点
（停止手順書の粒度 / V13 の再受領 / 12月本番運用の範囲）が同居している。
論点が**見える前に**ノートを分けることはできない。

**最初の診断（2026-09-24）で書いていたことに戻る**:
> `tasks.md` が続いているのは、**1行で完結する最小単位**があるから。
> イシュー側に同等の1行の最小単位が無いことが、継続しない直接の原因。

- **記法は `tasks.md` と同じ**（覚えることを増やさない・Obsidian の Tasks プラグインも拾える）

```markdown
## 論点
- [ ] 手順書が書けないのは情報不足ではなく、粒度の合意が無いからではないか 📅 2026-09-30
- [ ] V13 の期限に間に合わないのは再受領の可否が未確認だからではないか 📅 2026-10-02 [[2026-09-24_V13再受領]]
- [x] 検証は OS のみでよいのではないか 📅 2026-09-20 ✅ 2026-09-24 外れ
```

- **カードの単位はノートの中身で決まる（移行不要）**:
  - `## 論点`（`## 2. 論点` も同じ）に `- [ ]` 行がある → **行ごとに1枚**
  - 無い → **ノートで1枚**（従来どおり・5段のメタを出す）
  - **どちらが正しいかは決めない。**行が増えるかどうかで実測する
- **閉じる**は行を `- [x] … ✅ <今日> <判定>` にする（ノートの frontmatter は触らない）。
  ノートカードのときは従来どおり frontmatter の `status`/`verdict`
- **切り出し**（IS-Q13）: 行カードの［ちゃんと立てる…］→ ウィザード →
  **新しいノート（5段の器）を作り、元の行に `[[リンク]]` を残す**。
  切り出したノートは `## 論点` を持たないので**ノートカード1枚**になる（入れ子にならない）

### タスクは論点の下に生まれる（IS-Q14 — 2026-09-24 監査 R8）

利用者の要求「**必要なタスクを考える前にタスクを検証するところから**」。
監査時点では、論点を立てる経路と Plan Tasks でタスクを足す経路が**独立**していて、
タスクを作る瞬間に「どの論点のためか」を問う場所が無かった。

- カードの［**タスクにする…**］→ `ToolHandoff.send('taskboard', 'task', JSON, 'taskboard.html')`。
  JSON は `{ content（次の一手 or 空）, issue, memo: '論点: …', due, link: ノート名 }`
- `Plan Tasks` 側は起動時に `take('taskboard')` で受け、**tasks.md を読み込めた瞬間**に追加モーダルを
  内容・メモ（論点）・期限・関連ノート `[[…]]` 入りで開く（`docs/specs/taskboard.md` TB-H2）
- 受け取り無しでも、追加モーダルに「**この一手はどの論点のため？**」を一言だけ常設（TB-H3）。
  答えは強制しない — **問いが毎回見える**ことが訓練

|---|---|---|
| R1 選別 | 切り出し時、**同じノートの他の開いている論点を候補に並べる**（書き殴りで見えた複数の論点が本物の候補） | IS-UL13 |
| R7 ノイズ | ウィザード Step 2 の判定は**論点の段階だけ**（絵コンテ・サブは Step 3・4 で問う） | IS-U24 |

| R10 初見 | ノート0なら**使い方（3手順）**を開いて出す／［新しく立てる（5段）］は主役から降ろす（主役はカード） | IS-U25 |

### 書き殴りに問いを立てる（IS-Q11 — 2026-09-24。**実測に合わせた最重要の設計**）

**実測**: 利用者は**新しいノートを作らず1本を育てている**。04_Issues は2本のままで、
9/24 のノートが同日中に 3.8KB → 7.2KB（186行）に伸びた。中身は箇条書きの入れ子・TODO・
確認事項・日程で、旧テンプレの2〜5章は空。**しかも書き殴りの末尾に本人がこう書いている**:

```
- マイルストーンを考える
- いつまでに何をゴールにするか
- 結局必要なOUTPUTは何か
```

これはウィザードの Step1（マイルストーン）と Step3（絵コンテ）そのもの。
**問いは合っていて、渡し方が間違っていた** — ウィザードが必ず新規ノートを作るため、
育てているノートと分裂していた。

**書き殴りは Obsidian のままでよい。**ツールは「読んで、問いを立てる手伝い」に回る。3段階にする。

| 段階 | どこで | 手数 |
|---|---|---|
| ① 書き殴る | Obsidian（変えない） | — |
| ② **論点を一行だけ書く** | カードの論点をクリック → その場で打つ（判定もその場） | 1行 |
| ③ 5段フル | ［このノートに問いを立てる…］→ ウィザード | 5問 |

- **②**: `## 2. 論点` があれば中身を差し替え、無ければ**本文の先頭に節を作る**。
  注記行（`>` 始まり）は残す。締切は frontmatter へ（frontmatter が無ければ論点だけ書いて info）
- **③**: ウィザードは**既存ノートの先頭に5段を差し込む**（`upsertFrame`）。
  2回目以降は**その範囲だけ差し替える**ので重複しない。**書き殴りには一切触らない**。
  モーダルに「このノートの中身を見る」を出し、書き殴りを横に見ながら埋められる。
  既に書かれている分（ゴール・論点・絵コンテ・サブ・次の一手）は初期値に入る
- ［🎯 イシューを書く］（新規作成）は残す。**書き込み先が2通りある**ことをボタンの文言で示す
  （「04_Issues に作成」／「このノートに書き込む」）
- 編集中は**読み込み時の判定件数を隠す**（ライブ判定と数が食い違って見えるため）

### 閉じる ＝ 振り返り（IS-Q2 の再改訂）

［閉じる…］→ **当たり / 外れ / 未決**を選び、「次はどう立て直す？」を1行書く。

- ノートの **`status` と `verdict` の2キーを差し替え、`## 結論` に1行追記するだけ**。本文は触らない
- **書き込む直前に再読して NFC 比較**し、外部で変わっていたら**書かずに警告**
  （`Plan Tasks` の保存と同じ鮮度チェック — coding-rules「vault 連携」）
- frontmatter が無いノートには**書き込まない**（手書きのノートを壊さない）

## UI

- `<main class="app-wide">`・`.tool-header`・**1カラム**。上から ツールバー → カード一覧 →
  「書いたものを貼って点検する」（`<details>`・既定は閉じる）

## 純関数・フック

```
window.issue = {
  parseSections(text) → { title, goal[], issue[], unknowns[], risks[], next[], rest[] },
  judge(line, { deadline, unknowns, picture, candidates }) → [{ id, level, msg, fix }],
  toNote(parsed, { deadline, today, title }) → md 文字列,
  toTasks(nextLines, { deadline }) → md 文字列,
  buildMd(draft) → 5ステップの md（ウィザードの下書き → 入力欄）,
  issueLines(text) → [{ lineNo, raw, text, done, due, doneDate, verdict, link }],
  addIssueLine(text, line, due) → text（`## 論点` の末尾に1行。節が無ければ本文の先頭に作る）,
  replaceLine(text, lineNo, raw) → text,
  closeLineRaw(raw, verdict, today) → raw（`- [x]` ＋ ✅日付 ＋ 判定）,
  linkLineRaw(raw, noteName) → raw（`[[ノート名]]` を足す）,
  parseFrontmatter(text) → { data, body, has },
  setFrontmatter(text, patch) → text（**本文は一切変えない**。frontmatter が無ければ何もしない）,
  appendToSection(text, '## 結論', '- 行') → text,
  subRows(lines) → [{ what, way }]（表の見出し行・区切り行を除く）,
  summarize(text, fileName) → カード1枚分の要約
}
```

## 検証手順

> **合否の正本は `./test/run issue` が全 pass（コンソールエラー0件を含む）。**

### 実機スモーク（人手・自動化不能）

IS-U10/U11 はダミーの `showDirectoryPicker` で書き込み経路を通しているが、
**実際のピッカー・権限ダイアログ・ハンドルの再利用は自動化できない**
（coding-rules「自動化できない層は spec の実機スモーク節に列挙して人間に依頼する」）。
Chrome で `web/issue.html` を `file://` で開き、次を確認する:

1. ［04_Issues にノートを作成］→ フォルダ選択ダイアログが出る → `04_Issues` を選ぶ →
   書き込み許可を与える → `YYYY-MM-DD_<タイトル>.md` が実際に作られ、Obsidian 側に現れる
2. **ページを再読込してもう一度作成** → **フォルダを選び直さずに書ける**
   （IndexedDB のハンドルが効いている。権限の再許可ダイアログは出てよい）
3. 同じタイトルでもう一度押す → **上書きされず** warn が出る
4. ダイアログをキャンセル → **何も起きない**（エラーバナーを出さない）

## やらないこと

- **論点文の自動生成**（IS-Q4）— 純関数では不可能。AI の領分（`_prompts/Issue-driven.md` が担当）
- **イシューの一覧・進捗・ステータス管理**（IS-Q3）— 管理ツール化して tool-backlog の原則2で落ちる。
  正本は `04_Issues/` のノートであり、ツールは第二の正本を持たない
- **既存ノートの書き換え・削除・リネーム**（IS-Q2）— 作るのは**新規ノート1本だけ**。
  同名が既にあれば**上書きせず warn で止める**（vault-rules の掟②「削除・一括リネームは提案まで」）
- **`tasks.md` への直接書き込み** — 正本は `Plan Tasks` が持つ。二重の書き手を作らない。
  こちらは Tasks 記法の行をコピーで渡すだけ
- **ツール間の受け渡しの受け口**（IS-Q6）— v1 では作らない。
  `hub.routeText` の判定追加は既存の検索・ルーティングのテスト集合を動かすため、
  実際に「ハブから来たい」と思った回が出たら別件で足す

## 決定事項（2026-09-24）

- **IS-Q1**: 入力は「貼る」1本。欄分けフォームにしない（入力コストが当たり外れを決めるという実測）
- **IS-Q2（2026-09-24 に改訂）**: **`04_Issues` にノートを直接作る。**
  初版は「書き込まない」としていたが、利用者の指摘「普通に task みたいにそのままノートを
  作ってくれた方が助かる」により撤回。**既存の前例（`Plan Tasks` が `tasks.md` を、
  `Check Vault` が vault 全体を書き換えている）と CLAUDE.md「永続データの正本は vault 側」
  に照らすと、書き込まない方が例外だった。** コピーも残す（FSA 非対応ブラウザの経路）
- **IS-Q3**: 一覧・進捗・ステータスを持たない
- **IS-Q4**: 論点文の自動生成はしない（判定と整形だけ）
- **IS-Q5**: 判定は warn / info の2段。**拒否しない**（不正入力でも落ちず最善の出力 — coding-rules）
- **IS-Q6**: handoff の受け口は v1 では作らない
- **IS-Q14**: **タスクは論点の下に生まれる。**カードから Plan Tasks を論点つきで開く経路を作り、
  Plan Tasks 側にも「どの論点のため？」の一言を常設。tasks.md への直接書き込みはしない（書き手を2つにしない）

  **カードの単位はノートの中身で自動的に切り替える**（`## 論点` の行があれば行ごと、無ければノート）。
  1ノート=1論点か1行=1論点かは**決めない** — 移行不要にして、行が増えるかどうかで実測する

- **IS-Q10**: **一覧を画面の主にする**（利用者「今のままだと使わない」）。

- **IS-Q8**: 入力は**1問ずつのウィザード**にする（利用者「ただのテキスト入力欄であれば Obsidian で良い」
