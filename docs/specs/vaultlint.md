# vaultlint 仕様書兼テストケース

## 概要

Obsidian vault の健全性を検査するツール。`web/vaultlint.html`、表示名 `Check Vault`、カテゴリ: 整理。
**検査は読み取りのみ。修復は「提案 → 承認 → 実行」**（v2・2026-08-14 — vault の掟
「削除・一括リネームは提案まで、実行は本人の承認後」の承認フローをツール内に実装。
詳細は「修復」節）。`showDirectoryPicker` で vault を選び、`.md` を走査してクラス別に報告する。

根拠: vault の `_rules/backlog.md`（2026-08-03 の整理フェーズ）が、この検査を手動で行って
計測バグを踏み（32件→実は40件）、クラス分類を人力で行い「着手時に再調査すること」と
書き残している。実務ペインの記録が着手根拠（tool-backlog 2026-08-13 承認）。

## 検査クラス（この列挙が正本）

| クラス | 内容 |
|---|---|
| brokenLinks | `[[ターゲット]]`（`![[...]]` 含む）が解決できない。エイリアス `\|`・見出し `#`・ブロック `#^` は剥がして本体で判定。`[[#見出し]]`（自ファイル参照）は対象外 |
| missingAttachments | `![[名前.拡張子]]` および md リンク `![alt](相対パス)` の実体が無い（`http(s):`・`data:`・`obsidian:` は対象外。`%20` 等はデコードして照合） |
| badNames | ファイル名の罠: 連続半角スペース／全角スペース(U+3000)／NBSP(U+00A0)／先頭・末尾スペース／空ベース名（`.md`）。**フォルダ名も対象** |
| dupBasenames | 同じベース名の `.md` が複数**かつ、パス修飾なしのリンクがその名前を指している**もの（＝実際に曖昧）。パス一覧を出す |

## リンク走査の対象外（2026-08-14・VL-13）

**コードフェンス（``` / ~~~）の内側と、インラインコード（`` ` ``〜`` ` ``）の内側は走査しない**。
Obsidian はコード内のリンクを解決しないため、shell の `[[ -f file ]]` などを
リンク切れと誤検出する（v1 の欠陥。実 vault の 30_Resources に該当ノートあり）。
閉じフェンスが無い場合は末尾までコード扱い（doc2xl と同じ解釈）。

## リンク解決規則

- ターゲットに `/` を**含む**: vault ルート相対パスとして照合（`.md` 省略可）
- 含まない: ベース名照合
- 比較は **NFC 正規化＋小文字化**（macOS の実態に合わせ大文字小文字は同一視）
- 添付（非 md ファイル）はベース名で解決（Obsidian の「最短一致」相当。厳密な最短パス選択はしない — 存在すれば OK）

## 設定（2026-08-17・公開に伴う汎用化 — VL-Q6）

vault のフォルダ構成は利用者ごとに違うため、**フォルダ名をコードに書かない**。
値は `lib/config.js`（`localStorage` の `tools:config`）が持ち、画面上の設定欄で編集する。

| 設定 | 既定 | 意味 |
|---|---|---|
| `privateDirs` | `null`（**未設定**） | 読み込み自体をしない非公開フォルダ名の配列 |
| `inboxDir` | `''` | Inbox 棚卸しの対象フォルダ。空 = 棚卸しをしない |
| `archiveDir` | `''` | 棚卸しの移動先フォルダ。空 = 移動を提案しない |

- **`privateDirs === null`（未設定）と `[]`（除外なしと決めた）は区別する。**
  未設定のうちは［vault フォルダを選択］を**無効化し、理由を表示する** —
  未設定のまま走査すると非公開ノートを読み込む事故になるため（旧「`91_Private/` をコードで
  強制除外」＝ vault の掟① の一般化）。除外なしでよければ空欄のまま［設定を保存］を押す
- テストは `window.vaultlint.test.setConfig(cfg)` で構成を宣言する（**保存はしない**）

## 除外（読み込み自体しない）

- **設定した `privateDirs`**（未設定ならそもそも走査を開始しない）
- **`.obsidian/`・`.git/`・`.trash/` は設定に関係なく常に除外**（設定不可）
- 除外したディレクトリ数を統計に出す（黙って飛ばさない）

## Inbox 棚卸し（検査クラス5・2026-08-14）

- 対象: **設定した `inboxDir` 直下**の**純デイリー**（ベース名が `YYYY-MM-DD.md`）。
  サブフォルダのノートは純デイリーとして扱わない。
  それ以外の Inbox ノートは**件数のみ**報告する（内容判断はツールの領分外）
- **`inboxDir` が空なら検査自体をしない。** このとき検査クラス一覧から Inbox 棚卸しを
  **外す**（0件として「問題なし ✅」と表示すると、検査していないものを検査済みと偽ることになる）
- `lint(files, today)` — today（`YYYY-MM-DD`）を引数で受ける（テスト可能性。UI は当日）
- **7日より古い**デイリーを「アーカイブ候補」として報告。ただし**フェンス外に生の
  `- [ ]` が残る**ものは「未転記タスクあり（N件）」として候補から分けて提示
  （デイリーテンプレートの「今日やる」は ```tasks クエリなので生の `- [ ]` は手書きタスク）
- issue 形: `{ path, date, age, pending }`（pending = 未転記タスク行数）

## 修復（2026-08-14・v2 — 掟②「提案 → 承認 → 実行」の実装）

**VL-Q3 改訂の経緯**: v1 は「報告のみ」だったが、利用者から「毎回手で直すのか」の指摘。
掟②は「勝手に実行するな」であって「手でやれ」ではない — 選択式の承認 UI を挟めば適合する。

2段階の純関数（フックと UI が同一コードパス）:

- `planFixes(files, selections)` → `{ writes: [{path, before, after}], moves: [{from, to}],
  skipped: [{path, reason}], summary }` — 何をどう変えるかの**計画**（副作用なし）
- 適用はアダプタが行い、**書き込み直前にファイルごとに再読して読み込み時点と NFC 比較**。
  外部変更があればそのファイルは**スキップして報告**（taskboard の外部変更検知と同じ）

修復メニュー（チェックボックス選択式）:

| 検査 | 修復 | 既定 |
|---|---|---|
| brokenLinks | **テキスト化**（`[[x]]`→`x`・`[[x\|別名]]`→`別名`） | ON |
| brokenLinks | 行削除 — **行がリンクだけのときのみ選択可** | 個別選択 |
| missingAttachments | **参照トークンのみ除去**（行は残す。隣接する片側の空白も1つ除去） | 個別選択 |
| badNames（**ファイル名のみ**） | リネーム＋**リンク元の追随**（`[[旧]]`・`[[旧\|…]]`・`[[旧#…]]`・パス修飾。フェンス内は触らない）。**rename 先が既存と衝突する項目は実行不可として提示** | ON |
| inbox | 設定した `archiveDir` へ移動（フォルダは無ければ作成。移動先に同名があればスキップ）。**`archiveDir` が空なら移動を提案しない** | ON |

### 重複ベース名は「実害があるときだけ」出す（VL-Q12 — 2026-09-24）

**同名であること自体は問題ではない。**問題は「パス修飾なしのリンクがその名前を指していて、
どれに解決されるか決まらない」こと。旧実装は同名を全部出していた。

実測（利用者の vault・2026-09-24）: **重複ベース名18件に対し、パス修飾なしリンクは0件**。
つまり全部が実害ゼロで、しかも10件は**直してはいけないもの**だった
（`.claude/commands` と `.cursor/commands` は `_prompts/` のミラーで CLAUDE.md が定めた設計、
1on1 は人ごとにフォルダで分ける設計）。**直せないものが並ぶ報告は読まれなくなる。**

→ リンク走査で**パス修飾なしで指された名前**を集め、それに当たる重複だけを報告する。

**修復しないもの（報告のみ）**: 重複ベース名（どちらを指すべきか人間にも自明でない）／
**フォルダ名の罠**（子パス全体と全リンクの書き換えになり影響が大きすぎる — 提示のみ）

実行フロー（UI）: read 権限で検査 → 修復にチェック → ［選択した N 件を修復］→
**このとき初めて readwrite を要求**（二段階権限）→「obsidian-git でコミット済みか」の確認
（**git コミットが唯一の undo** — UI に明示）→ 実行 → **実行ログ**（変更ファイル・
before/after・スキップと理由）を表示＋コピー可 → 自動で再スキャン

## 画面構成

- `<main class="app">` 直下: `.tool-header`（「← ツール一覧」＋「このツールは何も保存・変更しません」）
- `<h1>Check Vault</h1>`・subtitle
- ［vault フォルダを選択］ボタン（`showDirectoryPicker`。**Chrome 系限定** —
  API が無いブラウザではボタンを無効化して理由を表示）／［再スキャン］（選択済みのとき）
- 結果: サマリ行（`ファイル N・ノート M・リンク L ／ 問題 K 件`）＋クラス別の表
  （ファイル・行番号・対象・補足）。0件のクラスは「問題なし ✅」
- ［報告をコピー］: Markdown（見出し＋クラス別リスト）。vault の `_rules/backlog.md` に
  そのまま貼れる形式
- ハンドルの永続化はしない（整理は低頻度。毎回選ぶ。要望が出たら taskboard の
  IndexedDB 方式を lib 化して共有 — tool-backlog に判断記録）

## 性能ガード（超過時は処理せず理由を表示。一部のみ処理はしない）

- ファイル総数 20,000 超で中止
- 1ファイル 2,000,000 文字超の md は**その場で読み飛ばして警告**（リンク抽出をしない）

## 純関数（フックと UI が同一コードパス）

`window.vaultlint.lint(files)` — `files = [{ path, text }]`（text は md のみ。添付は path だけ）
→ `{ issues: {brokenLinks, missingAttachments, badNames, dupBasenames}, stats, warnings }`

- issue の形: `{ file, line, target, note? }`（badNames は `{ path, reason }`、
  dupBasenames は `{ base, paths }`）
- `window.vaultlint.test.run(files)` — FSA を通さず結果画面まで描画（ハーネス用）

## 検証手順

> **合否の正本は `./test/run vaultlint` が全 pass（コンソールエラー0件を含む）。**

FSA（`showDirectoryPicker`）はヘッドレスで自動化できないため、実フォルダの走査は
Chrome 実機スモークで確認する:

- 設定（非公開フォルダ・Inbox・アーカイブ先）を保存 → 実 vault を選択 → スキャン完了・
  設定した非公開フォルダが統計の除外に出る・結果が既知の問題（ダブルスペース等）と整合する

## やらないこと

- ~~修復（リネーム・削除・リンク書き換え）~~ → **v2（2026-08-14）で承認式の修復を実装済み**
  （リンク切れのテキスト化・リネームのリンク追随・Inbox デイリーのアーカイブ移動。
  **承認したものだけ実行**する形で vault の掟②を守る）。
  **今も「やらない」のはノートの削除と一括リネームそのもの**
- ハンドルの永続化（低頻度。毎回選ぶ）
- Safari / Firefox 対応（showDirectoryPicker が無い。理由を表示して終わり）
- 孤立ノート（どこからもリンクされていない）の検出 — 「リンクしない運用のノート」が
  多数あり誤検知になる。要望が出たら再検討
- Obsidian 設定（attachmentFolderPath 等）の読取り — `.obsidian/` は除外対象。解決は上記規則のみ
