# devpad 仕様書兼テストケース

## 概要

開発ユーティリティ11種をタブ切替で1枚に集約したツール。`web/devpad.html`、表示名 `Convert`、
カテゴリ: 変換・比較。各タブは独立して壊れる（1機能のエラーが他に波及しない）ことが最重要要件。

> **タブ数の上限についての合意（2026-08-06）**: 11タブで打ち止めとする。
> タブが増えるほど「どこに何があるか」の発見性が落ちるため、
> **これ以上増やすなら検索またはツール分割が必要**。
> JSONPath / cron / JWT / ハッシュ / QR は `docs/tool-backlog.md` に留め、追加しない。

## 要件対応表

| ユーザー要件 | spec 節 |
|---|---|
| 各タブは独立して壊れない | タブ独立性 |
| JSON: 整形/圧縮/バリデーション（エラー位置表示） | タブ仕様 1 |
| JSON文字列⇔生テキスト、URLエンコード⇔デコード | タブ仕様 2, 3 |
| Base64（UTF-8日本語対応。TextEncoder使用） | タブ仕様 4 |
| Unix時刻⇔JST相互変換、現在時刻の各形式表示 | タブ仕様 5 |
| UUID v4生成（件数指定） | タブ仕様 6 |
| カウント: 全角半角別/行数/バイト数（CP932は概算明記） | タブ仕様 7 |
| 入力は各タブで独立保持。タブ切替で消えない | 状態保持 |
| SQL: 整形（キーワード大文字化・改行・インデント）/ 圧縮。DDL 対応 | タブ仕様 8 |
| 正規表現: マッチ・キャプチャ・置換プレビュー。暴走で固まらない | タブ仕様 9 |
| 基数変換: 10/16/8/2進の相互変換＋ビット表示 | タブ仕様 10 |
| XML: 整形 / 圧縮。宣言・コメント・CDATA を壊さない | タブ仕様 11 |

## 画面構成

- `<main>` 直下: `.tool-header`（「← ツール一覧」リンク＋「入力と設定は自動保存されます」注記）
- タブバー（`.tabs`）: **JSON / XML / SQL / エスケープ / URL / Base64 / 正規表現 / 基数 / 時刻 / UUID / カウント**
  - 整形系（JSON/XML/SQL）→ エンコード系（エスケープ/URL/Base64）→ その他（正規表現/基数）→
    生成・集計系（時刻/UUID/カウント）の並び（DEV-Q11）
  - **既存タブ同士の相対順序は1つも変えていない**（挿入のみ。筋肉記憶を壊さない）
  - `.tabs` は `flex-wrap: wrap` のため狭幅では折り返す（ページは横スクロールしない → DEV-47）
- 出力を持つタブ（JSON/エスケープ/URL/Base64/UUID）には出力コピーボタン（共通プロトコル: clipboard API → 選択フォールバック。空出力はコピーせず案内表示）
- 各タブは静的 `<section hidden>`。切替は `hidden` 属性のみ操作し DOM は破棄しない（→切替で入力が消えない）
- 各タブ内に専用のエラーバナー領域（他タブに波及しない）。**タブ内で input が発生したら
  当該タブのバナー（エラー・結果とも）を隠す**（修正済み入力に旧エラーが残らない — UX監査 DP-1）
  - このリスナは **capture フェーズで実行する**（2026-08-06 修正）。
    ライブ変換するタブ（基数）は入力ハンドラ自身がバナーを出すため、バブリングで消すと
    **出した直後に消えて何も表示されない**。「先に古い表示を消す → タブが反応する」の順序にする
- JSONタブの入力ペインタイトル横: 「サンプルを入れる」ボタン（**入力が空のときのみ表示**。
  投入と同時に整形を実行して出力まで見せる）
- **各タブの主要（先頭 primary）ボタンは Cmd/Ctrl+Enter でも実行**（ボタン title に表記。UX監査 CM-3）
- 時刻タブの変換結果（→JST / →Unix時刻 / 現在時刻一覧の値）は**クリックでコピー**
- **時刻タブの epoch→ は JST と ISO8601(UTC) の2形式を併記**（2026-08-13・DEV-52。
  「現在時刻は4形式なのに変換は JST 1形式」の非対称の解消。`epochToUtcIso` は
  `epochToJst` と同じ数値判定・単位規約で `YYYY-MM-DDTHH:mm:ss[.SSS]Z` を返す）
- **カウントタブに［集計をコピー］**（2026-08-13・DEV-53。`ラベル: 値` の6行を
  クリップボードへ — 他タブにはコピー手段があるのにカウントだけ無かった非対称の解消）
  （`title="クリックでコピー"`、成功時は time-result バナーに表示 — UX監査 DP-4）

## タブ独立性（アーキテクチャ）

- タブ登録 `TABS = [{id, label, init, getState, setState}]`。配線ループが各 `init()` を try/catch し、失敗タブは自身のパネル内にエラーバナー＋タブボタンに印、他タブは続行
- **init ループの後続処理（復元・Cmd/Ctrl+Enter 配線・コピー配線・自動保存の登録）も、
  特定タブの init 失敗で止まらない**（DEV-48）
- **復元した値に依存する表示は、各タブが init で `this._refresh` に生やし、
  復元後の一括ループが try/catch 付きで呼んで再計算する**
  （json=サンプルボタンの表示 / 基数=10進からの再計算 / カウント=集計。
  init 失敗タブは `_refresh` が無いので自然に飛ぶ。裸で呼ぶと init 失敗時に
  以降の配線が全部止まる — DEV-48/49）
- 全イベントハンドラは `guard(tabId, fn)` 経由（例外を当該タブのバナーに表示）
- 復元もタブごと try/catch（1タブ分の保存データ破損が他を壊さない）
- **`guard()` は同期ハンドラの try/catch でしかない（重要・2026-08-06）**。
  正規表現タブは Worker を使うため、`worker.onmessage` / `worker.onerror` / タイムアウト /
  Worker 再生成の**すべてを明示的に当該タブのバナーへルーティングする**。
  ここを漏らすと未処理エラー＝コンソールエラーになり、「コンソールエラー0件」の検証基準を静かに破る

## エラー規約（DEV-Q5・2026-08-06）

**新規4タブ（SQL / 正規表現 / 基数 / XML）の純関数は例外を投げず、必ず結果オブジェクトを返す**:

```
成功: { ok: true, value, ...付随情報 }
失敗: { ok: false, error: '理由', line?, col? }
```

理由: ①4タブとも「不正な入力は想定内」で例外にすべき事象ではない ②`line`/`col` を
同じ形で運べる（XML・SQL とも位置を出す）③`guard()` を「本物のバグの最後の網」に戻せる。

**既存3タブ（`b64decode` は `{error}`、`urlDecode`/`unescapeJsonStr` は throw、
`parseJsonWithPos` は `{ok}`）は変更しない** — 動作を変えずに規約だけ揃えるのは、
テスト済みコードを触るリスクに見合わないため。新規は最も新しい `{ok}` 形に寄せて収束させる。

## タブ仕様

1. **JSON**: 整形（2スペース）/ 圧縮 / バリデーション。**3操作とも**パース失敗時は位置注釈付きエラー（json-result バナー）を表示する（UX監査 DP-2 で整形/圧縮も検証と同じ表示に統一）。エラー位置は3段カスケード: ①メッセージ中の `(line N column M)` ②`at position N`（自前で行・列に変換）③位置なし→メッセージのみ表示。位置が取れた場合は「N行目 M文字目」＋該当行＋`^` キャレット表示。**エンジン依存の best-effort（Safari は位置なし）と UI に注記**
2. **エスケープ**: JSON文字列⇔生テキスト。エスケープ = `JSON.stringify(text)`（外側 `"` を含む →要確認 DEV-Q1）。アンエスケープ = `JSON.parse`、引用符なし入力は自動で `"..."` にラップして再試行（→要確認 DEV-Q2）。失敗はエラーバナー
3. **URL**: `encodeURIComponent` / `decodeURIComponent`（決定: encodeURI 切替は設けない。`+` は空白として扱わない）。デコード失敗（不正 `%`）はエラーバナー
4. **Base64**: エンコード = `TextEncoder` → 0x8000 バイトずつ `String.fromCharCode` → `btoa`。デコード = 空白除去・URL-safe（`-_`→`+/`）正規化 → `atob`（`InvalidCharacterError` 捕捉）→ `TextDecoder('utf-8', {fatal:true})`（不正シーケンスはエラーバナー）。テキストのみ対象（バイナリファイルは対象外）。**「URL-safe 出力」トグル（2026-08-13・DEV-51）**: ON で `+/`→`-_`・パディング `=` 無しの出力（入力は従来から両対応 — 入出力の非対称の解消）。トグル状態は保存対象
5. **時刻**: Unix時刻⇔JST（**JST=UTC+9固定**。マシンTZに依存しない `getUTC*` 計算。`Date.parse` は不使用、自前パーサで `YYYY/MM/DD HH:mm:ss`・`YYYY-MM-DD HH:mm:ss`・ISO8601 を受容）。数値入力は `/^-?\d+(\.\d+)?$/`、秒/ミリ秒は `Math.abs(v) >= 1e12` で自動判定＋手動ラジオ（自動/秒/ミリ秒）。日時→epoch は月日時分秒の妥当性を検証し、存在しない日時（`2024/13/99` 等の Date ロールオーバー）は受理せずエラーを返す。「現在時刻」ボタンで epoch秒 / epochミリ秒 / ISO8601(UTC) / JST日時 を一括表示
6. **UUID**: v4。`crypto.randomUUID()`、旧環境は `crypto.getRandomValues` フォールバック。件数指定 1〜1000、小文字、1行1件
7. **カウント**: 文字数=コードポイント数（`[...str]`、改行含む）。全角/半角: 半角 = U+0020〜U+007E と半角カナ U+FF61〜U+FF9F、それ以外は全角（**East Asian Width の近似である旨を UI に明記**。改行・タブは半角側）。行数 = LF 分割（末尾改行は行に数えない）。UTF-8バイト = `TextEncoder`。CP932バイト = 半角1・その他2の**概算（UI に「概算」明記。絵文字も2として計算）**

8. **SQL**（整形 / 圧縮。PostgreSQL 前提・best-effort）

   **トークナイザ**（公式ドキュメントで確認した規則のみ実装。2026-08-06）:
   `{t, v}` の列。`t` = `ws | lineComment | blockComment | str | dq | dollar | num | word | punct`
   - `--` 〜 行末 / `/* */`（**入れ子可能** — PostgreSQL 公式「These block comments nest,
     as specified in the SQL standard but unlike C」）
   - `'…'`（`''` で `'` を表す）/ `E'…'`（`\'` も可）/ `"…"`（`""` で `"` を表す）
   - `$tag$ … $tag$`（**タグ完全一致**。異なるタグで入れ子可能。DDL の関数本体で必須）
   - 複数文字の演算子（`::` `<=` `>=` `<>` `!=` `||` `->` `->>`）は1トークンにする
   - **未終端の文字列・コメント・ドル引用符は `{ok:false, error, line}`**
     （best-effort でも、未終端を黙って整形すると壊れた SQL を出力するため）

   **整形**:
   - **キーワード大文字化は `word` トークンのみ**。文字列・コメント・引用識別子・
     ドル引用符の中は一切触らない。**識別子がキーワードと同名なら大文字化される**旨を UI に明記
   - 主要キーワードの前で改行: `SELECT FROM WHERE GROUP HAVING ORDER LIMIT OFFSET UNION
     EXCEPT INTERSECT INSERT VALUES UPDATE SET DELETE RETURNING WITH` ＋ JOIN 系
     （`JOIN INNER LEFT RIGHT FULL CROSS LATERAL`）＋ DDL 系（`CREATE ALTER DROP TRUNCATE COMMENT`）
   - `ON` / `AND` / `OR` は1段インデントして改行。ただし **`BETWEEN a AND b` の `AND` は改行しない**
   - **要求した改行は、現在行が空なら捨てる**（`DELETE FROM` の `FROM`、`LEFT JOIN` の `JOIN`、
     サブクエリ直後の `SELECT` などで二重改行になるのを一律で防ぐ）
   - **括弧は事前に対応付けして3種に分類**（1パスで分類 → 1パスで出力）:
     - **定義グループ**: 直前の有意トークンを遡って `CREATE TABLE …` が見つかる括弧。
       `(` の後で改行・トップレベルの `,` ごとに改行・`)` の前で改行
       → **DDL が1カラム1行**になる。定義グループ内では**節キーワードの改行を抑止**する
       （`order` のような列名で改行しないため）
     - **サブクエリグループ**: 内部のトップレベルに `SELECT` を含む括弧 → 改行＋インデント
     - **インライングループ**: それ以外（`count(*)` `CHECK (x > 0)` を壊さない）
   - `;` の後は改行＋空行

   **圧縮**: 空白を1つに畳み、**コメントを削除する**（DEV-Q12）。
   `--` コメントを残して1行化すると**以降すべてがコメント化して SQL が壊れる**ため。
   削除件数を情報表示する（無言で情報を落とさない）。キーワードの大文字化はしない（1機能に絞る）

9. **正規表現**（マッチ・キャプチャ・置換プレビュー）

   **実行方式（DEV-Q6）— Worker ＋ 1秒タイムアウト**。
   2026-08-06 に `file://` で実測: Blob URL から Worker を生成でき、
   `/a+a+a+a+a+a+a+a+a+b/` に `'a'.repeat(60)` を与えた暴走を `terminate()` で **302ms で中断**できた。
   「JS の正規表現は途中で止められない」は **main thread の話**で、Worker に追い出せば止まる。
   - 初期化時に Worker を1つ作る。マッチ処理の本体 `runRegexCore(d)` は**関数を1つだけ定義し、
     `Function.prototype.toString()` で Worker ソースへ埋め込む**（同じ実装を2箇所に書かない）
   - 入力の 250ms デバウンスで post → main 側は **1000ms のタイマー**
   - 超過で `terminate()` → **Worker を作り直す** → 「実行が1秒を超えたため中断しました
     （カタストロフィックバックトラッキングの可能性）」を当該タブのバナーに出す
   - **タイムアウトは推定値**。実運用で重い正常ケースを誤って切るようなら見直す
   - マッチは**最大1000件**で打ち切り、打ち切った旨を表示する（無言で省略しない）
   - **長さ0マッチの無限ループ対策**: `m.index === re.lastIndex` なら `lastIndex++`
   - 結果表示は `.banner` ではない専用領域（`#re-result`）に出す。
     `main` の input リスナがパネル内の全 `.banner` を隠すため、banner に出すと入力ごとに点滅する

   **Worker が使えない環境**（`new Worker` が失敗する場合）:
   - **ライブ実行をやめ、明示ボタン実行に切り替える**（暴走時に固まるのが「入力するたび」になるのを避ける）
   - 対象文字列の上限を 10,000 文字に下げる
   - 常設注記「この環境では実行を中断できません」

   **対策できない範囲（正直に記載）**:
   - **フォールバック経路では中断できない**。ページごと固まり、エンジンが終わるまで待つしかない
   - **危険パターンの静的検出は原理的に不完全**（一般には決定不能）。
     量指定子付きグループの中に量指定子がある形（`(a*)*` `(\w+)+`）を**ヒントとして**出すだけで、
     保証ではない。**グループを持たない `a+a+a+b` 形は検出できない**（→ そちらはタイムアウトで守る）
   - Worker でも `terminate()` までの間 CPU は消費する（実測 302ms で解放）

   **機能**: マッチ一覧（index / マッチ文字列 / 番号キャプチャ / 名前付きキャプチャ）/
   対象文字列のハイライト（`createElement('span')` のみ）/ 置換プレビュー / 不正パターンはエラー表示

10. **基数変換**（10進 / 16進 / 8進 / 2進 ＋ ビット表示）

    **数値表現は BigInt（DEV-Q8）**。`Number('0xFFFFFFFFFFFFFFFF')` は
    `18446744073709552000` に化ける（2026-08-06 実測）ため、64bit を扱う道具として不可。

    **BigInt の実測した罠3つ（2026-08-06）**:
    - `BigInt('')` は **`0n`** → **空入力は BigInt に渡す前に弾く**（空欄が 0 に化けるのを防ぐ）
    - `BigInt('-0xff')` は **SyntaxError** → 符号は自分で分離してから絶対値を変換し、後で反転する
    - `BigInt.asUintN(width, v)` / `BigInt.asIntN(width, v)` が使える → 2の補数は標準 API で得る

    **負数の扱い（DEV-Q7）**:
    | 表示 | -5 の場合 |
    |---|---|
    | 10進 / 16進 / 8進 / 2進 | `-5` / `-5` / `-5` / `-101`（**符号付き**） |
    | ビット表示（32bit） | `11111111 11111111 11111111 11111011`（**2の補数**） |

    基数フィールドは「同じ整数の基数変換」という数学的一貫性を保ち、2の補数は
    **幅という概念を持つビット表示の側だけ**で扱う。混ぜると
    「16進が -5 なのか FFFFFFFB なのか」が読めなくなる。

    - 幅トグル 32bit / 64bit、8bit 区切りで空白挿入、同じ値の16進も併記
    - **選択幅で表現できない値は切り詰めず警告**。「収まる」の判定は
      **符号付き範囲または符号なし範囲のどちらかに入ること**
      （`asIntN(w,v)===v || asUintN(w,v)===v`）。
      `0xDEADBEEF` は符号付き32bit の上限を超えるが **32bit のビット列としては正確に表せる**ため、
      符号付きだけで判定すると「32bit では表現できません」と出てしまう（2026-08-06 実測で修正）
    - 入力の `_` と空白は無視。`0x` `0o` `0b` の接頭辞は該当基数で許容
    - **空入力は他フィールドをクリア**（エラーにしない）
    - 不正な桁は該当文字を挙げてエラー表示し、**他フィールドは変更しない**（誤った値を出さない）
    - このタブは**ライブ変換**のため `button.primary` を置かない
      （Cmd/Ctrl+Enter が「クリア」を叩いて入力を消すのを防ぐ）

11. **XML**（整形 / 圧縮。`DOMParser` / `XMLSerializer` を使用。外部ライブラリなし）

    **パースエラー判定（2026-08-06 実測に基づく）**:
    | 入力 | `querySelector('parsererror')` | 実際 |
    |---|---|---|
    | `<root><parsererror>ok</parsererror></root>` | **true（誤検出）** | 正当な要素。`namespaceURI` は `null` |
    | `<a><b></a>` | true | 本物のエラー。`namespaceURI` は **XHTML** |

    Mozilla の parsererror 名前空間は **Chromium では使われない**
    （`getElementsByTagNameNS(moz, 'parsererror')` は本物のエラーでも0件）。
    → 判定は「**要素名 `parsererror` かつ `namespaceURI` が XHTML または Mozilla NS**」。
    エラー文言 `error on line N at column M: メッセージ` から位置を抽出する
    （**エンジン依存の best-effort**。Safari は形式が異なる — JSON タブと同じ扱いで UI に明記）。

    **整形で壊さないための規則（DEV-Q9）**:
    - **XML 宣言は入力が `<?xml` で始まっていたときだけ出力する**。DOM に宣言のノードは無く
      （`firstChild` はコメント/要素）、`xmlVersion`/`xmlEncoding`/`xmlStandalone` から復元する。
      **宣言が無い入力に足すのは無言の改変**。逆に `XMLSerializer` が付けた場合は取り除く
      （実測では付かないが、シリアライザの挙動に依存させない）
    - **DOCTYPE / コメント / CDATA / 処理命令を保持**（CDATA は nodeType 4 として保存されることを実測）
    - **混在内容（テキストと要素が同じ親に混ざる要素）は子を整形しない**。
      空白を入れるとテキストの意味が変わる。この判定が無いと「整形」がデータを壊す
    - 子がテキスト1つだけの要素はインライン（`<a>x</a>`）。**テキストの中身は一切変更しない**
    - **開始タグは浅いクローンを `XMLSerializer` に通して生成**し、属性のエスケープを
      ブラウザに任せる（手書きのエスケープ表を持たない）

    **圧縮**: 要素間の空白のみのテキストノードを除去して `XMLSerializer` で出力。
    混在内容のテキストは触らない。

## 状態保持・保存仕様

- キー `tools:devpad`、payload `{activeTab, tabs: {json: {...}, ...}}` を一括保存
- 新規4タブの保存内容（2026-08-06）:
  `sql:{in,out}` / `regex:{pattern,flags,subject,replacement}` /
  **`base:{dec,width}`** / `xml:{in,out}`
  - **基数タブは10進と幅だけを保存し、16/8/2進は復元時に再計算する（DEV-Q10）**。
    4フィールドすべてを保存すると「10進と16進が食い違う」不整合な組が復元され得るため
- 保存タイミング: input から 500ms デバウンス＋ `pagehide`/`visibilitychange→hidden` で同期フラッシュ
- 1フィールド 100KB（UTF-16 code unit 長）超は保存対象外とし `{omitted:true}` マーカーを保存 → 復元時は空欄＋「大きすぎたため復元されませんでした」注記（古いデータの黙った復活を防ぐ）（→要確認 DEV-Q3）
- `ToolStorage.mountWarning()` を初期化時に呼ぶ
- 保存された `activeTab` が不正値（タブ改名・破損）のときは `json` にフォールバック（空画面防止）。初期化時のタブ表示では保存を行わない（`{omitted:true}` マーカーの即時上書き防止）

## 性能ガード（超過時は処理せず理由を表示）

- カウントタブ（リアルタイム）: 150ms デバウンス、2,000,000 文字超は集計中止＋「入力が上限（200万文字）を超えたため集計を中止しました」
- ボタン駆動タブ（JSON/エスケープ/URL/Base64）: 5,000,000 文字超は処理中止＋「入力が上限（500万文字）を超えたため処理を中止しました」
- **新規4タブは固有の上限を持つ（2026-08-06）**。共通の500万より低いのは処理コストが高いため:

| タブ | 上限 | 理由 |
|---|---|---|
| SQL | 200,000 文字 | 文字単位トークナイズ＋整形で出力が入力より膨らむ |
| 正規表現 | パターン 1,000 / 対象 100,000 文字（Worker 不可時は対象 10,000） | 加えて**実行1秒でタイムアウト** |
| 基数 | 1フィールド 256 文字 | BigInt の巨大桁は変換が遅い |
| XML | 1,000,000 文字 | DOMParser ＋ 再帰整形 |
