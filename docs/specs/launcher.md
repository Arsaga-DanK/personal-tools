# launcher 仕様書兼テストケース

## 概要

**ツールではなく、全ツールに載る共通コンポーネント**（`lib/launcher.js` ＋ `lib/tools.js`）。
`web/*.html` の `.tool-header` に［☰ ツール］を置き、**引き出し式**でツール一覧を出して
**ツールからツールへ直接移動**できるようにする。

採択理由（2026-09-24）: 2026-08-18 の使用実態診断で「16本のうち11本が貼るから始まるのに
ツール間リンクが0本」と分かり、ハブ側（［データから探す］［Obsidian 用のリンク集］）で手を打ったが、
**どれもハブを経由する前提**だった。利用者「**毎回 TOP に戻ってツールを選び直すのめんどくさいから
サイドメニュー作れない？**」がそこを突いた指摘で、ここが根本。

## 一覧の正本（LA-Q1）

**`lib/tools.js` の `TOOLS` / `CATEGORY_ORDER` が唯一の正本**（2026-09-24 に `index.html` から移設）。
ハブも引き出しメニューも**同じ配列・同じ `filter()`** を通る。片方だけ賢い状態を作らない。

- `path` は **index.html からの相対**で書く。`web/` 配下からは `ToolsList.hrefFor()` が `web/` を剥がす
- **絶対パスをコードに書かない**（`location.pathname` だけで判定 — CLAUDE.md）
- 「最近使った」（`tools:hub`）は **`ToolsList.recordUse()` に一本化**。
  ハブからも引き出しからも同じ形で書く（導線を変えた瞬間に履歴が死ぬのを防ぐ）
- `ToolStorage` が無いページ（`mask.html`）でも落ちない（毎回ガードする）

## UI

- `.tool-header` の**先頭**に［☰ ツール］（`#launcher-btn`）。**ハブ（index.html）には出さない**
  （そこが一覧そのものなので、開く先が自分自身になる）
- 既定は閉じている。**2ペイン系の横幅を奪わないため常時表示の列にしない**（LA-Q2）
- 開く: ボタン / **Cmd/Ctrl+K**（トグル）。閉じる: 同キー / Esc / 外側クリック
- 中身: 検索欄 → 「最近使った」→ カテゴリ順のツール → ［ハブを開く］
- **検索中はカテゴリ見出しを出さない**（絞り込んだのに見出しで分断されると読みにくい）
- 現在のツールは `aria-current="page"`
- キー操作: 検索欄で **Enter = 先頭を開く** / ↓ で一覧へ。一覧で ↑↓ 移動、↑ で検索欄へ戻る。
  **Enter は IME ガード必須**（変換確定で遷移させない — taskboard TB-I の教訓）
- Esc は**開いているときだけ**奪う（各ツールの Esc を壊さない）

## 検証手順

> **合否の正本は `./test/run launcher` が全 pass（コンソールエラー0件を含む）。**

## やらないこと

- **常時表示のアイコン列**（LA-Q2）— `Convert Table` など2ペイン系の横幅を常に削るため。
  引き出しなら閉じている間はゼロコスト
- ハブの［データから探す］の複製 — あれは貼ったデータから行き先を決める別の機能。
  引き出しからは［ハブを開く］で渡す
- ツールごとの並べ替え・ピン留め（「最近使った」で足りるかを先に見る）
