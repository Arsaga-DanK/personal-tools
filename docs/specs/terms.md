# terms 仕様書兼テストケース

## 概要

用語統一表を原稿へ一括適用するツール。`web/terms.html`、表示名 `Unify Terms`、カテゴリ: 変換・比較。
顧客の用語集・表記ルール（「サーバー→サーバ」等）を1行1ルールで貼り、原稿に**同時置換**で適用する。

## ルール記法（1行1ルール）

- `変換前<TAB>変換後`（**タブ優先** — Excel の2列コピーがそのまま貼れる）
  または `変換前→変換後`
- 空行・`#` 始まりの行は無視（コメント）
- 警告: 区切りが無い行／変換前が空の行／**変換前が重複**する行（最初の定義を使用）
- 変換前・変換後とも前後の空白は trim。大文字小文字は区別する（用語は正確に）

## 適用規則（この2つが本体）

1. **単一パスの同時置換** — 置換結果に別ルールを重ねない。
   `サーバ→クライアント` と `クライアント→サーバ` の**交換が正しく**行える
   （順次 replaceAll だと二重置換で全部同じ語になる事故が起きる）
2. **長い語優先** — `データベースサーバ→DBサーバ` と `サーバ→サーバー` が両方あるとき、
   `データベースサーバ` の中の「サーバ」は短いルールに食われない

実装: ルールを長い順に並べたリテラル・オルタネーション正規表現で1回 replace。

## 画面構成

- `<main class="app-wide">`・`.tool-header`（「入力とルールは自動保存されます」） — 見出し2行（`header.app-head` の中。説明は h1 の title・操作は2行目 `.app-controls` — 2026-10-05 段5・HUB-28）
- ルール欄（`#rules`・小さめ textarea・placeholder あり）→ 2ペイン（入力 `#input` / 出力 `#output`）
- ［結果をコピー］（primary・`title="Cmd/Ctrl+Enter"`・**コピー時に確定**）
- サンプル投入（入力が空のときだけ表示。ルールと入力を同時投入）
- リアルタイム変換（200ms デバウンス）
- サマリ: `適用 M 箇所（ルール K/R 本）`。未適用ルールがあれば
  ` ／ 未適用: from1・from2 …`（先頭5件＋「ほか」）

## 保存

`tools:terms`、payload `{ rules, input }`。300ms デバウンス＋`pagehide` /
`visibilitychange(hidden)` フラッシュ。1フィールド 100KB 超は `{omitted:true}`（devpad 規約）。

## 性能ガード（超過時は処理せず理由を表示）

- ルール 1,000 本超／入力 1,000,000 文字超

## 純関数（フックと UI が同一コードパス）

`window.terms = { parseRules, applyTerms }`

- `parseRules(rulesText)` → `{ rules: [{from, to, line}], warnings: [] }`
- `applyTerms(text, rules)` → `{ text, counts: [{from, to, n}] }`（counts はルール記載順）

## テストケース

| ID | 入力 | 期待 |
|---|---|---|
| TM-01 | ルール `サーバー\tサーバ`・入力 `サーバーのサーバー` | `サーバのサーバ`・counts n=2 |
| TM-02 | `サーバ→クライアント` と `クライアント→サーバ`・入力 `サーバとクライアント` | **`クライアントとサーバ`**（交換。二重置換しない） |
| TM-03 | `データベースサーバ→DBサーバ` と `サーバ→サーバー`・入力 `データベースサーバとサーバ` | `DBサーバとサーバー`（**長い語優先**） |
| TM-04 | `→` 区切り・`# コメント`・空行の混在 | ルールとして読める。コメント・空行は無視・警告なし |
| TM-05 | 区切りなし行／変換前が空／変換前の重複 | それぞれ行番号つき警告。重複は最初の定義を使用 |
| TM-06 | 2ルール中1つが0件 | counts に n=0 で残る（UI では未適用として表示） |
| TM-07 | 1,001 ルール／1,000,001 文字 | `{ok:false}` 相当（処理せず理由）。UI は warn バナー・出力空 |
| TM-08 | **ルール欄**で Tab ／ Esc の直後に Tab ／ 原稿欄で Tab | タブ文字が入る（区切りをキーボードで打てる — `lib/edit.js`）／ 素通し ／ **原稿欄は素通し**（散文なので Tab は「次へ」のまま） |

UI 手順ケース:
- **TM-U1**: ルールと入力を入れて 200ms → 出力とサマリ。**入力直後（確定前）にコピー →
  最新の結果**（コピー時に確定）
- **TM-U2**: リロードでルール・入力とも復元。デバウンス中の pagehide でもフラッシュ保存
- **TM-U3**: サンプル投入 → ルール・入力が入り出力が出る。ボタンは入力が空のときだけ表示
- **TM-U4**: 幅390px で横スクロールなし
- **TM-U5**: 未適用ルールがサマリに `未適用:` として出る

## 検証手順

> **合否の正本は `./test/run terms` が全 pass（コンソールエラー0件を含む）。**

## やらないこと

- 正規表現ルール（リテラルのみ — 用語集の写しがそのまま動くことを優先。
  正規表現は Convert の正規表現タブの領分）
- 大文字小文字の同一視・ゆらぎ推定（norm・NFKC の領分）
- 変更箇所ハイライト（v1 は件数サマリまで。欲しくなったら norm の方式を移植）

## 決定事項（2026-08-14）

- **TM-Q1**: 適用順 → **同時置換・長い語優先**（連鎖置換の事故防止が最優先）
- **TM-Q2**: ルール区切り → タブ優先＋`→` 併用（Excel コピーとの親和性）
- **TM-Q3**: norm への統合ではなく新ツール → norm は「機械的な文字種の正規化」、
  terms は「顧客固有の語彙の適用」で正本が違う（ルールは案件ごと）
