## 保存仕様（外部同時編集への防御）

### ツールバーの整理（2026-09-24。利用者「この部分を整理して」）

操作が**常時11個**並び、1280px でも2行に折り返していた。自動保存を入れた今、
［今すぐ保存］が常に見えているのも矛盾していた。

- **常時出すのは6つ**: ［＋タスク追加］／セクション・タグ・終了を含む・並び順／［Excel用コピー］
- **`<details class="more-menu">`（⋯）に畳む**: 週報の期間＋［週報コピー］／［Draw Gantt で開く］／
  ［全文コピー］／［完了をアーカイブ］／［再読込］
- **［今すぐ保存］は `isDirty()` のときだけ表示**（＝未保存インジケータを兼ねる）。
  自動保存が効いていれば一瞬で消え、**スキップされたとき（一括完了・fallback）は出たまま**になり逃げ道が見える。
  デモ中は無効表示のまま出す
- ラベルは「保存」→「**今すぐ保存**」（自動保存との違いを名前で示す）

### モード切替のショートカット（2026-09-24）

**Cmd/Ctrl+Shift+E** で `Check Issue` と往復する。実装は `lib/ui.js` の `ToolUI.mountModeSwitch()`
（`nav.modes` の `aria-current="page"` でない最初のリンクへ飛ぶので、モードが増えても直る）。
Chrome が奪うキーは避けた（Cmd+Shift+M=プロフィール / Cmd+Shift+I,J=DevTools / Cmd+J=ダウンロード）。

**自動保存（2026-09-24 に追加。利用者「毎回タスクとか作成後に『保存』ボタンを押さないといけないのが地味に億劫」）**

変更のたびに **1.2 秒のデバウンス**で保存する。**保存の中身は明示保存とまったく同じ経路**
（下の1〜4）を通るので、外部同時編集への防御は落ちない。

- **自動保存しない条件**（どれかに当たればスキップし、［今すぐ保存］に委ねる）:
  - `fallback` モード（Safari / Firefox。保存＝ダウンロードなので自動化すると毎回ファイルが降る）
  - デモ中 / 未読込
  - **一括完了の確認が必要なとき**（`BULK_COMPLETE_THRESHOLD` 以上）。
    自動保存が確認ダイアログを出すのは筋が悪いので、**info バナーで［今すぐ保存］を促す**
- **成功時はバナーを出さない**（1.2秒ごとに success バナーが出るとうるさい）。
  ツールバーの `#save-state` に「自動保存しました HH:MM」を出すだけ。
  **競合・失敗は従来どおりバナー**（見逃してはいけないため）
- 明示保存（ボタン / Cmd+S）は**残す** — 自動保存をスキップした場合の逃げ道になる
- `visibilitychange(hidden)` でも保存を試みる（デバウンス中に離脱したとき）

保存の中身（明示・自動で共通）:

1. 保存クリック → ハンドルから現ディスク内容を再読込
2. `NFC(ディスク) !== NFC(読込時スナップショット)` → **書き込まず**警告バナー
   「Obsidian 側で変更されています。再読込してください」＋［再読込］ボタン
   （再読込は未保存編集の破棄を confirm してから）
3. 一致 → `createWritable()` で全文書き込み → スナップショット更新 → 成功バナー
   「保存しました（変更N行・追加M行）」（編集追跡から算出）
4. 書き込み失敗（権限剥奪等）→ エラーバナー。編集状態は保持
- **比較は必ず NFC 正規化後**（macOS の NFD 由来の偽検知防止）。正規化は比較用の
  一時コピーのみ。**保存内容には適用しない**（バイト保全を壊すため）
- window focus / visibilitychange 時にも再読込して比較: 未編集なら自動再読込＋情報表示、
  編集中なら警告バナーのみ（既知の制約: 比較→書込間の TOCTOU は許容。個人ツールのため）


## ハンドル永続化仕様（設計判断: ToolStorage 拡張ではなく専用実装）

`FileSystemFileHandle` は structured clone が必要で、JSON/localStorage ベースの
ToolStorage には原理的に保存できない。よって **taskboard.html 内の専用 IndexedDB
実装**とする（db: `tools-taskboard` / store: `handles` / key: `tasksmd`。file:// では
全ページがオリジンを共有するため db 名接頭辞で衝突防止 — storage.js と同じ考え方）。

再訪フロー: 起動時に IDB からハンドル取得 → `queryPermission({mode:'readwrite'})` が
`granted` なら即読込。`prompt` なら［前回のファイルを開く: tasks.md］ボタンを表示し、
**クリック1回**で `requestPermission` → 読込（Chrome 側の許可ダイアログは Chrome の仕様）。

実装は `lib/fsa.js`（2026-09-25 に Check Issue とバイト一致していた 30 行を共有化）。
**db 名 `tools-taskboard`・store 名 `handles`・version 1 は変えない** — 変えると利用者のブラウザに
残っているハンドルが見えなくなり、tasks.md を選び直すことになる。

| ID | 操作 | 期待 |
|---|---|---|
| TB-FS1 | `ToolFsa.handles('tools-taskboard').set('probe', 1)` | `indexedDB.databases()` に `tools-taskboard` があり、`get('probe')` が 1 を返す（共有化しても db 名が変わらない） |


## フォールバック仕様（FSA 非対応 = Safari/Firefox）

`'showOpenFilePicker' in window` で判定。非対応時:
- 読込: `<input type="file" accept=".md,.txt">`
- 保存: ［.md をダウンロード］＋［全文コピー］（Obsidian へ手動反映）
- 常設情報バナー「このブラウザでは直接保存できません。ダウンロード/コピーで手動反映して
  ください」。外部変更検知・ハンドル永続化は無効


## モード切替（`Check Issue` と対）

`.tool-header` の下に `<nav class="modes">` を置き、［✅ タスク］［🎯 イシュー］で
`web/issue.html` と1クリックで行き来する（利用者「タスク画面からイシューの投稿ができるように。
モードの切り替えみたいに」）。自分側は `aria-current="page"`。
**スタイルは `lib/ui.css` の `.modes`**、**モーダルの殻も `lib/ui.css` へ移した**
（`Check Issue` が2番目の利用者になったため — `docs/specs/issue.md` の IS-Q9）。

| ID | 操作 | 期待 |
|---|---|---|
| TB-MS1 | モードセグメント | ［🎯 イシュー］が `web/issue.html` へのリンクで、［✅ タスク］が `aria-current="page"` |
| TB-MS2 | モーダルを開く（既存の追加モーダル） | `lib/ui.css` へ移した後も中央に出て、背景が敷かれる（算出スタイルで確認） |
| TB-UI1 | 起動直後のツールバー | 常時見えるボタンは ＋タスク追加 / Excel用コピー / ⋯ の3つ（保存は未保存のときだけ）。週報・アーカイブ・再読込・全文コピーは `#more-menu` の中 |
