# dates 仕様書兼テストケース

## 概要

日付・営業日・工数の計算ツール。`web/dates.html`、表示名 `Calc Dates`、カテゴリ: PM（初使用）。
「N営業日後はいつか」「期限に間に合わせるにはいつ着手か」「この期間は何営業日か」
「和暦・年度で何と書くか」「3人日は何時間か」を1画面で即答する。

## 祝日データ（静的同梱）

- **正本は内閣府「国民の祝日」CSV**（https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv 。
  SJIS・毎年2月頃に翌年分が追記される）。**実行時には参照しない**（オフライン完結・URL 変更の事故歴あり）
- 同梱範囲: **2020-01-01〜2027-12-31 の 143 件**（2026-08-14 に CSV から抽出）。
  振替休日・国民の休日は CSV と同じ **「休日」** 表記（例: 2026-09-22 は敬老の日と秋分の日に
  挟まれた国民の休日 → 「休日」）
- 五輪特措法の移動（2020: 海の日7/23・スポーツの日7/24・山の日8/10、
  2021: 海の日7/22・スポーツの日7/23・山の日8/8）を含む — 規則計算では出せないため同梱が正
- **運用**: 毎年2月頃に CSV を確認して1年分追記し、`RANGE.to` とこの節の範囲を更新する
- 範囲外の日付を含む営業日計算は、**土日のみ考慮で計算した上で warn**
  （「祝日データは2020〜2027年」）。黙って間違った答えを出さない

## 営業日の定義と関数の意味

- 営業日 = 土日でも祝日（同梱テーブル）でもない日
- `addBusinessDays(date, n)`: n>0 は date の「n営業日後」（date 自身は数えない）。
  n<0 は「n営業日前」。n=0 は date をそのまま返す
- 期限逆算は同じ関数の負数（「期限のN営業日前」= `addBusinessDays(期限, -N)`）
- `businessDaysBetween(a, b)`: a〜b の**両端を含む**営業日数。a > b は 0
- 日付は文字列 `YYYY-MM-DD` で受け渡し、内部は `Date.UTC`/`getUTCDay` で計算する
  （`new Date('YYYY-MM-DD')` は UTC 深夜扱いのため、ローカル TZ 依存の
  `getDay()` と混ぜると環境によって曜日がずれる）

## 和暦・年度

- 明治〜大正は扱わない（業務で使わないため。1926-12-25 より前は warn）
- 境界: 昭和 1926-12-25〜1989-01-07 / 平成 1989-01-08〜2019-04-30 / 令和 2019-05-01〜
- 元年表記: 各元号の1年目は「元年」（令和1年ではなく令和元年）
- 年度 = 4/1〜3/31（`月<4 なら 年-1`）。和暦年度は**年度開始日（4/1）時点の元号**で表記し、
  **2019年度だけは通年「令和元年度」**（官公庁の読み替え運用。4/1 時点はまだ平成31年だが
  「平成31年度」とは書かない）

## 工数換算

- 係数は可変: 1人日 = H 時間（既定 8）、1人月 = D 人日（既定 20）
- `convertEffort(value, unit, {hoursPerDay, daysPerMonth})` → `{hours, days, months}`
  （unit は `'時間' | '人日' | '人月'`）
- 表示は小数第2位まで（末尾ゼロは省く）

## UI（1画面・3セクション・リアルタイム計算）

1. **営業日**: 基準日＋N（後/前の切替）→ 結果日付（曜日つき）。期間（開始〜終了）→ 営業日数。
   結果行に［コピー］（`ToolUI.copy`）。基準日が祝日ならその名称を添える
2. **和暦・年度**: 日付 → 「令和8年」「2026年度（令和8年度）」＋曜日＋祝日名（該当時）
3. **工数**: 数値＋単位 → 3表記すべて。係数（1人日=H時間・1人月=D人日）は変更可

- 保存は**係数と N の値など UI 状態のみ**（`tools:dates`、`ToolStorage`）。日付は保存しない
  （開くたびに今日から計算するのが自然）
- 日付入力の初期値は今日

## 純関数・フック（UI と同一コードパス）

`window.dates = { addBusinessDays, businessDaysBetween, isHoliday(dateStr) → bool,
holidayName(dateStr) → string|null, inRange(dateStr) → bool, toWareki(dateStr) → {era,year,text},
toFiscal(dateStr) → {fy, text, wareki}, convertEffort, HOLIDAYS, RANGE }`

## やらないこと

- 祝日の規則計算（春分・秋分は天文計算、ハッピーマンデーは法改正で動く — 同梱テーブルが正）
- 会社独自の休業日（夏季休業等）の登録 — 要望が出たら（テーブルに1行足せる設計にはしておく）
- 和暦→西暦の逆変換・明治/大正 — 業務での出現頻度が低い
- 日付の保存（開くたび今日から。係数のみ保存）
