# taskboard 仕様書兼テストケース

## 前提と実検証結果（FSA API・Chrome 前提）

**File System Access API は `file://` で利用可能**（2026-08-04、Chrome ヘッドレス＋Playwright CDP で実検証済み）:

- `file://` ページで `isSecureContext === true`。`showOpenFilePicker` / `showSaveFilePicker` /
  `FileSystemFileHandle.prototype.createWritable` / `queryPermission` すべて存在
- ジェスチャ無し呼び出し → ジェスチャ要求のエラー（＝origin/scheme チェックは通過。
  file:// でブロックされる場合は opaque origin 系エラーになる）。
  **エラー名は Chrome のバージョンで変わる** — 2026-08-04 は
  `SecurityError: Must be handling a user gesture`、2026-08-17 の再測（Chrome 151）は
  `NotAllowedError: User activation required`（`showOpenFilePicker` は `AbortError`）
- ジェスチャ有り呼び出し → CDP の `Page.setInterceptFileChooserDialog` に傍受された
  `AbortError`（＝Chrome がダイアログ表示処理まで到達した証拠）
- `file://` オリジンで IndexedDB の put/get 動作確認済み → ハンドル永続化の土台あり

したがって **主経路は FSA（Chrome + file://）、フォールバックは非 Chrome（Safari/Firefox）用**。
`FileSystemFileHandle` の IndexedDB 保存→ブラウザ再起動後の復元は自動検証不能のため
「Chrome 実機スモーク項目」で確認する。

## 概要

Obsidian vault のタスク正本 `tasks.md`（Obsidian Tasks 記法）を表形式で
閲覧・編集するツール。`web/taskboard.html`、カテゴリ: タスク。
Obsidian と本ツールの両方から編集されるため、**外部同時編集への防御**と
**ラウンドトリップのバイト保全**を最優先要件とする。

実ファイルの構造要素（2026-08-04 時点で確認。すべて保全対象）: 先頭 HTML コメント /
`# tasks` 見出し / `## ` セクション3つ（PEW・UL・その他。その他は空でファイル末尾）/
タブ1個/階層のインデント / 本文中の `[[YYYY-MM-DD]]`（複数・`_TODO` 変種あり）/
`✅ YYYY-MM-DD` / `#102` のような数字のみ文字列（Obsidian ではタグ無効）/
LF・BOM なし・末尾改行あり。
※同日時点の実ファイルは全タスク完了済み（未完了0件）。テストは未完了を含む縮約
fixture で行う。

## データ仕様（解析）

読込テキストを `\n` で分割し行配列として保持（末尾改行は split/join で自然に保全）。
**編集していない行は原文文字列をそのまま出力する**（バイト保全の基本方式）。

- タスク行: `/^(\t*)- \[(.)\] (.*)$/`（**括弧内は任意の1文字**。Phase T2 で `( |x|X)` から拡張）。
  インデント=タブ数（深さ任意。深さ≥1 は直近の浅い行を親とする）。
  **状態の判定は `statusOf()` の1箇所だけで行い、`done` はそこから派生させる**
  → 「ステータス仕様」節
- セクション行: `^## ` 。タスクの所属セクション=直上の `## ` 見出し。`# tasks` は対象外
- 上記以外（HTML コメント・空行等）: パススルー行。表示せず一切触らない。
  **`- [?]` は Phase T2 からタスク行**（状態=不明）になった。**パススルーの例ではなくなった**
- タスク行の rest からメタトークンを抽出:
  - **開始日: `🛫 YYYY-MM-DD`（Phase T）** / 期限: `📅 YYYY-MM-DD` /
    完了日: `✅ YYYY-MM-DD`（絵文字+半角スペース1+日付）
  - **⏳（scheduled）は解析・表示・編集の対象にしない**。本文の一部として原位置のまま残す。
    ただし**トークン挿入位置の目印としてだけ参照する**（Obsidian 側で付いた ⏳ の前に
    🛫 を入れないと Tasks 標準順が壊れるため。→ 編集仕様 10）
  - 優先度: `🔺`(最高) `⏫`(高) `🔼`(中) `🔽`(低) `⏬`(最低)。UI から設定できるのは
    ⏫🔼🔽/なし の4値。🔺⏬ は表示のみ（変更操作をすれば4値に置換）
  - 本文 = rest からメタトークン（と各直前の空白1個）を除いた残り。`[[...]]`・`#文字列`・
    `🔁...` は本文の一部として**原位置のまま**
- タグ: 本文中の `#` + 英数・ひらがな等の連続。**数字のみは除外**（`#102` はタグでない。
  Obsidian と同判定）
- 元ノート: 本文中の全 `[[...]]`（`_TODO` 変種含む）


## 表示仕様（ソート・絞り込み・色分け）

- ソート: ファイル順（既定）/ **開始日昇順**（開始日なしは最後、同値は期限→ファイル順。
  TB-Q13。ガントの慣習に合わせるが**既定は変えない**）/ 期限昇順（期限なしは最後、
  同値はファイル順）/ 優先度順（⏫→🔼→なし→🔽。🔺は⏫扱い・⏬は🔽扱い）
- 絞り込み: セクション / タグ / 「終了を含む」（完了・中止。既定 OFF → TB-Q2）。組み合わせ可
- **完了グループは常に最下部**（Phase N・TB-Q20）。**ソート指定より優先する第1キー**。
  - 判定は **`subtreeAllDone(t)`**（部分木が全部完了）。
    **未完了の子孫を持つ完了親は上に残る**（進行中の作業が下に埋もれない。
    アーカイブ対象の判定と同じ関数を使う）
  - **リストビューのときだけ適用する**。`state.visibleRows` はタイムラインの行順にも
    使われるため、timeline では従来の並びを保つ（TB-C3）。Excel 用コピーは画面と一致する
  - ボードは列内で同じ規則を適用するが、**列＝ステータスのときは適用しない**
    （完了は「完了」列に集まるため。Phase T2・TB-G7）
  - **着手中（`[/]`）・保留（`[h]`）・不明は下がらない**（終わっていないため）。
    **中止（`[-]`）は下がる**（Phase T3。終了扱い。TB-S31）
- 色分け（未完了のみ）: 期限 < 今日 → 期限セルを `--error` 系で強調 / 期限 = 今日 →
  `--warn-bg` で強調 / 期限なし → 通常。完了行は muted
- UI 状態（**ビュー**・ソート・絞り込み・トグル・**追加フォームの前回値**）のみ
  `tools:taskboard` に自動保存（ToolStorage）。
  **タスクデータ・メモの内容・ファイル内容・ハンドルは localStorage に置かない**（正本は tasks.md）
- **追加フォームの既定値は前回入力した値**（Phase N・TB-Q22）。
  `add: { section, start, due, priority }`（すべて文字列。`''` = クリアも記憶する）
  - 固定デフォルトにしない（「今日」固定だと毎回消す手間が出る）
  - **セクションも同じ方式に統一**（従来の「先頭セクション固定」をやめる）。
    記憶した値がファイルに無ければ先頭セクションへフォールバック（TB-D3）
  - 記憶するのは**追加が成功したとき**（入力途中の値は覚えない）。
    **フォームの値は op を適用する前に読む** — `applyUiOp` → `render` で
    セクション select が作り直されるため、後から読むと値が変わる（2026-08-06 実測）
  - 既定値を入れるのは**読込時とフォームを開いたときだけ**（`applyAddDefaults()`）。
    `render` ごとに入れると**利用者がクリアした欄を再描画で復活させてしまう**（同日実測）
- **`restoreUi` は既知値のみ受け入れる**（TB-Q17）。`sort`/`view` に未知の文字列が
  入っていると `<select>` の値が空になり並び順が壊れるため、列挙に含まれる値だけ採用する
  （Phase T 以前から存在した弱点。`view` の追加で面が広がるので同時に直す）


## Excel 用コピー仕様

表示中（絞り込み・ソート反映後）の行を TSV でクリップボードへ。ヘッダー行を含む（→ TB-Q4）。
**ビューによって列構成が変わる**:

| ビュー | ヘッダー |
|---|---|
| リスト | `状態\t内容\t開始日\t期限\t優先度\tタグ\tセクション` |
| タイムライン | `内容\t開始日\t期限\t日数\t状態\tセクション` |

- 共通: 内容=本文（`[[...]]` 除去。子は深さ×全角スペース1個で字下げ）、
  タブ・改行は半角スペースに置換
- リスト: 状態=**済/着手/未**（Phase T2 で3値。不明は「未」）、優先度=高/中/低/空、
  タグ=`#タグ` スペース区切り。
  **開始日列を追加した**（TB-Q14。表に列があるのにコピーに無いのは無言の不一致になるため。
  この改訂で期限が3列目→4列目に移動する）
- タイムライン: 対象は `timelineModel` の `items`（🛫 を持つ行のみ・図と同じ並び）。
  **状態=済/遅延/着手/未**（Phase T2。図の色分けと一致させ、**遅延を優先する**
  — 遅れている事実の方が着手済みより重い）、**日数は 📅 が無ければ空欄**
- **ボタンのラベルをビューで変える**（リスト=［Excel用コピー］/ タイムライン=［計画をコピー］）。
  列構成が変わるのに見た目が同じだと気づけないため。
  - **ラベルは短く保つ**（長くするとツールバーが折り返して保存ボタンの位置が動く。
    2026-08-05 に［Excel用コピー（計画）］で実測して確認）。
    **列の内訳は `title` で示す**（ラベルより情報量が多く、幅を食わない）
  - `copyFeedback` が復元に使う `dataset.label` も同時に更新する。
    コピー結果表示（`.copied`）中はラベルを上書きしない（表示を奪わない）
- `navigator.clipboard` → 失敗時 textarea 選択方式にフォールバック。0行なら「出力がありません」。
  **タイムラインの性能ガード発動中はコピーも拒否する**（理由をボタンに表示）

  アーカイブはできません（Obsidian 標準は LF）」。該当行はチェック・ポップオーバー・編集を無効化し、
  エンジン側でも `taskAt`/`opAddChild` が CR 行を拒否する（`setRest` が `\r` を落として保存する
  バイト破壊の防止）。CR ファイルでは［＋タスク追加］［完了をアーカイブ］も無効
- 2,000,000 文字超: 読込中止・警告（一部のみ処理はしない）
- 未保存編集があるときのタブ閉じ/再読込: `beforeunload` で確認（デモ中は除く）

## Obsidian 手動スモーク項目（Phase T2・`[/]` の見え方と設定手順）

**確認は利用者が行う（未確認）。** `[/]` は Tasks の**既定のカスタムステータスに入っているが、
「正しく表示するにはテーマか CSS スニペットが必要」**と公式に明記されている。
つまり**設定を触らなくても意味（IN_PROGRESS = 未完了）は正しく、見た目だけがテーマ依存**。

- `- [/] タスク` が Obsidian の編集画面・閲覧画面でどう見えるか
  （テーマ次第で「半分塗りのチェックボックス」または「素のチェックボックス」）
- Tasks プラグインのクエリで `not done` に `[/]` が含まれること
- チェックボックスを Obsidian 側でクリックしたときに `/` → `x` へ進むこと（Next Status Symbol）

### 意図どおりの表示にしたい場合の設定手順

1. Obsidian の**設定 → コミュニティプラグイン → Tasks**（プラグイン設定）を開く
2. **「Task Statuses」** セクションを見る
   - **Core Statuses**: `[ ]` と `[x]`（削除・記号変更は不可）
   - **Custom Statuses**: **既定で `[/]` = In Progress（型 `IN_PROGRESS`・次の記号 `x`）と
     `[-]` = Cancelled（型 `CANCELLED`・次の記号 space）が入っている**。
     もし一覧に無ければ ➕ **Add New Task Status** で
     `Status Symbol=/` `Status Name=In Progress` `Next Status Symbol=x` `Status Type=IN_PROGRESS` を足す
3. **見た目**（半分塗りのチェックボックス等）はテーマ／CSS の担当。
   設定内の **Minimal Theme** / **ITS Theme & SlRvb Checkboxes** ボタンを押すと、
   そのテーマが対応する記号一覧を Custom Statuses に流し込める
   （**そのテーマを実際に使っている場合に押す**。押しただけでは見た目は変わらない）
4. ファイル内に本ツールの知らない記号が入ってしまったときは
   **Add All Unknown Status Types** で vault 内の未登録記号を一括登録できる
5. `[-]` を使う場合の注意: **Tasks では型 `CANCELLED` = "done" に一致する**が、
   **本ツールは「不明」＝未完了として扱う**（アーカイブされない）。
   → 「ステータス仕様 / 既知の差異」
