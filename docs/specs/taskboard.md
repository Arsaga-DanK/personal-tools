# taskboard 仕様書兼テストケース

## 前提と実検証結果（FSA API・Chrome 前提）

**File System Access API は `file://` で利用可能**（2026-08-04、Chrome ヘッドレス＋Playwright CDP で実検証済み）:

- `file://` ページで `isSecureContext === true`。`showOpenFilePicker` / `showSaveFilePicker` /
  `FileSystemFileHandle.prototype.createWritable` / `queryPermission` すべて存在
- ジェスチャ無し呼び出し → `SecurityError: Must be handling a user gesture`（＝origin/scheme
  チェックは通過。file:// でブロックされる場合は opaque origin 系エラーになる）
- ジェスチャ有り呼び出し → CDP の `Page.setInterceptFileChooserDialog` に傍受された
  `AbortError`（＝Chrome がダイアログ表示処理まで到達した証拠）
- `file://` オリジンで IndexedDB の put/get 動作確認済み → ハンドル永続化の土台あり

したがって **主経路は FSA（Chrome + file://）、フォールバックは非 Chrome（Safari/Firefox）用**。
`FileSystemFileHandle` の IndexedDB 保存→ブラウザ再起動後の復元は自動検証不能のため
「Chrome 実機スモーク項目」で確認する。

## 概要

Vault のタスク正本 `~/Personal/vault/03_Tasks/tasks.md`（Obsidian Tasks 記法）を表形式で
閲覧・編集するツール。`web/taskboard.html`、カテゴリ: タスク。
Obsidian と本ツールの両方から編集されるため、**外部同時編集への防御**と
**ラウンドトリップのバイト保全**を最優先要件とする。

実ファイルの構造要素（2026-08-04 時点で確認。すべて保全対象）: 先頭 HTML コメント /
`# tasks` 見出し / `## ` セクション3つ（PEW・UL・その他。その他は空でファイル末尾）/
タブ1個/階層のインデント / 本文中の `[[YYYY-MM-DD]]`（複数・`_TODO` 変種あり）/
`✅ YYYY-MM-DD` / `#102` のような数字のみ文字列（Obsidian ではタグ無効）/
LF・BOM なし・末尾改行あり。
※同日時点の実ファイルは全タスク完了済み（未完了0件）。テストは未完了を含む縮約
fixture で行う。

## データ仕様（解析）

読込テキストを `\n` で分割し行配列として保持（末尾改行は split/join で自然に保全）。
**編集していない行は原文文字列をそのまま出力する**（バイト保全の基本方式）。

- タスク行: `/^(\t*)- \[( |x|X)\] (.*)$/`。インデント=タブ数（深さ任意。深さ≥1 は直近の
  浅い行を親とする）。`[X]` は完了として認識（編集しない限り原文保持）
- セクション行: `^## ` 。タスクの所属セクション=直上の `## ` 見出し。`# tasks` は対象外
- 上記以外（HTML コメント・空行・`- [?]` 等の変則行）: パススルー行。表示せず一切触らない
- タスク行の rest からメタトークンを抽出:
  - 期限: `📅 YYYY-MM-DD` / 完了日: `✅ YYYY-MM-DD`（絵文字+半角スペース1+日付）
  - 優先度: `🔺`(最高) `⏫`(高) `🔼`(中) `🔽`(低) `⏬`(最低)。UI から設定できるのは
    ⏫🔼🔽/なし の4値。🔺⏬ は表示のみ（変更操作をすれば4値に置換）
  - 本文 = rest からメタトークン（と各直前の空白1個）を除いた残り。`[[...]]`・`#文字列`・
    `🔁...` は本文の一部として**原位置のまま**
- タグ: 本文中の `#` + 英数・ひらがな等の連続。**数字のみは除外**（`#102` はタグでない。
  Obsidian と同判定）
- 元ノート: 本文中の全 `[[...]]`（`_TODO` 変種含む）

## 編集仕様（行の書き換え規則）

編集は**トークン単位のインプレース・スプライス**（該当トークンと直前の空白1個のみを
追加/置換/削除。行の他部分のバイトは不変）:

1. **完了**: `- [ ]`→`- [x]`、行末に ` ✅ <今日>` を追加（Tasks プラグインと同挙動）
2. **完了解除**: `- [x]`/`- [X]`→`- [ ]`、`✅ 日付` トークンを除去
3. **📅 設定**: 既存があれば日付部分のみ置換（位置不変）。無ければ ✅ の直前
   （無ければ行末）に挿入。**削除**: トークンを除去
4. **優先度**: 既存絵文字を置換（位置不変）。無ければ 📅 の直前（無ければ ✅ の直前、
   無ければ行末）に挿入。なし=除去
5. **本文編集**: この操作のみ行を再構成 `インデント + - [状態] + 新本文 + 優先度 + 📅 + ✅`
   （メタトークンは Tasks 標準の行末順に再配置される。編集した行に限る）
6. **新規タスク**: 指定セクションの最終タスク行（子孫含む）の直後に挿入。タスクの無い
   セクションは見出しの直後に空行1つを挟んで挿入（既存の体裁に合わせる）。深さ0
7. **子タスク追加**: 親の最終子孫行の直後に、親のインデント+タブ1個で `- [ ] 内容` を挿入
8. **UI からの新規入力テキストは NFC に正規化して書き込む**。既存行の未編集部分には
   いかなる正規化も適用しない

タスク行の削除は提供しない（Obsidian 側で行う）。
**ただし「未保存の追加行の取り消し」は削除ではない**（tasks.md にまだ存在しない行を取り下げるだけ）。
→ 「追加の取り消し仕様」節。

## キーボードと IME 仕様（Phase I・2026-08-05）

### 症状と原因（2026-08-05 実測）

**日本語の変換確定 Enter が、そのまま「追加」「編集確定」を発火していた。**
CDP で未確定状態を作って測ると、IME が確定のために送る Enter は
`keydown { key:'Enter', isComposing:true, keyCode:13 }` としてページに届く:

```
未確定表示: 会議        ← かいぎ→Space で変換した直後（まだ確定していない）
追加された行: 会議      ← 確定の Enter が「追加」を発火
入力欄の残り: ""        ← 続きを打つつもりだった文字列が消える
```

`e.key === 'Enter'` だけを見て `isComposing` を見ていなかったのが原因。
**英数字だけ打つ場合は再現しない**ため「どの操作の後か特定できない」症状になっていた
（操作の順序ではなく、変換を挟んだかどうかで決まる）。

### ガード（3箇所・TB-Q6）

Enter を扱う次の3箇所すべてで、**ハンドラ先頭で変換中を判定して何もせず返す**:

```js
if (e.isComposing || e.keyCode === 229) return;
```

| 箇所 | 現在の実装 | ガードしないと起きること |
|---|---|---|
| 追加フォームの内容欄 | `web/taskboard.html` の `#add-content` keydown | 未変換・変換途中の文字列でタスクが追加される |
| 子タスク popover の入力欄 | `openChildPopover` 内の input keydown | 同様に子タスクが追加され、**popover も閉じて入力が失われる** |
| 内容セルのインライン編集 | `startBodyEdit` 内の input keydown | **既存タスクの内容が未変換文字列で上書きされる**（被害が最も大きい） |

- `keyCode === 229` の併用は **`isComposing` を立てない IME への保険**（deprecated だが現存する）
- **ハンドラ全体を返す**（Enter 分岐だけでなく Escape 分岐も通さない）。変換中の Escape は
  IME の変換取り消しであり、編集の中断やポップオーバーの閉鎖に使われてはいけない
- インライン編集の `blur` → `commit` は従来どおり（`done` フラグで二重確定は防がれている）。
  変換確定の Enter でコミットされなくなるため、**確定後にもう一度 Enter**（または blur）で確定する。
  これは他アプリと同じ作法

### 追加後のフォーカス復帰（TB-Q7）

追加が成功したら `#add-content` に値のクリアとあわせて**フォーカスを戻す**。
現状はマウスで［追加］を押すとボタンにフォーカスが残り、続けて打った文字がどこにも入らず、
次の Enter が「内容が空」の警告になる（誤追加ではないが「意図しない挙動」の体感を増やしていた）。

### 意図的に残す Enter 経路

次は仕様どおりの動作として維持する（2026-08-05 に発火しないことを実測済み）:

- ［＋タスク追加］ボタンにフォーカス＋Enter → フォームの開閉トグルのみ
- セクション / 期限 / 優先度の各欄で Enter → 何も起きない（ハンドラは内容欄に直付けで委譲なし）
- フォームを閉じた状態で Enter → 何も起きない（ページ内に `<form>` が無く暗黙送信の経路も無い）
- ［追加］ボタンにフォーカス＋Enter → ボタンの標準動作としての再実行。
  内容が空なので追加は起きず警告バナーのみ（TB-Q7 のフォーカス復帰でこの状況自体が減る）

## 追加の取り消し仕様（Phase I・TB-Q8）

誤って追加した行を、**保存前に限り**取り下げる。既存タスク行の削除は引き続き提供しない。

### 対象

- `orig === null` の行（＝読込時に存在せず、このセッションで追加された行）**のみ**
- **保存すると `doSave` が全行の `orig` を `raw` で更新する**ため、
  保存後は対象が消え、取り消しボタンも自然に消える（＝保存済みの行は通常のタスク行）
- 既存行（`orig !== null`）を対象にした取り消しは**例外**にする（削除機能への裏口を作らない）
- **子孫を持つ追加行は取り消せない**。ボタンを disabled にし title で
  「先に子タスクを取り消してください」と示す（部分木の削除は「削除機能」になるため）

### 挿入された空行の同時取り消し

`opAddTask` は**タスクの無いセクションに追加するとき空行も一緒に挿入する**
（`lines.splice(hIdx + 1, 0, {raw:'', orig:null}, {raw, orig:null})`）。
取り消しでは**その空行も一緒に取り下げて追加前の状態に戻す**。判定規則:

> 取り消す行の**直前**が「`orig === null` かつ空行」で、**その前**が `## ` 見出しなら、その空行も除去する。

この規則は挿入順に依存せず収束する（同一セクションに2件追加してからどちらを先に取り消しても
最終的に元のバイト列に戻る。TB-U3 で照合）:

空セクション（F1 の `## その他`）に A・B の2件を追加した状態を起点に、両方の順序を追う。
`*` 付きが `orig === null`（このセッションで挿入された行）:

```
起点        19: ## その他        ← 見出し（orig は実値）
            20: ''          *   ← A の追加で挿入された空行
            21: - [ ] A     *
            22: - [ ] B     *   ← B の追加は既にタスクがあるので空行を挟まない
            23: ''              ← F1 の元の20行目（末尾改行になる）

▼ 逆順（B → A）                    ▼ 順不同（A → B）
undo B: 直前が 'A' で空行でない     undo A: 直前が空行* でその前が見出し
        → B のみ除去                       → 空行* と A をまとめて除去
  19: ## その他                      19: ## その他
  20: ''          *                  20: - [ ] B     *
  21: - [ ] A     *                  21: ''
  22: ''
undo A: 直前が空行* でその前が見出し  undo B: 直前が見出しで空行でない
        → 空行* と A をまとめて除去          → B のみ除去
  19: ## その他                      19: ## その他
  20: ''                             20: ''
      ＝ F1 と同一                        ＝ F1 と同一
```

### エンジン側の扱い

**操作（op）として実装する**: `{ type:'undoAdd', line: N }` を `runOp` の分岐に追加する。
既存の編集エンジンと同じ経路に乗るため、純関数 `applyOps(text, ops, today)` で
**バイト同一性まで照合できる**（新しい検証経路を作らない）。

### UI

- 表の操作列（現在は［＋子］）に、**追加行にだけ**取り消しボタン［↩︎］を出す。
  title は「この追加を取り消す（未保存）」
- **追加行に視覚マーク**を付ける（行に `.row-added`。左端にアクセント色の縦線）。
  誤って増えた行に気づけるようにするための表示で、保存すると消える
- 取り消し後は情報バナー「追加を取り消しました」を出す（行が消えることを削除と誤解させない
  — UX監査 TB-1 と同じ配慮）

## 保存仕様（外部同時編集への防御）

保存は明示ボタンのみ。自動保存しない。

1. 保存クリック → ハンドルから現ディスク内容を再読込
2. `NFC(ディスク) !== NFC(読込時スナップショット)` → **書き込まず**警告バナー
   「Obsidian 側で変更されています。再読込してください」＋［再読込］ボタン
   （再読込は未保存編集の破棄を confirm してから）
3. 一致 → `createWritable()` で全文書き込み → スナップショット更新 → 成功バナー
   「保存しました（変更N行・追加M行）」（編集追跡から算出）
4. 書き込み失敗（権限剥奪等）→ エラーバナー。編集状態は保持
- **比較は必ず NFC 正規化後**（macOS の NFD 由来の偽検知防止）。正規化は比較用の
  一時コピーのみ。**保存内容には適用しない**（バイト保全を壊すため）
- window focus / visibilitychange 時にも再読込して比較: 未編集なら自動再読込＋情報表示、
  編集中なら警告バナーのみ（既知の制約: 比較→書込間の TOCTOU は許容。個人ツールのため）

## ハンドル永続化仕様（設計判断: ToolStorage 拡張ではなく専用実装）

`FileSystemFileHandle` は structured clone が必要で、JSON/localStorage ベースの
ToolStorage には原理的に保存できない。よって **taskboard.html 内の専用 IndexedDB
実装**とする（db: `tools-taskboard` / store: `handles` / key: `tasksmd`。file:// では
全ページがオリジンを共有するため db 名接頭辞で衝突防止 — storage.js と同じ考え方）。

再訪フロー: 起動時に IDB からハンドル取得 → `queryPermission({mode:'readwrite'})` が
`granted` なら即読込。`prompt` なら［前回のファイルを開く: tasks.md］ボタンを表示し、
**クリック1回**で `requestPermission` → 読込（Chrome 側の許可ダイアログは Chrome の仕様）。

## フォールバック仕様（FSA 非対応 = Safari/Firefox）

`'showOpenFilePicker' in window` で判定。非対応時:
- 読込: `<input type="file" accept=".md,.txt">`
- 保存: ［.md をダウンロード］＋［全文コピー］（Obsidian へ手動反映）
- 常設情報バナー「このブラウザでは直接保存できません。ダウンロード/コピーで手動反映して
  ください」。外部変更検知・ハンドル永続化は無効

## 表示仕様（ソート・絞り込み・色分け）

- ソート: ファイル順（既定）/ 期限昇順（期限なしは最後、同値はファイル順）/
  優先度順（⏫→🔼→なし→🔽。🔺は⏫扱い・⏬は🔽扱い）
- 絞り込み: セクション / タグ / 「完了を含む」（既定 OFF → TB-Q2）。組み合わせ可
- 色分け（未完了のみ）: 期限 < 今日 → 期限セルを `--error` 系で強調 / 期限 = 今日 →
  `--warn-bg` で強調 / 期限なし → 通常。完了行は muted

## Excel 用コピー仕様

表示中（絞り込み・ソート反映後）の行を TSV でクリップボードへ:
ヘッダー行（→ TB-Q4）＋ `状態\t内容\t期限\t優先度\tタグ\tセクション`。
状態=済/未、内容=本文（`[[...]]` 除去。子は深さ×全角スペース1個で字下げ）、
優先度=高/中/低/空、タグ=`#タグ` スペース区切り。
`navigator.clipboard` → 失敗時 textarea 選択方式にフォールバック。0行なら「出力がありません」。

## エラー・警告仕様

- どの入力でも例外で落ちない。変則行はパススルー（解釈も破壊もしない）
- CR（`\r`）検出（UX監査 TB-2 で改訂）: TASK_RE/HEAD_RE は末尾 `\r` を許容し**表示はする**。
  警告バナー「CR 改行（Windows形式）のファイルです。表示のみ可能で、該当行の編集・タスク追加・
  アーカイブはできません（Obsidian 標準は LF）」。該当行はチェック・ポップオーバー・編集を無効化し、
  エンジン側でも `taskAt`/`opAddChild` が CR 行を拒否する（`setRest` が `\r` を落として保存する
  バイト破壊の防止）。CR ファイルでは［＋タスク追加］［完了をアーカイブ］も無効
- 2,000,000 文字超: 読込中止・警告（一部のみ処理はしない）
- 未保存編集があるときのタブ閉じ/再読込: `beforeunload` で確認（デモ中は除く）

## 完了アーカイブ仕様（UX監査 TB-4）

表示中の完了タスクを `~/Personal/vault/03_Tasks/archive.md` へ追記し、tasks.md から除去する。

- **対象は親子グループ単位**: 深さ0の部分木が**すべて完了**しており、かつ現在の表示
  （絞り込み・「完了を含む」反映後）に出ているもの。部分木ごと移動する。未完了の子孫を持つ
  完了親は文脈ごと残す（ソート・絞り込みと同じグループ単位の設計）
- **前提: 未保存の変更がないこと**（あれば警告して中止 — アーカイブ＝純粋な移動に保つ）
- **tasks.md 側**は保存と同じ外部変更検知（NFC 比較。不一致なら中止＋警告＋再読込ボタン）
- **archive.md のハンドル**は IndexedDB（key `archivemd`）に永続化。無ければ
  `showSaveFilePicker({suggestedName:'archive.md'})` で取得・作成（キャンセルは静黙中止）
- **追記手順**: 書き込み直前に archive.md を読み直し（外部編集を消さない。read→write 間の
  TOCTOU は保存仕様と同様に許容）、空なら先頭に `# archive\n` を付与、末尾改行が無ければ補い、
  対象行を**原文のまま**（インデント・メタトークン不変）1行ずつ追記
- **順序: archive 追記 → tasks.md から除去して保存**（archive 書込失敗なら行は消えない。
  tasks 保存失敗時は行配列を読込時状態へ戻し、「再実行すると archive.md 側が重複する」旨を警告）
- 成功バナー「アーカイブしました（N行を archive.md へ移動）」
- フォールバック（FSA 非対応）・デモ中・CR ファイルでは無効

  - 不採用①「トリガーを `Cmd/Ctrl+Enter` に変更」: **保存が既に Cmd+S** のため、追加まで修飾キーに
    すると修飾キー操作が2種類並ぶ。`Enter=追加` / `Cmd+S=保存` の操作モデルの方が素直
    （リポジトリ全体の Cmd+Enter 慣習より、このツール内の一貫性を優先する — ユーザー判断）
  - 不採用②「Enter での追加をやめてボタンのみ」: 最頻ツールの入力速度が落ち、
    キーボード導線を足した ux-backlog CM-3 の方針に逆行する
- **TB-Q7**: 追加後のフォーカス → **決定: `#add-content` に戻す**（連続追加を自然にする。
  ボタンにフォーカスが残る現状の副作用を消す）
- **TB-Q8**: 誤追加の取り消し → **決定: `orig === null` の追加行限定＋挿入された空行も同時に取り消す**。
  `{type:'undoAdd', line}` として既存の op エンジンに載せ、`applyOps` でバイト同一性を照合する
  - 子孫を持つ追加行は取り消し不可（部分木の削除は「削除機能」になるため）
  - 不採用「1段 undo（`Cmd+Z`）」: 期限・優先度・完了も救えるが範囲が広く、
    今回の症状に対して過剰。「どこまで戻るか」が見えにくく多段化の圧力もかかる
  - 不採用「現状の周知のみ（保存前なら再読込で破棄できる）」: 実装ゼロだが**全変更が消える**ため、
    朝の計画を一通り入れた後には使えない
- **TB-Q9（→要確認）**: **Escape の IME ガード**。調査中に見つけた同種の欠陥で、
  承認された3箇所には含まれていない。
  `document` の Escape ハンドラ（`closePopover`）は変換中でも発火するため、
  **子タスク popover で変換を取り消そうと Escape を押すと popover が閉じて入力が失われる**。
  対処は同じ1行（`if (e.isComposing || e.keyCode === 229) return;`）。
  - **推奨: Phase I に含める**（原因・対処・テスト方法が TB-I4 と同型で、追加コストがほぼ無い）
  - 含めない場合は ux-backlog に記録する
