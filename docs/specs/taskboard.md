# taskboard 仕様書兼テストケース

## 前提と実検証結果（FSA API・Chrome 前提）

**File System Access API は `file://` で利用可能**（2026-08-04、Chrome ヘッドレス＋Playwright CDP で実検証済み）:

- `file://` ページで `isSecureContext === true`。`showOpenFilePicker` / `showSaveFilePicker` /
  `FileSystemFileHandle.prototype.createWritable` / `queryPermission` すべて存在
- ジェスチャ無し呼び出し → `SecurityError: Must be handling a user gesture`（＝origin/scheme
  チェックは通過。file:// でブロックされる場合は opaque origin 系エラーになる）
- ジェスチャ有り呼び出し → CDP の `Page.setInterceptFileChooserDialog` に傍受された
  `AbortError`（＝Chrome がダイアログ表示処理まで到達した証拠）
- `file://` オリジンで IndexedDB の put/get 動作確認済み → ハンドル永続化の土台あり

したがって **主経路は FSA（Chrome + file://）、フォールバックは非 Chrome（Safari/Firefox）用**。
`FileSystemFileHandle` の IndexedDB 保存→ブラウザ再起動後の復元は自動検証不能のため
「Chrome 実機スモーク項目」で確認する。

## 概要

Obsidian vault のタスク正本 `tasks.md`（Obsidian Tasks 記法）を表形式で
閲覧・編集するツール。`web/taskboard.html`、カテゴリ: タスク。
Obsidian と本ツールの両方から編集されるため、**外部同時編集への防御**と
**ラウンドトリップのバイト保全**を最優先要件とする。

実ファイルの構造要素（2026-08-04 時点で確認。すべて保全対象）: 先頭 HTML コメント /
`# tasks` 見出し / `## ` セクション3つ（PEW・UL・その他。その他は空でファイル末尾）/
タブ1個/階層のインデント / 本文中の `[[YYYY-MM-DD]]`（複数・`_TODO` 変種あり）/
`✅ YYYY-MM-DD` / `#102` のような数字のみ文字列（Obsidian ではタグ無効）/
LF・BOM なし・末尾改行あり。
※同日時点の実ファイルは全タスク完了済み（未完了0件）。テストは未完了を含む縮約
fixture で行う。

## データ仕様（解析）

読込テキストを `\n` で分割し行配列として保持（末尾改行は split/join で自然に保全）。
**編集していない行は原文文字列をそのまま出力する**（バイト保全の基本方式）。

- タスク行: `/^(\t*)- \[(.)\] (.*)$/`（**括弧内は任意の1文字**。Phase T2 で `( |x|X)` から拡張）。
  インデント=タブ数（深さ任意。深さ≥1 は直近の浅い行を親とする）。
  **状態の判定は `statusOf()` の1箇所だけで行い、`done` はそこから派生させる**
  → 「ステータス仕様」節
- セクション行: `^## ` 。タスクの所属セクション=直上の `## ` 見出し。`# tasks` は対象外
- 上記以外（HTML コメント・空行等）: パススルー行。表示せず一切触らない。
  **`- [?]` は Phase T2 からタスク行**（状態=不明）になった。**パススルーの例ではなくなった**
- タスク行の rest からメタトークンを抽出:
  - **開始日: `🛫 YYYY-MM-DD`（Phase T）** / 期限: `📅 YYYY-MM-DD` /
    完了日: `✅ YYYY-MM-DD`（絵文字+半角スペース1+日付）
  - **⏳（scheduled）は解析・表示・編集の対象にしない**。本文の一部として原位置のまま残す。
    ただし**トークン挿入位置の目印としてだけ参照する**（Obsidian 側で付いた ⏳ の前に
    🛫 を入れないと Tasks 標準順が壊れるため。→ 編集仕様 10）
  - 優先度: `🔺`(最高) `⏫`(高) `🔼`(中) `🔽`(低) `⏬`(最低)。UI から設定できるのは
    ⏫🔼🔽/なし の4値。🔺⏬ は表示のみ（変更操作をすれば4値に置換）
  - 本文 = rest からメタトークン（と各直前の空白1個）を除いた残り。`[[...]]`・`#文字列`・
    `🔁...` は本文の一部として**原位置のまま**
- タグ: 本文中の `#` + 英数・ひらがな等の連続。**数字のみは除外**（`#102` はタグでない。
  Obsidian と同判定）
- 元ノート: 本文中の全 `[[...]]`（`_TODO` 変種含む）

## 編集仕様（行の書き換え規則）

編集は**トークン単位のインプレース・スプライス**（該当トークンと直前の空白1個のみを
追加/置換/削除。行の他部分のバイトは不変）:

1. **ステータス変更**（Phase T2・`{type:'setStatus', line, status}`）: 括弧内の**1文字だけ**を
   インプレース置換（`todo`→`' '` / `doing`→`/` / `done`→`x`）。**完了にしたときだけ**
   行末に ` ✅ <今日>` を追加し、**完了から離れるとき**に `✅ 日付` を除去する
   （Tasks プラグインと同挙動）。**現在と同じ状態なら何もしない**（`[X]` は `[X]` のまま残る）
2. **完了 / 完了解除**は `setStatus` の**別名**（`complete` = `status:'done'` /
   `uncomplete` = `status:'todo'`）。同じ判定を2箇所に持たない。
   **着手中（`[/]`）からも完了にできる**（Phase T2 の必須修正。以前は「スペース以外なら
   何もしない」早期 return があり、着手中の行はチェックしても完了にならなかった）
3. **📅 設定**: 既存があれば日付部分のみ置換（位置不変）。無ければ ✅ の直前
   （無ければ行末）に挿入。**削除**: トークンを除去
4. **優先度**: 既存絵文字を置換（位置不変）。無ければ **🛫 → ⏳ → 📅 → ✅ → 行末** の
   最初に見つかったものの直前に挿入。なし=除去
   （Phase T で anchor を拡張。Tasks 標準順では Priority が 🛫 より前。
   🛫/⏳ を持たない行では anchor が変わらないので従来挙動は不変 — TB-09）
5. **本文編集**: この操作のみ行を再構成
   `インデント + - [状態] + 新本文 + 優先度 + 🛫 + 📅 + ✅`
   （メタトークンは Tasks 標準の行末順に再配置される。編集した行に限る）
6. **新規タスク**: 指定セクションの最終タスク行（子孫含む）の直後に挿入。タスクの無い
   セクションは見出しの直後に空行1つを挟んで挿入（既存の体裁に合わせる）。深さ0
7. **子タスク追加**: 親の最終子孫行の直後に、親のインデント+タブ1個で `- [ ] 内容` を挿入
9. **セクション移動**（SM-1・2026-08-05）: 既存タスクを別セクションへ移す
   `{type:'moveSection', line, section}`。
   - **移動先セクションの末尾へ移す**（`opAddTask` と**同じ挿入規則を共用** = `insertIntoSection`。
     タスクがあれば最終タスク行（子孫含む）の直後、無ければ見出し直後に空行1つを挟む）。
     同じ「セクションへ入れる」操作で規則を分けない
   - **元の位置には戻らない**（順序は保存されない）。「移動→元のセクションへ戻す」で
     ファイルがバイト同一になるのは**元々そのセクションの最後だったタスク**の場合だけ。
     一般には移動先の末尾に着地するため順序が変わる。**これは仕様**
     （利用者の期待は「移動先の末尾に来る」であり、元位置の記憶は undo の領分）
   - **部分木ごと移動する**。自分より深いタスク行が続く限りを1ブロックとして扱い、
     **子タスクも順序を保って一緒に移る**
   - **行オブジェクトをそのまま移す**ので、移動した行のバイトも、触っていない行のバイトも
     変わらない（`raw`/`orig` を書き換えない）。守るべきはこれで、往復のバイト同一は検証手段
   - **子タスク（深さ≥1）は移動できない**（例外）。親を移動すれば一緒に移るため。
     UI でもセクション列がクリック可能になるのは深さ0の行だけ
   - 移動元と移動先が同じなら**何もしない**（UI では現在のセクションのボタンを disabled にする）
   - **行の移動は行内容を変えないため `diffCounts` に出ない。**`isDirty()` は
     行単位の差分が0のとき**全文をスナップショットと比較**して移動を拾う
     （比較のみ。保存内容には正規化も再構成もしない）。
     **保存ボタンの有効・無効も `isDirty()` で判定する**（件数で判定すると移動だけのとき
     保存できなくなる。バッジの数字は従来どおり行単位の差分件数）
   - 保存成功バナーは変更・追加が0行のとき「**（行の移動）**」と表示する
     （**行数が減っているときは「（N行を削除）」** — メモ削除も行内容を変えないので
     0行・0行になり、「行の移動」と出すと誤解を招く。Phase N で追加）。
     **空セクションへ移動した場合は挿入した空行が「追加1行」として数えられる**ので
     「（変更0行・追加1行）」になる（空行も実際にファイルへ増えるため、これが正しい表示）
   - **空セクションへの挿入ごとに空行が1つ増える**（末尾改行を保つため元の空行を最後に残す
     規則の帰結。`opAddTask` と共通）。空セクションへ入れて出す往復を繰り返すと空行が
     累積するが、**タスク行のバイトと相対順序は完全に保存される**（TB-S8 で照合）
8. **UI からの新規入力テキストは NFC に正規化して書き込む**。既存行の未編集部分には
   いかなる正規化も適用しない
11. **タグの付与・削除**（Phase N・`{type:'setTags', line, tags}`）:
    - 追加は**本文の末尾**（メタトークンのうち**位置が最も前のもの**の直前。無ければ行末）に ` #タグ`
      - 「最初にマッチした正規表現」で決めてはいけない。F1 の13行目（`📅 … ⏫` の非標準順）で
        ⏫ の直前＝📅 の後ろに入ってしまう（2026-08-06 に実測して修正）
    - 削除は該当 `#タグ` と**直前の空白1個のみ**除去（インプレース）
    - **数字のみ（`#102`）はタグではない**ので触らない。判定は `tagsOf()` を
      表示（`parseDoc`）と編集（`opSetTags`）で**共用**する（規則を2箇所に持たない）
    - 追加 → 削除でバイト同一に戻る（TB-T4）
10. **🛫 設定**（Phase T・`{type:'setStart', line, date}`）: 既存があれば日付部分のみ置換
    （位置不変）。無ければ **⏳ → 📅 → ✅ → 行末** の最初に見つかったものの直前に挿入。
    **削除**（`date: null`）: トークンと直前の空白1個のみ除去

### Tasks 標準順を保証する範囲（Phase T・重要）

トークンの標準順は Obsidian Tasks プラグインのソース `src/Layout/TaskLayoutOptions.ts` の
`TaskLayoutComponent` enum で確定（2026-08-05 に一次情報で確認。コメントに
"The order here determines the order that task fields are rendered and written to markdown"）:

```
Description → Id → DependsOn → Priority → 🔁 → 🏁 → ➕ → 🛫 → ⏳ → 📅 → ❌ → ✅
```

本ツールが扱う部分は **本文 → 優先度 → 🛫 → 📅 → ✅**。ただし:

> **既存行のトークン順が非標準でも矯正しない**（バイト保全が優先）。
> F1 の13行目は実ファイル由来で `📅 2026-08-05 ⏫` という非標準順を持つが、
> 🛫 を足しても `🛫 … 📅 … ⏫` となり **⏫ の位置は動かさない**。
> **標準順を保証するのは「本文編集で再構成した行」と「新規追加行」だけ**。
> 既存行に対しては「標準順の位置に挿入する」だけで、既にあるトークンは移動しない。

挿入位置の判定を「優先順のリストで最初に見つかったものの前」にしているのはこのため。
周囲がどんな順序でも、挿入するトークンだけは正しい位置に入る。

タスク行の削除は提供しない（Obsidian 側で行う）。
**ただし「未保存の追加行の取り消し」は削除ではない**（tasks.md にまだ存在しない行を取り下げるだけ）。
→ 「追加の取り消し仕様」節。

## ステータス仕様（Phase T2・2026-08-06）

### Phase T3 の追加（2026-08-06）: 保留（`[h]`）と中止（`[-]`）

**動機**: Obsidian 側でキャンセルした行が本ツールで「未完了」として残り続けるのは実害
（未完了件数に混ざり、アーカイブでも掃けない）。

**一次情報の訂正2件**（公式 Status Types で確認）:

1. **ON_HOLD の慣用記号は `[h]`**（`[?]` は Status Types 表に無い）。`[?]` は「不明」として扱う
2. **`[-]`（CANCELLED）と `[~]`（NON_TASK）は Tasks の "done" 側**に一致する
   （"done" = DONE / CANCELLED / NON_TASK）

> **判定の軸を2つに分ける。**
> `done` = ✅ が付く完了だけ（**チェックボックスの ON/OFF はこれ**）
> `finished` = 終わっている（`done` か `cancelled`）。**表示・件数・並び・アーカイブはこちら**

| 経路 | 使う判定 | 理由 |
|---|---|---|
| チェックボックスの `checked` | `done` | 中止にチェックが入ると完了と見分けられない |
| 行・カードの muted 表示 | `finished` | 終わったものは薄く見せる |
| 終了グループを最下部へ（`subtreeFinished`） | `finished` | 中止が上に残ると邪魔 |
| 「終了を含む」トグル | `finished` | 中止も終わったもの |
| ヘッダーの未完了件数 | `finished` | 中止は残務ではない |
| **アーカイブ対象** | `finished` | **決定: 中止も archive.md へ移す**（下記） |
| 期限の色分け | `finished` | **保留は色が付く**（保留は残務。期限は生きている） |
| タイムラインの `state` | `cancelled` を追加 | 完了と同じ灰色に見せない（塗らず破線） |
| Excel 用コピーの状態列 | `status` | 済 / 中止 / 保留 / 着手 / 未（計画は遅延を優先） |
| 一括完了の確認件数 | **`finished` への遷移** | 中止もアーカイブ対象なので同じ重さ |

**中止をアーカイブ対象に含める判断**（要確認だった点・採用理由）:
`archive.md` は「もう手を動かさない行の置き場」であり中止もそれに該当する。
記号 `[-]` は原文のまま移るので archive.md 上で完了と区別できる。
tasks.md を掃く経路はアーカイブしかないため、含めないと中止行が永久に残る。
**代わりに確認ダイアログへ内訳を出す**（`3件（うち中止 1件）を archive.md へ移動します。…`）。
完了だけのときは従来どおりの文言（中止が混ざったときだけ内訳が増える）。

- **`[-]` に ❌（キャンセル日）は付けない** — 本ツールは ❌ を解析しないので、
  書けるが消せないトークンを作らない（Tasks 側で付いた ❌ は本文として保全される）
- **`[~]`（NON_TASK）は入れない**（vault に現れていない）。必要になれば
  `STATUS_CHAR` / `STATUS_LABEL` / `statusOf` / `ST_COLUMNS` / `FINISHED` に1行ずつ
- トグルのラベルは **「終了を含む」**（`完了・中止を含む` にすると**ツールバーが折り返して
  保存ボタンの位置が動く**。2026-08-06 に実測して短縮。内訳は `title` で示す）

**ボードのステータス列（5列問題の決定）**:

- **未着手 / 着手中 / 完了 は0件でも常設**、**保留・中止は該当が1件以上あるときだけ列に出す**
- 列が無い状態への変更は**状態バッジのポップオーバー（5択）**から行える
  （ドラッグは主要3列の移動に集中させる）
- 5列のときは**列幅を 300px → 220px に詰める**（横スクロールに逃がすと完了列が画面外に出る。
  2026-08-06 にスクリーンショットで実測して追加）
- キーボード移動（`Cmd/Ctrl+←→`）は**描画した列の集合**（`state.boardCols`）を見る
  — 別に計算すると端の判定がずれる

### Phase 0: 一次情報の確認（Obsidian Tasks 公式ドキュメント）

**独自記法は発明せず、Obsidian Tasks の標準記法に従う。** 2026-08-06 に公式ドキュメント
（`publish.obsidian.md/tasks` の Statuses / Custom Statuses / Status Settings）で確認した:

Unknown = 型 `TODO` として "not done" に一致する」** — どちらに転んでも

### 本ツールが扱う状態と、記号の対応

### 既知の差異（Obsidian Tasks との食い違い）

- **`[~]`（NON_TASK）は Tasks では "done" 側だが、本ツールは「不明」＝未完了として扱う**。
  安全側（アーカイブされない・チェックも触らない）。必要になれば1行ずつ足す（下記）
- **`[X]`（大文字）**は Tasks のコアが小文字 `x` であり大文字の扱いは公式に明記が無い。
  本ツールは**従来どおり完了として読み、原文を保持する**（`x` に矯正しない）

### 拡張の手順（NON_TASK など新しい状態を足すとき）

**5箇所に1行ずつ**足すだけで増える構造にしてある（TB-Q44 の条件）:

```js
const STATUS_CHAR  = { …, nontask: '~' };                                 // ← 1行
const STATUS_LABEL = { …, nontask: 'タスクでない' };                      // ← 1行
function statusOf(ch) { … if (ch === '~') return ST_NONTASK; … }          // ← 1行
const ST_COLUMNS   = [ …, { key: ST_NONTASK, label: '〜' } ];              // ← 1行（ボードの列）
const FINISHED     = { done: true, cancelled: true, nontask: true };      // ← 終了側なら1行
```

`done` / `finished` はどちらも `statusOf` からの派生なので、
**状態を足しても完了判定のコードを触らずに済む**。

### 設計の核: 状態を決める場所を1箇所にする

```js
function statusOf(ch)          // 記号 → 状態（ここだけが状態を決める）
parseDoc:  status: statusOf(m[2])                    // 状態は1回だけ決める
           done: status === ST_DONE                 // ✅ が付く完了だけ（派生）
           finished: isFinished(status)             // 終わっている（派生）
function statusOfLine(raw)     // 行文字列 → 状態（行配列を直接見る経路用）
```

> **`TASK_RE` を `(.)` に広げただけで `done` の定義（`m[2] !== ' '`）を直さないと、
> 着手中のタスクが「完了」と判定され、アーカイブで tasks.md から消える。**
> 実データが静かに壊れる最短経路がこれ。だから `done` を独立に判定させない。

## キーボードと IME 仕様（Phase I・2026-08-05）

### 症状と原因（2026-08-05 実測）

**日本語の変換確定 Enter が、そのまま「追加」「編集確定」を発火していた。**
CDP で未確定状態を作って測ると、IME が確定のために送る Enter は
`keydown { key:'Enter', isComposing:true, keyCode:13 }` としてページに届く:

```
未確定表示: 会議        ← かいぎ→Space で変換した直後（まだ確定していない）
追加された行: 会議      ← 確定の Enter が「追加」を発火
入力欄の残り: ""        ← 続きを打つつもりだった文字列が消える
```

`e.key === 'Enter'` だけを見て `isComposing` を見ていなかったのが原因。
**英数字だけ打つ場合は再現しない**ため「どの操作の後か特定できない」症状になっていた
（操作の順序ではなく、変換を挟んだかどうかで決まる）。

### ガード（4箇所・TB-Q6 / TB-Q9）

キー入力を扱う次の4箇所すべてで、**ハンドラ先頭で変換中を判定して何もせず返す**:

```js
if (e.isComposing || e.keyCode === 229) return;
```

| 箇所 | 現在の実装 | ガードしないと起きること |
|---|---|---|
| 追加フォームの内容欄 | `web/taskboard.html` の `#add-content` keydown | 未変換・変換途中の文字列でタスクが追加される |
| 子タスク popover の入力欄 | `openChildPopover` 内の input keydown | 同様に子タスクが追加され、**popover も閉じて入力が失われる** |
| 内容セルのインライン編集 | `startBodyEdit` 内の input keydown | **既存タスクの内容が未変換文字列で上書きされる**（被害が最も大きい） |
| **Escape の popover 閉鎖**（TB-Q9） | `document` の keydown → `closePopover` | 子タスク popover で**変換候補を戻すための Escape** を押すと popover が閉じ、入力が失われる |

- `keyCode === 229` の併用は **`isComposing` を立てない IME への保険**（deprecated だが現存する）
- **ハンドラ全体を返す**（Enter 分岐だけでなく Escape 分岐も通さない）。変換中の Escape は
  IME の変換取り消しであり、編集の中断やポップオーバーの閉鎖に使われてはいけない
- インライン編集の `blur` → `commit` は従来どおり（`done` フラグで二重確定は防がれている）。
  変換確定の Enter でコミットされなくなるため、**確定後にもう一度 Enter**（または blur）で確定する。
  これは他アプリと同じ作法

### 追加後のフォーカス復帰（TB-Q7）

追加が成功したら `#add-content` に値のクリアとあわせて**フォーカスを戻す**。
現状はマウスで［追加］を押すとボタンにフォーカスが残り、続けて打った文字がどこにも入らず、
次の Enter が「内容が空」の警告になる（誤追加ではないが「意図しない挙動」の体感を増やしていた）。

### 意図的に残す Enter 経路

次は仕様どおりの動作として維持する（2026-08-05 に発火しないことを実測済み）:

- ［＋タスク追加］ボタンにフォーカス＋Enter → フォームの開閉トグルのみ
- セクション / 期限 / 優先度の各欄で Enter → 何も起きない（ハンドラは内容欄に直付けで委譲なし）
- フォームを閉じた状態で Enter → 何も起きない（ページ内に `<form>` が無く暗黙送信の経路も無い）
- ［追加］ボタンにフォーカス＋Enter → ボタンの標準動作としての再実行。
  内容が空なので追加は起きず警告バナーのみ（TB-Q7 のフォーカス復帰でこの状況自体が減る）

## 追加の取り消し仕様（Phase I・TB-Q8）

誤って追加した行を、**保存前に限り**取り下げる。既存タスク行の削除は引き続き提供しない。

### 対象

- `orig === null` の行（＝読込時に存在せず、このセッションで追加された行）**のみ**
- **保存すると `doSave` が全行の `orig` を `raw` で更新する**ため、
  保存後は対象が消え、取り消しボタンも自然に消える（＝保存済みの行は通常のタスク行）
- 既存行（`orig !== null`）を対象にした取り消しは**例外**にする（削除機能への裏口を作らない）
- **子孫を持つ追加行は取り消せない**。ボタンを disabled にし title で
  「先に子タスクを取り消してください」と示す（部分木の削除は「削除機能」になるため）

### 挿入された空行の同時取り消し

`opAddTask` は**タスクの無いセクションに追加するとき空行も一緒に挿入する**
（`lines.splice(hIdx + 1, 0, {raw:'', orig:null}, {raw, orig:null})`）。
取り消しでは**その空行も一緒に取り下げて追加前の状態に戻す**。判定規則:

> 取り消す行の**直前**が「`orig === null` かつ空行」で、**その前**が `## ` 見出しなら、その空行も除去する。

この規則は挿入順に依存せず収束する（同一セクションに2件追加してからどちらを先に取り消しても
最終的に元のバイト列に戻る。TB-U3 で照合）:

空セクション（F1 の `## その他`）に A・B の2件を追加した状態を起点に、両方の順序を追う。
`*` 付きが `orig === null`（このセッションで挿入された行）:

```
起点        19: ## その他        ← 見出し（orig は実値）
            20: ''          *   ← A の追加で挿入された空行
            21: - [ ] A     *
            22: - [ ] B     *   ← B の追加は既にタスクがあるので空行を挟まない
            23: ''              ← F1 の元の20行目（末尾改行になる）

▼ 逆順（B → A）                    ▼ 順不同（A → B）
undo B: 直前が 'A' で空行でない     undo A: 直前が空行* でその前が見出し
        → B のみ除去                       → 空行* と A をまとめて除去
  19: ## その他                      19: ## その他
  20: ''          *                  20: - [ ] B     *
  21: - [ ] A     *                  21: ''
  22: ''
undo A: 直前が空行* でその前が見出し  undo B: 直前が見出しで空行でない
        → 空行* と A をまとめて除去          → B のみ除去
  19: ## その他                      19: ## その他
  20: ''                             20: ''
      ＝ F1 と同一                        ＝ F1 と同一
```

### エンジン側の扱い

**操作（op）として実装する**: `{ type:'undoAdd', line: N }` を `runOp` の分岐に追加する。
既存の編集エンジンと同じ経路に乗るため、純関数 `applyOps(text, ops, today)` で
**バイト同一性まで照合できる**（新しい検証経路を作らない）。

### UI

- 表の操作列（現在は［＋子］）に、**追加行にだけ**取り消しボタン［↩︎］を出す。
  title は「この追加を取り消す（未保存）」

## 計画ビュー仕様（Phase T・2026-08-05）

期間を持つ大きなタスク（例「外部IF定義書を 8/15 までに仕上げる」）を扱うためのビュー。
**別ツールにはしない**（データモデルが同じで、記法パーサ・バイト保全・FSA ハンドル・
外部変更検知という最もリスクの高いコードを複製しないため）。

### 描画方式: div の絶対配置（SVG は使えるが、バーには不要）

`createElement('svg')` は `HTMLUnknownElement` になり描画されない。ただしこれは**名前空間の
問題であって file:// の制約ではない**: **`createElementNS` なら file:// でも SVG は本物として
描ける**（2026-08-07 に実測。曲線パス＋`<marker>` の矢印頭まで実寸で描画される
→ `docs/verification-notes.md` §2）。横棒バーは div の絶対配置と CSS で足りるので
名前空間 API を持ち込まないが、**依存関係の矢印（次バッチ）は SVG で描く**。

```
#timeline-view            （リスト時は hidden）
  #tl-note                （案内・警告・ガード理由。banner 系クラスを再利用）
  #tl-scroll              （overflow-x: auto）
    .tl-head              目盛り（ズームごとの刻み）
    .tl-rows              position: relative
      .tl-today           今日の縦線（1本・z-index 1・**pointer-events: none**）
      .tl-row.tl-section  セクション見出し行（Phase T4・折り畳みボタン）
      .tl-row
        .tl-label         字下げ＋本文（position: sticky; left: 0; z-index 2）
        .tl-track         position: relative
          .tl-bar         position: absolute（left/width をピクセル計算・tabindex=0）
            .tl-bar-fill  完了率の塗り（Phase T4・pointer-events: none）
            .tl-bar-text  日数と完了率（幅が足りなければ出さない）
            .tl-handle    端ドラッグのつかみ（Phase T4・幅が足りるバーだけ）
          .tl-drag-tip    ドラッグ中のプレビュー（Phase T4・トラック直下に置く）
```

DOM ノード数は `行数×5 + セクション数×2 + 目盛り + 1`。上限（200行）でも約1,100ノード。

**案内・警告は `#tl-note`（ビュー内）に出し、共通バナー（`#banner`）は使わない。**
`render()` から共通バナーに書くと、直後に呼び出し側が出す「完了にしました」等の
情報バナーと奪い合うため。

```js
const TL_PAD_DAYS = 3;           // 表示範囲の余白

function dayNum(ymd)   // Date.UTC ベースの通日
function diffDays(a, b)
```

**`dayNum` は `Date.UTC` を使う**。ローカル `Date` の差分は DST 境界で ±1時間ずれて
日数が1日狂う（JST に DST は無いので実害はないが、回避コストがゼロなので固定する）。

| 項目 | 規則 |
|---|---|
| 対象 | リストの表示対象（絞り込み・「完了を含む」を反映）のうち **🛫 を持つ行だけ**。行の並びはソート select に従う |
| インデント | 元の深さをそのまま使う（親が対象外でも変えない）。ラベルは `└ ` 前置 |
| `end` | 📅 があり `📅 >= 🛫` ならそれ。無い／逆転なら `🛫`（＝1日分のバー） |
| `days` | 両端含む（`diffDays + 1`）。**📅 が無ければ `null`**（推測値を数値として書かない） |

| `from` / `to` | `min(🛫) − 3日` 〜 `max(end) + 3日`。today が `[min(🛫)−31, max(end)+31]` の内なら範囲に含める（→ TB-Q12） |
| `todayIn` | today が `from`〜`to` に入るか。false なら縦線を引かず「今日（YYYY-MM-DD）は表示範囲外です」と表示 |
| `invalidCount` | 📅 < 🛫（逆転）の件数。0でなければ `#tl-note` に警告 |

| `hasCR` | CR 行はドラッグさせない |

### 週報コピー（2026-08-14・TB-WR1/WR2）

日報・週次振り返り（`_prompts/` の AI プロンプト）の**機械的な下ごしらえ**だけをツール化する:

- ツールバーに期間セレクト（**今週／先週**・月曜始まり）と［週報コピー］

### 🏁 On Completion の警告（2026-08-13・TB-R22）

実行されません」。記法自体は TB-Q40 どおり書き換えない（原文保持）。blocked 警告とは独立

### 性能ガード（超過時は描画しない）

「一部のみ表示」はしない。理由と対処を `#tl-note` に出す:

- 行数超過: 「対象が N 件（上限 200 件）のためタイムラインを表示しません。
  セクションやタグで絞り込んでください」
- **描画幅超過**（Phase T4）: 「表示期間が長すぎてタイムラインを表示できません（N 日・ズーム: 日）。

- **閾値は実データが0件の時点での推定値**（2026-08-05 時点の実 tasks.md はタスク0件）。
  **実データで運用してから見直す**

  セクション／タグの絞り込みが効いているときは「絞り込みで隠れている行があるかもしれません」を併記

## タイムライン強化仕様（Phase T4・2026-08-07）

実装前に測って設計を決めた3点（→ `docs/verification-notes.md` §2・§4）:

1. **SVG は `createElementNS` なら file:// でも描ける**（依存関係の矢印の前提。次バッチ）
2. **`setPointerCapture` は動く**（バーの外へ出ても `pointermove` が届く）
3. **ドラッグの後にも `click` が飛ぶ** → 抑止フラグが必須。
   さらに**フラグは次の `pointerdown` で必ず捨てる**（バー外で指を離すと `click` が
   バーに来ないため、残ったフラグが次のクリックを飲む）
4. **`bar.style.left` は CSS 由来の値を読めない** → ドラッグ量は**日付（モデル）から計算する**

### 1. バーのドラッグで日付変更

HTML5 DnD は使わない（離散的なドロップ先向けの API。ここでは連続位置＋日スナップが要件）。
`pointerdown` / `pointermove` / `pointerup` ＋ `setPointerCapture`。

| 領域 | 操作 | 発行する op |
|---|---|---|
| 左端 7px（`ew-resize`） | 開始日だけ | `setStart` |
| 右端 7px（`ew-resize`） | 期限だけ | `setDue` |
| 中央（`grab` / `grabbing`） | 期間を平行移動 | `setStart` ＋ `setDue`（`applyUiOps` で1回の render） |

- スナップは `Math.round(dx / DAY_PX / snap) * snap`（`snap` はズームごと。→ 4節）
- プレビューは**バーの style と吹き出し（`.tl-drag-tip`）だけ**を書き換え、`render()` は呼ばない。
  `requestAnimationFrame` で1フレーム1回に間引く
- 吹き出しは `🛫 2026-08-01 → 📅 2026-08-19（19日）・+4日ずらす`。
  **何日動かしたかをモードごとの言葉で併記する**（Phase T5）:
  平行移動 = `+4日ずらす` / 左端 = `開始 -2日` / 右端 = `期限 +2日`。
  0日のときは書かない。**クランプされた場合も「実際に動いた分」**を出す（要求値ではなく結果）
- 吹き出しは**バーと同じ行の右横**に出す（Phase T5b で上下方式から変更）。
  **同じ行にバーは1本しかないので、横に置けば他の行を一切隠さない。**
  上下に出す方式は、上=セクション見出しの帯・下=次の行を隠すため廃止した
  （どちらに出しても別の行の情報が消える。上下の二択が誤りだった）
  - 順序は **右横 → 入らなければ左横へ反転 → それも無理なら可視域に抑える**。
    最後の抑え込みではバーに重なるが、吹き出しは不透明な背景と枠を持つので読める
  - **判定は図の幅ではなく「画面に見えている範囲」で行う**。図の幅で判定すると、
    図が狭いとき（F10 は288px）に「右に入らない」と誤判定して左へ回り込む
    （2026-08-07 に実測して修正）。ラベル列は sticky で図に重なるので可視域から差し引く
  - 文字が変わると幅も変わるので、位置は描画のたびに測り直す
- **Escape でキャンセル**（op を出さず元の位置へ戻す）。`pointercancel` も同じ経路。
  ドラッグ中の Escape は**ポップオーバーの Escape ハンドラへ渡さない**（`stopPropagation`）
- **逆転（📅 < 🛫）は作らせない**: 左端が `due` を越える／右端が `start` を下回る方向は
  **クランプして止める**（拒否して何もしないより、止まる方が操作として分かる）
- 変化0日なら op を出さない＝**クリック扱い**（計画ポップオーバーが開く）
- CR 行はドラッグ不可（他の編集経路と同じ）

#### 端ハンドルを出す条件（TB-Q45・条件付き承認への対処）

> **中央を掴む余地（7px）を必ず残す。残らない幅では端ドラッグを出さない。**

| 条件 | ハンドル | 根拠 |
|---|---|---|
| 📅 あり・幅 **21px 以上** | 左右2つ | 7 + 7 + 中央7 = 21 |
| 📅 なし・幅 **14px 以上** | **右だけ**（📅 を新設する。TB-Q46） | 7 + 中央7 = 14。片側だけなので左右の判定が重ならない |
| 上記未満 | なし（中央ドラッグのみ・`grab` のみ） | 「できるように見えて不定」より「できないと分かる」 |

実測: 日ズームでは 5日=80px→両端 / 1日=16px→右だけ / 2日=32px→両端。
週ズームでは 5日=20px なので**ハンドルは出ない**（中央ドラッグは効く）。月ズームも同様。

#### キーボード（ドラッグを唯一の手段にしない）

バーは `tabindex=0`。`←→` = 期間を1日平行移動 / `Shift+←→` = 期限だけ伸縮
（📅 が無ければ `Shift+→` で新設）/ `Enter`・`Space` = 計画ポップオーバー。
**`Cmd/Ctrl`・`Alt` 付きは無視する**（ボードの `Cmd/Ctrl+←→` と衝突させない。TB-Q47 で
「開始日だけ」のキー割り当ては作らず、計画ポップオーバーに任せると決めた）。
`render()` でバーが作り直されるので**同じ行のバーへフォーカスを戻す**。

### 2. 依存関係（🆔 / ⛔）と矢印 — Phase T6（2026-08-12 実装）

#### 一次情報（2026-08-12 に再確認。公式ドキュメントとプラグインのソース）

| 項目 | 確認結果 |
|---|---|
| 記法 | `🆔 <id>` / `⛔ <id>,<id>`。複数は **`,` 区切り・空白は任意で可** |
| id の文字 | `[A-Za-z0-9_-]+` |
| 重複 | "intended to be unique across the whole vault … **However, there is no checking for this.**" 重複するとその id を持つ**全タスクに依存**する |
| トークン順 | `Description → **Id → DependsOn** → Priority → 🔁 → 🏁 → ➕ → 🛫 → ⏳ → 📅 → ❌ → ✅`（`src/Layout/TaskLayoutOptions.ts` の enum。コメント "The order here determines the order that task fields are rendered and written to markdown"） |
| blocked | 自分が TODO/IN_PROGRESS/ON_HOLD **かつ** 依存先のいずれかも同じ |
| 完了・中止の影響 | **"If either end of dependsOn link is DONE, CANCELLED or NON_TASK, no blocking occurs"** |
| blocked の完了 | **Tasks は止めも警告もしない**（公式に記述なし） |

> **ドキュメントの矛盾と採否**: 別のページには id が "Placed at the end of the task line" とあるが、
> **行を書き出しているソースの enum は Priority より前**。enum のコメントが「書き出し順を決める」と
> 明言しているので **enum を採用**した（ドキュメントよりソースを信じる）。

#### 5値化との整合

| 本ツール | Tasks の型 | 関係に参加するか |
|---|---|---|
| `todo` `[ ]` / `doing` `[/]` / `hold` `[h]` / `other` | TODO / IN_PROGRESS / ON_HOLD / Unknown=TODO | **する** |
| `done` `[x]` / `cancelled` `[-]` | DONE / CANCELLED | しない |

> **`finished`（`done` か `cancelled`）が、ちょうど「関係に参加しない」と一致する。**
> Phase T3 で `done` と `finished` を分けた設計をそのまま使い、**新しい判定を足さない**。

#### 記法の編集（バイト保全）

- op は `{type:'setId', line, id}` と `{type:'setDependsOn', line, ids}`
- 挿入位置は **標準順の位置にある「最も前のメタトークン」の直前**（`opSetTags` と同じ方式）。
  `🆔` は `⛔ → 優先度 → 🛫 → ⏳ → 📅 → ✅` の最も前、`⛔` は `優先度 → …` の最も前
- **既存トークンは動かさない**（非標準順は矯正しない）。既存があれば位置のまま値だけ差し替える
- `editContent` の再構成順は `本文 → 🆔 → ⛔ → 優先度 → 🛫 → 📅 → ✅`
- **id の発行**: `[a-z0-9]{6}`。**衝突チェックは開いているファイル内だけ**
  （FSA で1ファイルしか読んでいないので vault 全体は見られない）。20回引き直して駄目なら例外

#### 依存グラフ（純関数 `depGraph(rows)`）

- **表示中の行全体**から作る（🛫 が無くて図に出ない行も含める）。リスト・ボードの印と
  完了時の警告も同じグラフを見る
- 循環検出は white/gray/black の DFS を**明示スタックの反復**で書く（深さを気にしない）。
  自己参照（`⛔` に自分の id）も循環として拾う
- 重複 id は辺にしない／存在しない id は `unresolved` に数え、**原文は残す**
  （他ファイルのタスクを参照している可能性があるので消してはいけない）
- 表示する辺（`live`）は**どちらの端も `finished` でないもの**だけ

#### 矢印の描画

- **SVG を `createElementNS` で作る**（`createElement('svg')` は HTMLUnknownElement。
  file:// で描けることは実測済み → `docs/verification-notes.md` §2）
- 座標は**モデルから計算する**（x = 日オフセット × dayPx、y = 描いた行の累算）。
  そのため **CSS 側で全行の高さを 24px に固定**した（見出し行も含む）
- 先行バーの右端中央 → 後続バーの左端中央へ3次ベジェ、`<marker>` で矢印頭
- `pointer-events: none`（バーのドラッグを奪わない）／`z-index: 1`（ラベル列より下）
- **矢印を1本も描かない条件**: 循環・重複 id・上限超過（`MAX_TL_ARROWS = 60`）。
  いずれも理由を `#tl-note` に出す（一部だけ描くと嘘になる）
- **端が図に出ていない関係は描かず件数だけ出す**（TB-Q52。折り畳み・絞り込み・🛫 なしで起きる）

#### 設定 UI（編集モーダルの「依存（先行タスク）」欄）

- 関連ノートと同じチップ＋追加の作法。**依存は id ではなく行番号で持つ**
  （id 未設定のタスクも選べるようにするため。保存時に無ければ発行する）
- 選択肢から外すのは**自分・自分の子孫・自分に依存しているタスク**（直接循環の予防）。
  **祖先は外さない**（親子関係は依存関係ではないので親を先行にしても循環しない）
- 新規追加では依存を付けない（追加後に編集で足す。`addTask` に載せると id 発行と挿入位置が絡む）。
  **このため新規モーダルには依存欄そのものを出さない**（出すと「入力できるのに保存で
  黙って捨てられる」口になる — TB-R20）。編集モーダルでは、依存があれば
  他の詳細項目と同様に「詳細」を自動で開く（隠れた値に気づかないのを防ぐ）

#### 表示と完了時の扱い

- リストの内容セルとボードのカードに **`⛔N`**（TB-Q54）。数字は**関係の総数**で、
  色を変えるのは blocked のときだけ（`--warn-border`）
- **先行が終わっていないまま完了にしたら警告するが止めない**（TB-Q55）。
  Tasks 自身も止めも警告もしないので**記法の意味を変えない**。
  8/3 のアーカイブ事故の教訓は「無言で通さない」であって「禁止する」ではない

### 3. セクション区切り

- 行をセクションごとにまとめ、`.tl-row.tl-section` の見出し行を挟む（`▾ PEW（3）`）
- **折り畳める**。状態は `state.tlClosed`（Set）で持ち、**永続化しない**（TB-Q48。
  tasks.md 側でセクション名が変わると迷子になる。メモ・ボードの子と同じ方針）
- **🛫 を持つ行が無いセクションの見出しは出さない**（空の帯が並ぶのを防ぐ）
- 帯はラベル列から続けて塗る（`.tl-label` は sticky のため独自の背景を持つ）
- **ファイルを読み込んだら `memoOpen` / `boardKidsOpen` / `tlClosed` を捨てる**
  （行番号もセクション名も別のファイルでは通じない）

### 4. ズーム（日 / 週 / 月）

| ズーム | 1日の幅 | 目盛り | スナップ |
|---|---|---|---|
| 日（既定） | 16px | 7日ごとに `8/1` | 1日 |
| 週 | 4px | **7日または14日ごと**に `8/3`（下記） | 1日 |
| 月 | 1.6px | 月初に `8月` | **7日** |

- **スナップ単位をズームに合わせる**（TB-Q49）。月ズームは1日=1.6px なので1日スナップでは掴めない。
  日単位の微調整はバークリック → 計画ポップオーバー

#### 粗いズームは短い範囲では選べない（Phase T5・2026-08-07）

> **図の幅がラベル列（260px）以上になるズームだけを選べる。日ズームは常に選べる。**

閾値の根拠（スクリーンショットで実測）: 月ズームで **163日=277px** は月目盛りが6つ並んで
読めるが、**100日=176px** は苦しく、**38日=61px**（この指摘の発端）は判読不能。
「図が自分のラベル列より細い」状態は図として成立しないので、そこを境にした。
この条件を満たすのは **月=163日以上・週=65日以上**。

- 選べないズームは `<option disabled>` にし、**理由を `title` に書く**
  （「この期間（38日）では図が細くなりすぎます（163日以上で選べます）」）。
  disabled なだけでは「なぜ選べないのか」が分からない
- **選択（`state.ui.tlZoom`）は書き換えない。** 絞り込みで範囲が縮んだ間だけ日で描き、
  範囲が戻れば選択も戻る。選択を書き換える実装だと**理由の表示が次の再描画で消える**
  （2026-08-07 に実測して設計変更。`#tl-note` に出す理由は毎回計算する）
- 実効ズームが選択と違うときは `#tl-note` に
  「この期間（N日）では「月」だと図が細くなりすぎるため「日」で表示しています」
#### 目盛りの刻みは「ラベルが収まる最小の刻み」で決める（Phase T5b・2026-08-07）

> **刻みは px/日だけで決まり、範囲の長さには依存しない。**
> 決め手は**その範囲に出るラベルの最大幅**（2桁月を含むか）。

ラベル幅の実測（11px フォント・`padding-left: 3px` 込み）:
`8/3`=21.5px / `8/10`=26.7px / **`10/4`=26.7px** / `11/24`=31.4px / **`12/29`=33.1px**

図で確認した境目（週ズームの7日刻み = 28px 間隔）:

| 範囲 | 最大ラベル | 7日刻みの結果 | 採用 |
|---|---|---|---|
| 8月起点65日 | `10/4`（26.7px） | 収まって読める（すきま1.3px） | **7日刻み**（目盛り10本） |
| 11月起点100日 | `11/16`（31.4px） | `11/1611/2311/30` と重なり読めない | **14日刻み**（8本） |

- 見積りは `3 + 文字数 × 6.0`（実測とほぼ一致）。**必要なのは「間隔に収まること」だけ**で、
  すきまに余裕（+2px）を要求すると読める `10/4` まで弾いてしまう（実測して修正）
- 候補は `[そのズームの最小刻み, 14, 28]` の順に試し、最初に収まったものを使う
- **日ズームは常に7日刻み**（7日=112px でどのラベルも収まる）。
  **月ズームは切り替え不要**（1ヶ月=48px に対しラベルは最大 `12月`=26.9px。実測ですきま22px）
- `state.ui.tlZoom` を永続化（**既知値のみ受け入れ**、未知なら `day`。TB-Q17 と同じ方針）
- 選択 UI は**ビュー切替タブと同じ行**（`ズーム: [日/週/月]`）。タイムライン表示中だけ出す
  （`[hidden]` は `display: flex` に負けるので `[hidden]` 側の規則も書く）

### 5. 子タスクの完了率

- 子を持つタスクのバーに **`3/5（60%）` と塗り**（`.tl-bar-fill`）。子なしには出さない
- **分子は `done` だけ**（着手中を 0.5 と数えない＝推測を混ぜない）
- **中止（`[-]`）はその部分木ごと分母から外す**（TB-Q51。やらないと決めた作業を未達に数えない）
- 孫も数える（部分木の全子孫）
- 塗りを併せて出すのは、狭いバーでは数値が読めないため（文字は 96px 以上のときだけ）

## メモ仕様（Phase N・2026-08-06）

タスクに付随する情報を持たせる。**独自記法を作らず、Obsidian でそのまま読める md にする。**

### 記法: `\t- メモ`（インデントした箇条書き）— TB-Q18

**Obsidian Tasks の公式ドキュメントで確認（2026-08-06）**:

> "Tasks only supports **single-line checklist items**."
> "Text after the first line in a multi-line checklist item is **ignored
> (but is unaffected in the stored `.md` file)**."

つまり **Tasks はこの行を無視するが、ファイル上は変更しない**。撤退してもデータが孤児にならない。

ご提示の案（プレーンなインデント行 `\t補足メモ`）から**箇条書きに変更**した理由:

| 形 | Obsidian の表示 | 空行の誤認 |
|---|---|---|
| `\t補足メモ`（プレーン） | CommonMark のリスト項目継続で**タスク行と同じ段落に連結**され1行に見える | タスク直後の空行をメモと誤認し得る |
| **`\t- 補足メモ`（箇条書き）** | **タスクの下に入れ子の箇条書き**。Obsidian のアウトライナで一緒に折り畳める | `^\t+- ` に一致しないので**構造的に誤認しない** |

### メモ行の定義

> **メモ行 = タスク行の直後に連続する行のうち、`^\t+- ` で始まり `- [` では始まらず、
> インデントがそのタスクより深いもの。**

- **プレーンなインデント行はメモとして読まない**（従来どおりパススルー・一切触らない。TB-Q19）。
  両形式を読むと「編集時にどちらで書き戻すか」の再整形問題が生まれ、
  **触っていない行のバイトを変える**危険があるため
- 空行・HTML コメント・見出しは `^\t+- ` に一致しないので巻き込まない
  （F1 の14行目＝13行目のタスク直後の空行はメモにならない）
- 複数行メモは**同じインデントの箇条書きを連続で並べる**（1行=1項目）

### 部分木の境界を1関数に集約（最重要）

メモ導入前は「より深いタスク行が続く限り」で部分木を数える処理が**5箇所に散っていた**。
メモ行に当たると打ち切られるため、そのままでは:

| 箇所 | 起きること |
|---|---|
| `opMoveSection` | セクション移動でメモが取り残される |
| `opAddChild` | 子タスクがメモより前に挿入される |
| `subtreeLines`（アーカイブ） | **メモが tasks.md に孤児として残る**（実データが静かに汚れる） |
| `hasAddedDescendant` | 取り消し可否の判定がずれる |
| `insertIntoSection` | 最終タスクのメモの前に挿入される |

→ **`subtreeEnd(lines, i)` を1つ作り、5箇所すべてをそれに置き換えた。**
`isMemoLine(raw, parentIndent)` / `memoBlock(lines, i)` も同じ節に置く。

### メモの編集（`{type:'setMemo', line, text}`）

- **位置ごとに比較し、一致する行はオブジェクトごと据え置く** → 変更していないメモ行の
  バイトと `orig` は変わらない（**同じ本文の setMemo はファイルがバイト同一** — TB-M1）
- 行数が増えれば挿入（`orig: null`）、減れば余りを除去
- **本文が `[ ] ` で始まる行は拒否する**（`\t- [ ] …` はタスク行になってしまう。TB-M6）。
  `- [ ] …` は `\t- - [ ] …` になり箇条書きの本文なので許す
- **メモ行の削除は提供する**（メモ編集の一部。TB-Q21）。
  **タスク行（`- [` で始まる行）の削除は引き続き提供しない**
- `opUndoAdd` は、取り消す追加行のメモ行が `orig === null` なら**一緒に取り下げる**（孤児を残さない）
- アーカイブは**メモ行も archive.md へ移す**。
  ただし**確認とバッジの件数はタスク数で数える**（メモ行で膨らませない。移動行数は成功バナーの「N行」で示す）

### UI

- 操作列に **［＋メモ］/［メモ］**（ホバー表示。［＋子］と同じ作法）
- メモを持つ行は内容セルに **`📝N`** マーカー（常時表示）。**クリックで直下に展開／折り畳み**
- 展開したメモ行はダブルクリックで編集。ポップオーバーの textarea は
  **Cmd/Ctrl+Enter で確定**（Enter は改行）。空にして確定すると削除
- **展開状態は永続化しない**（TB-Q24。行番号は編集で動くため、保存すると別の行が開く）

## ボードビュー仕様（Phase S・2026-08-06）

### 列＝セクション（TB-Q30）

ファイルの `## ` 見出しから列を自動生成（増減に追随。**空セクションも列として出す**）。

採用理由: **ドロップが `opMoveSection`（既存・バイト保全済み・部分木ごと移動）になる**。
- 不採用「列＝状態（未/済）」: 2列しかなくボードとして機能しない
- 不採用「列＝優先度」: 4列で成立し実装も同程度だが、優先度は既にセル2クリックで変えられる。
  **将来「列の元（セクション／優先度）」のトグルは安価**（ドロップが `setPriority` に分岐するだけ）

### 列の基準を切り替える（Phase T2・TB-Q43）

**`列: [セクション / ステータス / 優先度]` の `<select>` はビュー切替タブと同じ行に置く**
（Phase T3 で移動。ボードの中に置くと**ボードへ入るまで存在に気づけない**）。
ボード表示中だけ出す（`[hidden]` は `display: flex` に負けるので `[hidden]` 側の規則も書く）。
**タブ自体の幅は変えない**（幅が動くと押し間違いが起きる）。
現在の基準はボードへ入る前でも**ボードタブの `title`**（「カードを列に並べる（列: ステータス）」）で読める。
Phase S で「将来のトグルは安価（ドロップが分岐するだけ）」と書いた拡張をそのまま実装した形。

| 基準 | 列 | ドロップ時の op |
|---|---|---|
| セクション（既定） | ファイルの `## ` 見出し（空セクションも） | `moveSection` |
| ステータス | **未着手 / 着手中 / 完了** は常設、**保留・中止は該当があるときだけ**（Phase T3） | `setStatus` |
| 優先度 | **⏫ 高 / 🔼 中 / 🔽 低 / なし**（固定4列） | `setPriority`（なし = `null`） |

- **列は `boardColumns()`、カードの所属は `cardKeyOf(t)`、移動は `moveCardTo(line, key)` の
  3関数だけが基準を知っている。** ドラッグもキーボード（`Cmd/Ctrl+←→`）も同じ3関数を通る
  ので、片方だけ基準に追随しない状態にならない
- **不明な記号（`[?]` `[!]` 等）のカードは「未着手」列に置く**（専用の列を作らない）。
  そこから別の列へ動かせば標準の記号に変わる
- **5列になるときは列幅を 300px → 220px に詰める**（`cols-many`）。
  横スクロールに逃がすと**完了列が画面外に出る**（2026-08-06 に実測して追加）
- 🔺（最高）は「高」列、⏬（最低）は「低」列に寄せる（並び順の `PRI_RANK` と同じ考え方）
- **ステータス列のときだけ「完了を列内の最下部へ」ソートを適用しない**
  （完了は「完了」列に集まるので、列内で下げる意味がない。TB-G7）
- 「完了を含む」OFF のとき、ステータス列の**「完了」列は空のまま見出しだけ残す**
  （列が消えると「完了列が無い＝壊れた」ように見える。件数 `(0)` で状態が読める）
- `state.ui.board.groupBy` を `tools:taskboard` に永続化。**既知値（3つ）のみ受け入れ**、
  未知なら `section` へフォールバック（TB-Q17 と同じ方針）

### カード（TB-Q31）

1タスク＝1カード（**深さ0だけ**）。本文（`[[リンク]]` 除去）＋ `📝N`／期限（リストと同じ色分け）／
優先度／タグ／`▸ 子 N`／［移動］。**カードクリックで編集モーダル**（Phase E を再利用。
閉じるとフォーカスがカードに戻る）。

- 完了カードは muted、「完了を含む」OFF では出ない、ON では**各列の中で最下部**
  （リストと同じ `subtreeAllDone` 判定を列内に適用）

### 子タスクは親カードに折り畳んで含める（TB-Q32）

**エンジンの規則（子は親と一緒に移る・子だけ移動できない）と UI を一致させる。**
独立カードにすると「操作できそうに見えるのに動かせない」状態が生まれる。

- 既定は畳む。`▸ 子 N` で展開。**子の行クリックでその子の編集モーダル**
- **子の行に `draggable` は付けない**（親と一緒に動く）
- 展開状態は永続化しない（`state.boardKidsOpen`。行番号が編集で動くため）

### ドラッグ&ドロップ

- HTML5 `draggable`（外部ライブラリなし）。`dataTransfer` に行番号を載せる
- **`dragover` で必ず `preventDefault()`** — これを忘れると `drop` が発火しないのに
  例外も警告も出ない。**テストは「イベントが飛んだか」ではなく「保存後のファイル内容」で照合する**（TB-B6）
- 対象列に `.drop-target`、掴んでいるカードに `.dragging`。`dragend`/`dragleave` で消す
- **同じ列へのドロップは何もしない**（`opMoveSection` の no-op）

### ドラッグ以外の移動手段（TB-Q33）

ドラッグを唯一の手段にしない:

- カードは `tabindex="0"`。**`Cmd/Ctrl+←` / `Cmd/Ctrl+→` で前後のセクションへ移動**（端では何もしない）
- **Enter / Space で編集モーダル**
- **［移動］ボタン**で既存のセクションポップオーバー（マウスだけの経路）

### 性能ガード

`MAX_BOARD_CARDS = 300`。超過時は**描画せず**理由を表示（一部のみ表示はしない）。

### Excel 用コピー

**リストと同じ列**（ボードは同じ行集合の別表示なので列を変える理由がない）。

## テキスト検索仕様（Phase S・2026-08-06）

### 対象（TB-Q34）

**タスク本文 ＋ メモ ＋ タグ ＋ 関連ノート名**。関連ノートを含めるのは
`[[2026-07-07]]` のような日付ノートから辿る使い方があり、関連ノート列に出ている情報だから。

- **NFC 正規化 ＋ 小文字化して比較**（macOS 由来の NFD で取りこぼさない）
- **250ms デバウンス**・インクリメンタル
- **検索語は永続化しない**（`state.ui.q` はメモリのみ。`persistUi` に入れない）
- セクション / タグ / 「完了を含む」との併用は **AND**

### ヒットの見せ方（TB-Q35）

> **一致したタスクと、その祖先と、その子孫を表示する。一致しない兄弟は隠す。**

- 子だけ一致したときに**親が消えて文脈が失われるのを防ぐ**
- 一致した親の子孫も出す（出さないとボードの `▸ 子 N` と実際の表示が食い違う）
- **タグ絞り込みとは意図的に挙動が違う**（タグはグループ全体を出す）:
  **タグは「分類を眺める」操作なのでグループごと見せる／検索は「1つを探す」操作なので
  一致だけに絞る方が速い。** 同じ絞り込みに見えて目的が違うので、
  後から「なぜ挙動が違うのか」を再検討しなくて済むようここに残す
- **ヒット件数を表示**（「N 件ヒット」）。0件のときは検索語を含む案内
  （無言で空になると壊れたように見える）

### メモが一致した行はメモを自動で展開する（Phase T5・2026-08-07）

メモだけが一致した行は、畳んだままだと `📝N` マーカーしか出ず**なぜヒットしたのかが読めない**
（ハイライトは展開したメモに付く仕様のため）。そこで検索語がメモ本文に一致した行は、
その行のメモを自動で開く。

- **自動で開いた行だけ `state.memoAutoOpen` で覚える**。検索語を変える・やめるときに
  それだけを畳み、**手動で開いたメモは畳まない**
- 検索のたびに「前回の自動展開を取り消してから測り直す」（開きっぱなしを防ぐ）
- 永続化しない（`memoOpen` と同じ方針。読込時に捨てる）
- **ボードのカードにも展開したメモを出す**（Phase T5b・`.card-memo`）。
  検索で一致した行はカードでも**なぜヒットしたのかが読める**。
  リストで手動展開したメモもカードに出る（**同じ `memoOpen` を見るので、
  リストとボードを往復しても状態がずれない**）。ハイライトも同じ `appendHighlighted` を通す
  - ボードにメモの開閉ボタンは置かない（開閉はリスト側と検索が担う。カードを操作口で埋めない）

### ハイライト（TB-Q36）

内容セル・カード本文・展開したメモに `<span class="hit">` を付ける（`createElement` のみ）。

- **判定は NFC 正規化後、装飾は表示文字列に対する素の大文字小文字無視検索**。

## 追加・編集モーダル仕様（Phase E・2026-08-06）

### Phase 0 の不具合と原因（既定値がセットされなかった件）

**原因: 記憶を書き込む経路がコード全体で1箇所（追加フォームでの追加）しかなかった。**
Phase T/N で「セルクリック2回で期限を入れる」経路を第一級にしたため、
実運用の日付設定はそちらを通り、**記憶が一度も埋まらなかった**。
記憶・復元の経路自体は動いていた（実測済み）。

→ 対処は2つ:
1. **`rememberFromOp()` で全編集経路から記憶する**（`applyUiOp` の中＝1箇所）。
   対象は `setStart` / `setDue` / `setPriority` / `setTags` / `moveSection` / `addTask`
2. **投入は `openTaskModal()` の1箇所だけ**（従来は `loadText` とフォーム開閉の2箇所だった）

この型（テストが実装と同じ思い込みを共有する）は
`docs/verification-notes.md` §5b「テストが緑でも意味を失う3つの型」型3 に記録した。

### 開き方（TB-Q25）

| 操作 | モード |
|---|---|
| ［＋タスク追加］ | 新規 |
| 操作列の **［編集］** | 編集 |
| 展開したメモ行のダブルクリック | 編集（メモにフォーカス） |

**行のダブルクリックは使わない** — 内容セルにダブルクリックのインライン編集があり、
行に付けるとバブリングで両方発火する。

### 1行追加フォームは廃止（TB-Q26）

既定値の投入箇所が2つあることが Phase 0 の不具合の温床だったため、統合して1つにする。
素早い追加は ［＋タスク追加］→ 内容 → **Enter または Cmd/Ctrl+Enter** で従来と同じ打鍵数。

### セル単位のポップオーバー編集は残す（TB-Q27）

1項目だけ直すときの2クリックは価値があるため残し、**代わりに `openPopover` に
ビューポート内クランプ**を入れて「画面はじで途切れる」を根本解決する（改訂2）。

### フィールドと既定値

内容 / メモ（複数行）/ タグ / セクション / 開始日 / 期限 / 優先度 / **関連ノート**。

- **内容以外はすべて任意**。`<details>` で「詳細（すべて任意）」に畳み、**初期は内容とメモだけ**見せる
  - **値が入っている項目が1つでもあれば詳細を開く**（隠れた値に気づかないのを防ぐ）
- **内容欄はタグと関連ノートを含まない**（専用の欄で編集するため）。
  含めると内容を編集したとき `bodyTextOf` でタグが二重になる（2026-08-06 にスクリーンショットで発見）。
  **`#102` のような数字のみはタグではないので内容側に残る**
- 新規モードの既定値は `state.ui.add`（クリアも `''` として記憶）。
  記憶したセクションがファイルに無ければ先頭セクションへフォールバック
- 編集モードは既存値を読み込む（記憶は使わない）

### 関連ノート（TB-Q29）

- 本文中の `[[...]]` を編集する。テキスト入力で名前を指定（`[[ ]]` は自動）
- **［今日のデイリー］で `[[YYYY-MM-DD]]`（今日）を1クリック挿入**。重複は追加しない
- 複数の追加・削除可。**変更時は本文末尾に正規化される**（元の位置は保たれない）
- **内容・タグ・リンクのいずれも変わっていなければ `editContent` を発行しない**（バイト保全）
- 表の列名は **「関連ノート」**（旧「元ノート」。設定手段がなかった時代の名前）
- **Obsidian で開くリンク（TB-Q1。2026-08-13 に spec 本文へ明文化・モーダルにも展開）**:
  リストの関連ノート列のチップと、編集モーダルの関連ノートチップは
  `obsidian://open?vault=<vault 名>&file=<encodeURIComponent(名前)>` の `<a>`。
  クリック時に Chrome の外部プロトコル確認ダイアログが出るのは仕様
  （タグ・依存のチップはリンクにしない — TB-R21）
- **vault 名は設定値（2026-08-17・公開に伴う汎用化 — TB-Q56）**: `lib/config.js` の
  `vaultName`（`localStorage` の `tools:config`）。ツールバーの「vault 名」欄で編集し、
  保存は `change`（blur / Enter）。**既定は空 = 未設定**で、そのときは関連ノートを
  `<a>` にせず `<span class="chip">` として名前だけ出す（TB-R25）——
  間違った vault 名のリンクは押しても黙って何も起きず、原因が分からないため。
  この設定が効くのは `obsidian://` リンクだけで、`tasks.md` の読み書きには関係しない

### 挙動

- **中央配置のオーバーレイ**（`position: fixed; inset: 0`）。
  `width: min(620px, 94vw)` / `max-height: 88vh` ＋ 内部スクロールで画面端で切れない
- **Escape で閉じる**（`isComposingKey` で変換中は無視）/ オーバーレイ外クリックでも閉じる
- **内容欄の Enter で保存**（Phase I の「Enter=追加」の決定を維持。IME ガード必須）/
  **Cmd/Ctrl+Enter はモーダル内のどこからでも保存**（メモ textarea でも有効）
- **未保存で閉じようとしたら `confirm('入力を破棄しますか？')`**（開いた時点の値と比較）
- **フォーカス管理**: 開く前の `activeElement` を記憶 → 内容欄へ →
  **Tab はモーダル内で循環**（表示されている要素だけを対象。閉じた `<details>` の中は除く）→
  閉じたら元へ戻す
- **新規モードは保存後もモーダルを開いたまま**にし、内容とメモだけ空にする
  （Phase I の TB-Q7「連続追加を自然にする」と同じ意図。他の欄は前回値として残る）。
  編集モードは保存で閉じる

### 編集モードは変更したフィールドの op だけ発行

発行順（**行番号が動く操作を後ろに置く**）:

```
editContent（内容・リンクが変わったとき。タグもこれに含まれる）
  または setTags（タグだけ変わったとき＝インプレースで最小差分）
→ setStart → setDue → setPriority → setMemo → moveSection
```

`moveSection` を先に出すと行番号が変わり、後続の op が別の行を編集してしまう。

## 保存仕様（外部同時編集への防御）

保存は明示ボタンのみ。自動保存しない。

1. 保存クリック → ハンドルから現ディスク内容を再読込
2. `NFC(ディスク) !== NFC(読込時スナップショット)` → **書き込まず**警告バナー
   「Obsidian 側で変更されています。再読込してください」＋［再読込］ボタン
   （再読込は未保存編集の破棄を confirm してから）
3. 一致 → `createWritable()` で全文書き込み → スナップショット更新 → 成功バナー
   「保存しました（変更N行・追加M行）」（編集追跡から算出）
4. 書き込み失敗（権限剥奪等）→ エラーバナー。編集状態は保持
- **比較は必ず NFC 正規化後**（macOS の NFD 由来の偽検知防止）。正規化は比較用の
  一時コピーのみ。**保存内容には適用しない**（バイト保全を壊すため）
- window focus / visibilitychange 時にも再読込して比較: 未編集なら自動再読込＋情報表示、
  編集中なら警告バナーのみ（既知の制約: 比較→書込間の TOCTOU は許容。個人ツールのため）

## ハンドル永続化仕様（設計判断: ToolStorage 拡張ではなく専用実装）

`FileSystemFileHandle` は structured clone が必要で、JSON/localStorage ベースの
ToolStorage には原理的に保存できない。よって **taskboard.html 内の専用 IndexedDB
実装**とする（db: `tools-taskboard` / store: `handles` / key: `tasksmd`。file:// では
全ページがオリジンを共有するため db 名接頭辞で衝突防止 — storage.js と同じ考え方）。

再訪フロー: 起動時に IDB からハンドル取得 → `queryPermission({mode:'readwrite'})` が
`granted` なら即読込。`prompt` なら［前回のファイルを開く: tasks.md］ボタンを表示し、
**クリック1回**で `requestPermission` → 読込（Chrome 側の許可ダイアログは Chrome の仕様）。

## フォールバック仕様（FSA 非対応 = Safari/Firefox）

`'showOpenFilePicker' in window` で判定。非対応時:
- 読込: `<input type="file" accept=".md,.txt">`
- 保存: ［.md をダウンロード］＋［全文コピー］（Obsidian へ手動反映）
- 常設情報バナー「このブラウザでは直接保存できません。ダウンロード/コピーで手動反映して
  ください」。外部変更検知・ハンドル永続化は無効

## 表示仕様（ソート・絞り込み・色分け）

- ソート: ファイル順（既定）/ **開始日昇順**（開始日なしは最後、同値は期限→ファイル順。
  TB-Q13。ガントの慣習に合わせるが**既定は変えない**）/ 期限昇順（期限なしは最後、
  同値はファイル順）/ 優先度順（⏫→🔼→なし→🔽。🔺は⏫扱い・⏬は🔽扱い）
- 絞り込み: セクション / タグ / 「終了を含む」（完了・中止。既定 OFF → TB-Q2）。組み合わせ可
- **完了グループは常に最下部**（Phase N・TB-Q20）。**ソート指定より優先する第1キー**。
  - 判定は **`subtreeAllDone(t)`**（部分木が全部完了）。
    **未完了の子孫を持つ完了親は上に残る**（進行中の作業が下に埋もれない。
    アーカイブ対象の判定と同じ関数を使う）
  - **リストビューのときだけ適用する**。`state.visibleRows` はタイムラインの行順にも
    使われるため、timeline では従来の並びを保つ（TB-C3）。Excel 用コピーは画面と一致する
  - ボードは列内で同じ規則を適用するが、**列＝ステータスのときは適用しない**
    （完了は「完了」列に集まるため。Phase T2・TB-G7）
  - **着手中（`[/]`）・保留（`[h]`）・不明は下がらない**（終わっていないため）。
    **中止（`[-]`）は下がる**（Phase T3。終了扱い。TB-S31）
- 色分け（未完了のみ）: 期限 < 今日 → 期限セルを `--error` 系で強調 / 期限 = 今日 →
  `--warn-bg` で強調 / 期限なし → 通常。完了行は muted
- UI 状態（**ビュー**・ソート・絞り込み・トグル・**追加フォームの前回値**）のみ
  `tools:taskboard` に自動保存（ToolStorage）。
  **タスクデータ・メモの内容・ファイル内容・ハンドルは localStorage に置かない**（正本は tasks.md）
- **追加フォームの既定値は前回入力した値**（Phase N・TB-Q22）。
  `add: { section, start, due, priority }`（すべて文字列。`''` = クリアも記憶する）
  - 固定デフォルトにしない（「今日」固定だと毎回消す手間が出る）
  - **セクションも同じ方式に統一**（従来の「先頭セクション固定」をやめる）。
    記憶した値がファイルに無ければ先頭セクションへフォールバック（TB-D3）
  - 記憶するのは**追加が成功したとき**（入力途中の値は覚えない）。
    **フォームの値は op を適用する前に読む** — `applyUiOp` → `render` で
    セクション select が作り直されるため、後から読むと値が変わる（2026-08-06 実測）
  - 既定値を入れるのは**読込時とフォームを開いたときだけ**（`applyAddDefaults()`）。
    `render` ごとに入れると**利用者がクリアした欄を再描画で復活させてしまう**（同日実測）
- **`restoreUi` は既知値のみ受け入れる**（TB-Q17）。`sort`/`view` に未知の文字列が
  入っていると `<select>` の値が空になり並び順が壊れるため、列挙に含まれる値だけ採用する
  （Phase T 以前から存在した弱点。`view` の追加で面が広がるので同時に直す）

## 完了アーカイブ仕様（UX監査 TB-4）

表示中の完了タスクを vault の `archive.md` へ追記し、tasks.md から除去する。

- **対象は親子グループ単位**: 深さ0の部分木が**すべて完了**しており、かつ現在の表示
  （絞り込み・「完了を含む」反映後）に出ているもの。部分木ごと移動する。未完了の子孫を持つ
  完了親は文脈ごと残す（ソート・絞り込みと同じグループ単位の設計）
- **前提: 未保存の変更がないこと**（あれば警告して中止 — アーカイブ＝純粋な移動に保つ）
- **tasks.md 側**は保存と同じ外部変更検知（NFC 比較。不一致なら中止＋警告＋再読込ボタン）
- **archive.md のハンドル**は IndexedDB（key `archivemd`）に永続化。無ければ
  `showSaveFilePicker({suggestedName:'archive.md'})` で取得・作成（キャンセルは静黙中止）

### アーカイブ先の取り違え防止（AR-1・2026-08-05。実際に事故った）

**事故**: アーカイブ先を tasks.md と別のディレクトリに保存でき、`~/Documents/archive.md` に
書かれた。保存先が視認できないまま実行できてしまうのが原因。

**API 調査の結論（2026-08-05 実測）**: **`FileSystemFileHandle` から親ディレクトリは取得できない。**

| API | 有無 | 意味 |
|---|---|---|
| `FileSystemFileHandle.getParent()` | **なし**（proto は `createWritable`/`getFile`/`move` のみ） | ファイルハンドル単体では場所が分からない |
| `FileSystemHandle.name` | あり | **ファイル名だけ**は取れる |
| `FileSystemDirectoryHandle.resolve(handle)` | あり | **ディレクトリハンドルがあれば**配下判定＋相対パスが取れる（非配下は `null`） |
| `showDirectoryPicker()` | あり | ディレクトリハンドルの取得手段（追加の許可プロンプトが必要） |
| `File.webkitRelativePath` | 空文字 | `<input webkitdirectory>` 由来のときだけ埋まる（FSA では使えない。API 仕様） |

したがって**「同じディレクトリか」の判定はディレクトリハンドルを持たない限り不可能**。
ご要望の「アーカイブ先が tasks.md と別の場所です: `<パス>`」は**パスを表示できない**ため、
次の代替で実装する:

1. **予防（採用）**: 保存ピッカーを **`startIn: <tasks.md のハンドル>`** で開く。
   Chrome は tasks.md と同じディレクトリでピッカーを開くため、
   別の場所に保存するには利用者が意図的に移動する必要がある（事故の主因を潰す）
2. **可視化（採用）**: アーカイブ実行前の確認に**保存先ファイル名を必ず出す**
   （AR-3 の件数確認と統合。「N件を `<name>` へ移動します。よろしいですか？」）。
   名前だけでも `~/Documents/archive.md` を選んでいれば `archive.md` と表示されるので

### 一括操作の事故防止（AR-3・2026-08-05。実際に事故った）

**事故**: 8/3〜8/4 に49件を一括で完了チェックし、実際には未完了のタスクまでアーカイブされた。

- **保存時**: **未保存の「未完了→完了」が5件以上**なら `confirm('N件を完了にします。よろしいですか？')`。
  キャンセルなら保存しない（`{ok:false, reason:'cancel'}`）
  - **閾値5件・時間窓は使わない**（決定 TB-Q11）。保存は明示操作なので「未保存分の件数」が
    自然な単位で、時間窓のような壊れやすい状態を持たずに済む。
    件数は**保存時に行配列から導出**する（`orig` が未完了・`raw` が完了の行を数える）ので
    カウンタの同期ずれが起きない
  - **1〜2件の通常操作では何も出ない**（既存の操作を重くしない）。
    導出は保存時の1回だけで O(行数)
- **アーカイブ実行時**: **件数によらず必ず** `confirm('N件を <アーカイブ先ファイル名> へ移動します。よろしいですか？')`。
  キャンセルなら `{ok:false, reason:'cancel'}`（archive・tasks とも不変）
  - アーカイブは「ファイルをまたぐ不可逆な移動」なので、1件でも確認する
- 完了解除（`uncomplete`）は数えない。**チェックを入れた件数**だけを対象にする
- **追記手順**: 書き込み直前に archive.md を読み直し（外部編集を消さない。read→write 間の
  TOCTOU は保存仕様と同様に許容）、空なら先頭に `# archive\n` を付与、末尾改行が無ければ補い、
  対象行を**原文のまま**（インデント・メタトークン不変）1行ずつ追記
- **順序: archive 追記 → tasks.md から除去して保存**（archive 書込失敗なら行は消えない。
  tasks 保存失敗時は行配列を読込時状態へ戻し、「再実行すると archive.md 側が重複する」旨を警告）
- 成功バナー「アーカイブしました（N行を archive.md へ移動）」
- フォールバック（FSA 非対応）・デモ中・CR ファイルでは無効

    - **前のテストで開いたままのポップオーバーを閉じてから始める**（バーに重なるとドラッグを奪う）。
      閉じる引き金は **`mousedown`**（`body.click()` では閉じない）
    - 日ズーム / 週 / 月の3枚と、ドラッグ中のプレビュー、折り畳み後、ダークモードを

## Obsidian 手動スモーク項目（Phase T2・`[/]` の見え方と設定手順）

**確認は利用者が行う（未確認）。** `[/]` は Tasks の**既定のカスタムステータスに入っているが、
「正しく表示するにはテーマか CSS スニペットが必要」**と公式に明記されている。
つまり**設定を触らなくても意味（IN_PROGRESS = 未完了）は正しく、見た目だけがテーマ依存**。

- `- [/] タスク` が Obsidian の編集画面・閲覧画面でどう見えるか
  （テーマ次第で「半分塗りのチェックボックス」または「素のチェックボックス」）
- Tasks プラグインのクエリで `not done` に `[/]` が含まれること
- チェックボックスを Obsidian 側でクリックしたときに `/` → `x` へ進むこと（Next Status Symbol）

### 意図どおりの表示にしたい場合の設定手順

1. Obsidian の**設定 → コミュニティプラグイン → Tasks**（プラグイン設定）を開く
2. **「Task Statuses」** セクションを見る
   - **Core Statuses**: `[ ]` と `[x]`（削除・記号変更は不可）
   - **Custom Statuses**: **既定で `[/]` = In Progress（型 `IN_PROGRESS`・次の記号 `x`）と
     `[-]` = Cancelled（型 `CANCELLED`・次の記号 space）が入っている**。
     もし一覧に無ければ ➕ **Add New Task Status** で
     `Status Symbol=/` `Status Name=In Progress` `Next Status Symbol=x` `Status Type=IN_PROGRESS` を足す
3. **見た目**（半分塗りのチェックボックス等）はテーマ／CSS の担当。
   設定内の **Minimal Theme** / **ITS Theme & SlRvb Checkboxes** ボタンを押すと、
   そのテーマが対応する記号一覧を Custom Statuses に流し込める
   （**そのテーマを実際に使っている場合に押す**。押しただけでは見た目は変わらない）
4. ファイル内に本ツールの知らない記号が入ってしまったときは
   **Add All Unknown Status Types** で vault 内の未登録記号を一括登録できる
5. `[-]` を使う場合の注意: **Tasks では型 `CANCELLED` = "done" に一致する**が、
   **本ツールは「不明」＝未完了として扱う**（アーカイブされない）。
   → 「ステータス仕様 / 既知の差異」
