# doc2xl 仕様書兼テストケース

## 概要

Markdown 文書の**見出し階層**を Excel 用の**階層表**（大項目・中項目・小項目＋内容）に
変換するツール。`web/doc2xl.html`、表示名 **Outline**、カテゴリ: 設計。
出力は Markdown 表と TSV（Excel 用コピー）の両方。**MD → Excel の一方向のみ**。

### 位置づけ（3層アーキテクチャ）と、逆方向を作らない理由

| 層 | 担当 | 理由 |
|---|---|---|
| A: Excel → md | MarkItDown ＋ AI（`~/Personal/vault/_prompts/`） | 方眼紙 Excel は視覚レイアウトで意味を表現し、md は論理構造で表現する。**表現モデルが違うので機械変換では意味のある md にならない**（一次情報: 比較検証記事。2026-08-12 の調査） |
| B: md → Excel | **本ツール** | 見出し階層 → 列は**機械的に決まる**（意味判断が要らない）。既存ツールがほぼ無い（pandoc も xlsx 出力に非対応） |
| C: md の編集 | Obsidian・既存ツール | — |

- **逆方向（Excel階層列 → md）は実装しない**（DX-Q6）。①実務の流れは md → Excel の一方向で、
  逆流を用意すると「Excel が正本」になる運用を許してしまう ②「どの列が階層か」の指定 UI が
  必要なうえ、空セル埋め・結合セルで表の形が揺れて機械判定できない部分が残る
  ③必要になったら「貼り付けた TSV に対して階層列を選ぶ」1画面を後から足せる
- **.xlsx の直接読み書きはしない**（ブラウザ単体では外部ライブラリ必須。CDN 禁止の制約）

### 着手判定の記録（tool-backlog の3原則・2026-08-12）

①チーム共有情報ではない（設計書は自分の成果物。ツールは情報を抱えない）
②使う瞬間に得をする（変換の瞬間だけ使い、保持・更新を要求しない）
③既存ツールで代替できない（Tables はセル範囲⇔md表の専用。Convert のタブは11個で打ち止め）。
着手条件は「利用者が自分から要望したもの」の1回目（着手ルールの追記を参照）。

## 変換仕様

### 階層列

- `#`〜`######` を階層列へ。**列番号 = 見出しレベル**。深さ（列数）は入力に現れた
  **最大レベル**から自動判定（H1〜H3 しかなければ3列）
- **階層飛び**（H1 → H3）は間の列を空にして構造を保つ（H2 を勝手に作らない）
- `#` が7個以上の行は見出しではなく本文（CommonMark の上限は H6。DX-Q7）
- **同じ階層の繰り返しは空セル**（既定）。「空セルを上の値で埋める」オプションで
  フィルタ・ピボット向けの形にもできる（DX-Q2）
- **内容の無い見出しも1行として出す**（無言で消さない。見出しだけの骨組み md でも
  アウトライン全体が表に残る）
- 見出しより前の本文（導入文）は階層列すべて空＋内容列に入れる
- YAML front matter（**先頭行**が `---` で始まり `---` / `...` で閉じる塊）は
  表に載らないメタデータなので**落として警告**。閉じが無ければ front matter ではない

### 内容列と md 要素の扱い

> **原則: 落とさない。表現できないものは原文のまま内容列に入れ、警告に「種別 × 件数」を出す。**

| 要素 | 扱い | 警告 |
|---|---|---|
| 箇条書き `- * +` | 1項目 = 1行。**ネストは全角スペース × 深さで字下げ**（インデント2スペースまたはタブ1個 = 1階層） | — |
| 番号付きリスト `1.` `1)` | **`1.` 形式に揃えて番号を残す**（設計書では番号自体が意味を持つ）。ネストの字下げは箇条書きと同じ | — |
| 段落 | 1段落 = 1行。連続行は**セル内改行**で1セルに | — |
| 引用 `>` | 記号を落として本文へ（段落として扱う） | — |
| コードブロック ``` | フェンスを除いた中身を**1セルに改行込み**。言語名は落とす。TSV は `"` で囲む | — |
| インラインコード・強調・打ち消し | 記法を落として文字だけ（`` `x` `` `**x**` `*x*` `~~x~~` → `x`）。**アンダースコア強調（`_x_` `__x__`）は落とさない** — `user_id` のような識別子と機械的に区別できず、強調を消すつもりで識別子を壊す方が実害が大きい | — |
| リンク `[a](url)` | **表示テキストのみ**（URL を落とす） | ○ 件数 |
| Wiki リンク `[[a]]` `[[a\|b]]` | `a` / 別名 `b` のみ | — |
| 画像 `![alt](url)` | alt のみ | ○ 件数 |
| 水平線 `---` `***` `___` | 落とす | ○ 件数 |
| HTML ブロック（`<` で始まる行〜空行） | **原文のまま1セル** | ○ 件数 |
| 脚注定義 `[^x]:` / 定義リスト `: ` | **原文のまま1セル** | ○ 種別と件数 |

### 仕様の限界（意図的に対応しないもの）

- **setext 見出し**（本文行の直後の `===` / `---`）は解釈しない。`---` は水平線として
  警告に出るので無言では消えない
- **箇条書きの継続行**（ぶら下げインデントの2行目）は独立した段落行になる
  （CommonMark の継続規則までは実装しない。行として残るので情報は失わない）

### 文書中の md 表（DX-Q4）

**内容列の右に、表をそのまま展開する**（列位置を動かさない）。

- 出力の列数 = 階層列数 + 1（内容）+ **表の最大列数**。表の列の見出しは空
- 表のヘッダー行も1行として出す。区切り行（`|---|`）は記法なので落とす
- 表の行では**内容列は空**（表が内容そのもの）
- 不採用案「内容列から表を始める」: 内容列の意味が表によって変わり、
  Excel 側でフィルタや数式を当てられなくなる
- セル内の `\|` エスケープは `|` に戻す
- **30列を超える表**は、その表だけ各行を ` | ` 連結で内容列に入れて警告（DX-Q5。
  「一部のみ処理はしない」原則は表単位で守りつつ、幅だけの理由で全体を止めない）

### オプション

| オプション | 既定 | 選択肢 |
|---|---|---|
| 階層列の見出し名 | 大項目/中項目/小項目/細項目/項目5/項目6 | `レベル1〜6` ／ カスタム（カンマ区切り。足りない分は `レベルN` で補う） |
| 空セル埋め | OFF（空セル） | ON（上の値を繰り返す） |
| 内容の単位 | 1行1セル | 見出し配下をまとめて1セル（セル内改行。**表は常に独立した行**） |
| 出力形式 | Markdown表 | TSV |

### 出力の書式

- Markdown 表: セル内改行は `<br>`、`|` は `\|` にエスケープ。ヘッダー行＋区切り行＋データ行
- TSV: セルに タブ・改行・`"` を含むとき `"` で囲み `"` を `""` に（Tables と同じ `tsvCell` 規約）。
  **ヘッダー行を含む**

## エラー・警告規約

- どの入力でも例外で落ちない。エンジンは `{ ok: true, value, warnings, md, tsv }` /
  `{ ok: false, error }` を返す（ddl2spec・Convert の新規タブと同じ規約）
- バナー・コピーは `lib/ui.js` の共通核（`ToolUI.banner` / `ToolUI.copy` / `ToolUI.feedback`）。
  ラッパは `showBanner(kind, text)`（全ツール統一の引数順）
- 警告は info バナーに ' / ' 連結（excel2md と同じ）。ガードは warn バナー

## 性能ガード（超過時は処理せず理由を表示。一部のみ処理はしない）

| 対象 | 上限 | 超過時 |
|---|---|---|
| 入力 | **50万文字** | 「入力が上限（50万文字）を超えたため処理を中止しました」 |
| 出力行 | **5,000行** | 「出力が上限（5,000行）を超えたため処理を中止しました」 |
| 表の列 | **30列** | その表だけ内容列へ連結＋警告（全体は止めない。DX-Q5） |

## 画面構成

- `<main class="app">` 直下: `.tool-header`（「← ツール一覧」＋「入力は自動保存されます」）
- `<h1>Outline</h1>`・subtitle（正本は Markdown 側、Excel は納品時の生成物）
- ツールバー: 階層列の見出し名 select（カスタム時はテキスト入力を表示）／
  「空セルを上の値で埋める」トグル／内容の単位 select／出力形式ラジオ（Markdown表 / TSV）／
  ［出力をコピー］（**Cmd/Ctrl+Enter でも実行**。title にキー表記）
- 2ペイン（入力 Markdown / 出力）。**リアルタイム変換**（250ms デバウンス）
- サンプル投入ボタン（入力が空のときだけ表示。見出し3階層・ネスト箇条書き・番号付き・
  md 表・リンク警告が1回で見える機能一覧の下書き）
- プレビュー表は作らない（出力を Tables に貼れば見られる。二重に持たない）

## Excel 用コピー（text/html 併記・2026-08-13）

出力形式が **TSV のとき**、コピーは text/plain（TSV・従来どおり）に加えて
text/html（書式付き `<table>`）を同時に書く（機構は `lib/excel.js` の `ToolExcel.copy`。
excel2md・ddl2spec と同じ二重フレーバー。Markdown 表出力のときは従来どおり平文のみ）:

- 罫線・ヘッダー背景・文字列化ガードは `lib/excel.js` の `cellStyle` が正本
- **空セル埋め OFF のとき、階層列の空セル（＝直上の見出しの継続）は rowspan の結合セル**
  として貼られる（`valign="top"`）。継続判定は**親列（左）も継続しているときだけ** —
  大項目が変わった行の中項目の空欄は、新しい（結合されない）空セル
- **空セル埋め ON のときは結合しない**（「全行に値を入れる」というオプションの意味に 1:1 対応）
- 内容列・md 表由来の列は結合しない
- 書き込み失敗時は平文コピーにフォールバック

Excel 実機スモーク項目: TSV でコピー → Excel 貼り付けで**階層列が結合セルになり、
罫線・ヘッダー背景が付く**こと（自動検証は HTML 文字列まで。Excel 側の解釈は実機のみ）

## 保存（localStorage は UI 状態のみの原則との整合）

- `tools:doc2xl` に**オプションと入力**を保存（ddl2spec と同じ「入力は自動保存されます」型。
  変換はその場で済む道具で、原稿の正本はエディタ側にある）
- **10万文字を超える入力は保存しない**（localStorage の容量目安。復元されないだけで
  変換はできる。devpad の 100KB/フィールド上限と同じ考え方）

## テストケース

照合フック: `window.doc2xl.convert(text, opts)` →
`{ ok, value: { header, rows, depth, tableCols }, warnings, md, tsv }`。
`opts = { names: 'default'|'level'|'custom', custom: '', fill: false, split: 'line'|'block' }`。

| ID | 入力 | 期待 |

## 決定事項（DX-Q1〜Q8・2026-08-12 承認）

- **DX-Q1**: 表示名 → **`Outline`**（`Doc` は `docs/` と紛れる）
- **DX-Q2**: 空セル埋めの既定 → **OFF**（納品物は人が読む前提で空セルが慣習。
  フィルタ・ピボット向けに ON も選べる）
- **DX-Q3**: 内容の分割単位の既定 → **1行1セル**（箇条書き1項目=1行が Excel で扱いやすい）
- **DX-Q4**: md 表の置き場所 → **内容列の右**。不採用「内容列から表を始める」は
  内容列の意味が表によって変わり、フィルタ・数式を当てられなくなる
- **DX-Q5**: 30列超の表 → **その表だけ内容列へ連結＋警告**（幅だけの理由で全体を止めない）
- **DX-Q6**: 逆方向 → **実装しない**（概要の3点。逆流は「Excel が正本」の運用を許す）
- **DX-Q7**: 見出しは **H6 まで**（7個以上の `#` は本文）
- **DX-Q8**: 着手条件 → **1回目だが着手**（利用者が自分から要望・調査で範囲を絞り済み。
  ユーザー判断。ルール追記は `docs/tool-backlog.md`）

## やらないこと

- .xlsx の直接読み書き / Excel → MD の機械変換（AI ＋ `_prompts/` の担当）
- 逆方向（Excel階層列 → md）/ プレビュー表 / Tables（excel2md）の変更
- setext 見出し・箇条書き継続行の CommonMark 完全対応（→ 仕様の限界）
